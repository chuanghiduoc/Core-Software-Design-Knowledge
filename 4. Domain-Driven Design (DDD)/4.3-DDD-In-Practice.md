## Project Structure cho DDD

### ❌ Bad: Structure theo technical layers

```
src/
├── controllers/       # ❌ Nhóm theo layer — khó tìm code cho 1 feature
│   ├── orderController.ts
│   └── userController.ts
├── services/
│   ├── orderService.ts
│   └── userService.ts
├── models/            # ❌ Tất cả models cùng folder → cross-context deps
│   ├── order.ts
│   └── user.ts
└── repositories/
    ├── orderRepository.ts
    └── userRepository.ts
# Thêm 1 feature → sửa 4 folders. Không thấy bounded context boundaries.
```

### ✅ Good: Structure theo Bounded Context

```
src/
├── shared/                         # Shared Kernel
│   ├── domain/
│   │   ├── Entity.ts
│   │   ├── ValueObject.ts
│   │   ├── DomainEvent.ts
│   │   └── Specification.ts
│   └── types/
│       ├── Money.ts
│       └── Email.ts
│
├── ordering/                       # Bounded Context: Order Management
│   ├── domain/                     # Domain Layer — PURE business logic
│   │   ├── model/
│   │   │   ├── Order.ts            # Aggregate Root
│   │   │   ├── OrderItem.ts        # Inner Entity
│   │   │   └── OrderStatus.ts
│   │   ├── event/
│   │   │   ├── OrderPlaced.ts
│   │   │   └── OrderCancelled.ts
│   │   ├── service/
│   │   │   └── OrderPricingService.ts
│   │   ├── repository/
│   │   │   └── OrderRepository.ts  # Interface ONLY
│   │   └── error/
│   │       └── InvalidOrderStateError.ts
│   │
│   ├── application/                # Application Layer — use cases
│   │   ├── command/
│   │   │   ├── PlaceOrder.ts
│   │   │   └── CancelOrder.ts
│   │   ├── query/
│   │   │   └── GetOrderById.ts
│   │   └── dto/
│   │       └── OrderDto.ts
│   │
│   └── infrastructure/             # Adapters — implementations
│       ├── persistence/
│       │   └── PostgresOrderRepository.ts
│       └── http/
│           └── OrderController.ts
│
├── inventory/                      # Bounded Context: Inventory
│   ├── domain/
│   ├── application/
│   └── infrastructure/
│
└── main.ts                         # Composition Root
```

### Dependency Rule

```
Infrastructure → Application → Domain
Domain NEVER imports from Application or Infrastructure.
```

## DDD với Hexagonal Architecture

DDD + Hexagonal bổ sung hoàn hảo: DDD cho **building blocks**, Hexagonal cho **layer organization**.

### ❌ Bad: Domain phụ thuộc infrastructure

```typescript
import { Entity, Column, ManyToOne } from 'typeorm'; // ❌ ORM trong domain!

@Entity('orders')
class Order {
  @Column() id: string;
  @Column() status: string;
  @ManyToOne(() => Customer) customer: Customer; // ❌ ORM relationship
  place(): void { this.status = 'PLACED'; }
}
```

### ✅ Good: Domain layer hoàn toàn pure

```typescript
// === DOMAIN (center of hexagon) — zero external deps ===

// Ports (interfaces)
interface OrderRepository {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<void>;
}

interface PaymentGateway {
  charge(request: ChargeRequest): Promise<ChargeResult>;
  refund(paymentId: PaymentId, amount: Money): Promise<RefundResult>;
}

// Pure domain model
class Order extends AggregateRoot<OrderId> { /* business logic only */ }

// === APPLICATION (use cases) ===
class PlaceOrderHandler {
  constructor(
    private readonly orderRepo: OrderRepository,     // Inject port
    private readonly eventBus: DomainEventBus,
  ) {}

  async handle(cmd: PlaceOrderCommand): Promise<OrderId> {
    const order = Order.create(cmd.customerId, cmd.shippingAddress);
    cmd.items.forEach(i => order.addItem(i.productId, i.name, i.price, i.quantity));
    order.place();
    await this.orderRepo.save(order);
    await this.eventBus.publishAll(order.clearDomainEvents());
    return order.id;
  }
}

// === INFRASTRUCTURE (adapters) ===
class PostgresOrderRepository implements OrderRepository { /* Knex/Prisma impl */ }
class StripePaymentAdapter implements PaymentGateway { /* Stripe SDK impl */ }

class OrderHttpController {
  constructor(private readonly placeOrder: PlaceOrderHandler) {}
  async handlePlaceOrder(req: Request, res: Response): Promise<void> {
    const orderId = await this.placeOrder.handle(PlaceOrderCommand.fromRequest(req.body));
    res.status(201).json({ orderId: orderId.value });
  }
}

// === COMPOSITION ROOT (main.ts) — wire everything ===
function bootstrap(): void {
  const orderRepo = new PostgresOrderRepository(db);
  const eventBus = new InProcessEventBus();
  const placeOrderHandler = new PlaceOrderHandler(orderRepo, eventBus);
  const controller = new OrderHttpController(placeOrderHandler);
  // Start server...
}
```

## Aggregate Design Rules

Bốn quy tắc theo Vaughn Vernon ("Implementing DDD"):

### Rule 1: Giữ Aggregate nhỏ

```typescript
// ❌ God Aggregate
class Order {
  items: OrderItem[];
  payments: Payment[];        // ❌ Separate aggregate
  shipments: Shipment[];      // ❌ Separate aggregate
  auditLog: AuditEntry[];    // ❌ Hàng trăm entries
  customerProfile: Customer;  // ❌ Khác aggregate
}

// ✅ Small, focused
class Order {
  private _items: OrderItem[];       // Part of aggregate
  private _status: OrderStatus;
  private _customerId: CustomerId;   // Reference by ID only
}
class Payment { _orderId: OrderId; /* separate aggregate, own lifecycle */ }
class Shipment { _orderId: OrderId; /* separate aggregate */ }
```

### Rule 2: Reference by ID

```typescript
// ❌ Direct reference — load Order = load Customer + Product
class Order { customer: Customer; product: Product; }

// ✅ ID reference — load Customer only when needed
class Order { customerId: CustomerId; }
class OrderItem { productId: ProductId; productName: string; unitPrice: Money; } // Snapshot
```

### Rule 3: Một transaction = Một aggregate

```typescript
// ❌ Update 2 aggregates trong 1 transaction → lock nhiều rows → deadlock
await db.transaction(async (trx) => {
  await orderRepo.save(order, trx);
  await inventoryRepo.save(inventory, trx);  // ❌ Cross-aggregate transaction
});

// ✅ 1 transaction per aggregate + domain events cho eventual consistency
await this.orderRepo.save(order);
await this.eventBus.publishAll(order.clearDomainEvents());
// OrderPlaced event → InventoryReservationHandler reserves stock in separate txn
```

### Rule 4: Eventual consistency giữa aggregates

```typescript
// Invariants TRONG aggregate → enforce ngay (strong consistency)
class Order {
  addItem(...): void {
    if (this._items.length >= 50) throw new MaxOrderItemsExceededError(50); // ✅ Immediate
  }
}

// Invariants GIỮA aggregates → eventual consistency qua events
class OrderPlacedPolicy implements DomainEventHandler<OrderPlaced> {
  async handle(event: OrderPlaced): Promise<void> {
    try {
      await this.inventoryService.reserve(event.orderId, event.items);
    } catch {
      await this.orderService.cancelDueToStockout(event.orderId); // Compensating action
    }
  }
}
```

## Domain Events cho Inter-Aggregate Communication

### Outbox Pattern — reliable event publishing

```typescript
// Problem: save aggregate OK nhưng publish event fail → inconsistency
// Solution: save event cùng transaction với aggregate

class OutboxDomainEventBus implements DomainEventBus {
  constructor(private readonly db: Knex) {}

  async publishAll(events: DomainEvent[]): Promise<void> {
    for (const event of events) {
      await this.db('domain_event_outbox').insert({
        id: event.eventId, event_type: event.eventType,
        payload: JSON.stringify(event), published: false,
      });
    }
  }
}

// Background job: poll outbox → publish to message broker
class OutboxProcessor {
  async processUnpublished(): Promise<void> {
    const events = await this.db('domain_event_outbox')
      .where('published', false).orderBy('occurred_at').limit(100);

    for (const row of events) {
      await this.messageBroker.publish(row.event_type, row.payload);
      await this.db('domain_event_outbox')
        .where('id', row.id).update({ published: true });
    }
  }
}
```

## Anti-Patterns

### 1. Anemic Domain Model — model chỉ có data, logic ở service

```typescript
// ❌ Anemic — Order là data container vô dụng
class Order {
  id: string; items: OrderItem[]; status: string; total: number;
}
class OrderService {
  placeOrder(order: Order): void {
    if (order.items.length === 0) throw new Error('Empty');
    order.status = 'PLACED'; // ❌ Anyone can set invalid status
    order.total = order.items.reduce((s, i) => s + i.price * i.qty, 0);
  }
}

// ✅ Rich Domain Model — logic thuộc về entity
class Order extends AggregateRoot<OrderId> {
  private _status: OrderStatus;
  place(): void {
    if (this._items.length === 0) throw new EmptyOrderError();
    this._status = OrderStatus.Placed; // Only change via behavior methods
    this.addDomainEvent(new OrderPlaced(/* ... */));
  }
  get status(): OrderStatus { return this._status; } // No setter
}
```

### 2. God Aggregate — quá lớn, load chậm, lock nhiều

```typescript
// ❌ Customer chứa mọi thứ → 50MB in memory
class Customer {
  orders: Order[];                // 10,000 orders!
  reviews: Review[]; wishlist: WishlistItem[];
  paymentMethods: PaymentMethod[]; loyaltyPoints: LoyaltyPoints;
}

// ✅ Tách thành nhiều small aggregates
class CustomerProfile { personalInfo: PersonalInfo; addresses: Address[]; }
class Wishlist { customerId: CustomerId; items: WishlistItem[]; }
class LoyaltyAccount { customerId: CustomerId; points: number; }
```

### 3. Leaking Domain Logic — business rules ở controller

```typescript
// ❌ Logic ở controller → duplicate khi thêm API/CLI/queue handler
class OrderController {
  async placeOrder(req: Request, res: Response): Promise<void> {
    const order = await this.orderRepo.findById(req.params.id);
    if (order.items.length === 0) return res.status(400).json({ error: 'Empty' }); // ❌
    if (order.total > 10000 && !order.isApproved) return res.status(400).json({ error: 'Need approval' }); // ❌
    order.status = 'PLACED';  // ❌ Direct mutation
  }
}

// ✅ Controller chỉ: parse request → call use case → format response
class OrderController {
  async placeOrder(req: Request, res: Response): Promise<void> {
    try {
      const orderId = await this.placeOrderHandler.handle(
        new PlaceOrderCommand(OrderId.from(req.params.id)));
      res.status(200).json({ orderId: orderId.value });
    } catch (error) {
      if (error instanceof DomainError) res.status(400).json({ error: error.message, code: error.code });
      else throw error;
    }
  }
}
```

## Khi nào DDD là Overkill

### KHÔNG phù hợp

```
1. CRUD apps — Admin panels, data entry → dùng framework + ORM trực tiếp
2. Read-heavy apps — Dashboards, reporting → query DB trực tiếp
3. Prototype / MVP — Cần ship trong 2 tuần → ship nhanh, refactor sau
4. Simple domains — Blog, todo → DDD complexity > domain complexity
5. Small team (1-2 devs) + simple domain → clean code là đủ
```

### Dấu hiệu bạn CẦN DDD

```
- Domain experts mất 30+ phút giải thích rules vẫn chưa xong
- Developers thường xuyên hiểu sai requirements
- Cùng một từ nghĩa khác nhau ở các teams
- Business rules đổi liên tục, code phải adapt nhanh
- Hệ thống 5+ năm lifespan, nhiều teams
```

### Spectrum — không cần "all or nothing"

```
Simple CRUD ────────────────────────────────── Complex Domain

No DDD          DDD Lite              Full DDD
│                 │                      │
│  Plain CRUD     │  Value Objects       │  Ubiquitous Language
│  ORM models     │  Rich entities       │  Bounded Contexts
│  Service layer  │  Domain events       │  Context Mapping
│                 │                      │  Aggregates + CQRS

→ Bắt đầu DDD Lite (Value Objects + Rich Entities), evolve khi cần.
```

## DDD với CQRS

Tách **write model** (commands/aggregates) và **read model** (queries/projections).

### ❌ Bad: Load aggregate cho read operations

```typescript
// ❌ Load 50 items + reconstruct aggregate chỉ để return 3 fields
class GetOrderHandler {
  async handle(query: GetOrder): Promise<OrderDto> {
    const order = await this.orderRepo.findById(query.orderId); // Heavy load
    return { id: order.id.value, status: order.status, total: order.totalAmount.amount };
  }
}
```

### ✅ Good: Separate read model

```typescript
// WRITE SIDE: Aggregates handle commands
class PlaceOrderHandler {
  async handle(cmd: PlaceOrderCommand): Promise<OrderId> {
    const order = Order.create(cmd.customerId, cmd.shippingAddress);
    cmd.items.forEach(i => order.addItem(i.productId, i.name, i.price, i.quantity));
    order.place();
    await this.orderRepo.save(order);
    await this.eventBus.publishAll(order.clearDomainEvents());
    return order.id;
  }
}

// READ SIDE: Direct SQL — no domain model needed
interface OrderReadModel {
  id: string; customerName: string; status: string;
  itemCount: number; totalAmount: number; placedAt: string;
}

class OrderQueryService {
  constructor(private readonly db: Knex) {}

  async getOrderById(orderId: string): Promise<OrderReadModel | null> {
    return this.db('order_read_model').where('id', orderId).first();
  }

  async getOrdersByCustomer(customerId: string, page: number, size: number) {
    return this.db('order_read_model').where('customer_id', customerId)
      .orderBy('placed_at', 'desc').offset((page - 1) * size).limit(size);
  }
}

// SYNC: Domain Events update read model
class OrderPlacedProjection implements DomainEventHandler<OrderPlaced> {
  async handle(event: OrderPlaced): Promise<void> {
    await this.db('order_read_model').insert({
      id: event.orderId.value, customer_id: event.customerId.value,
      status: 'PLACED', item_count: event.items.length,
      total_amount: event.totalAmount.amount, placed_at: event.occurredAt.toISOString(),
    });
  }
}
```

| Dùng CQRS | Không cần |
|-----------|-----------|
| Read patterns khác write patterns | Read/write dùng cùng model |
| High read-to-write ratio (100:1) | Balanced read/write |
| Complex domain + complex reporting | Simple CRUD |

## Testing Domain Logic

DDD cho phép test domain **mà không cần infrastructure** — fast, isolated, reliable.

### ❌ Bad: Cần DB + HTTP server chỉ để test business rule

```typescript
describe('PlaceOrder', () => {
  let db: Database; let server: HttpServer;
  beforeAll(async () => { db = await connectDB(); server = await startServer(); });
  it('should fail for empty order', async () => {
    const res = await fetch('http://localhost:3000/orders', { method: 'POST', body: '...' });
    expect(res.status).toBe(400);
  });
});
// Setup: 5 giây. Run: 500ms. Fragile. Tests nhiều thứ cùng lúc.
```

### ✅ Good: Pure unit tests — no infrastructure

```typescript
describe('Order Aggregate', () => {
  function createDraftOrder(): Order {
    return Order.create(CustomerId.from('c-1'), Address.create({
      street: '123 Main', city: 'NYC', state: 'NY', postalCode: '10001', country: 'US',
    }));
  }
  function addItem(order: Order): void {
    order.addItem(ProductId.from('p-1'), 'Book', Money.create(29.99, Currency.USD), Quantity.create(2));
  }

  describe('addItem()', () => {
    it('should add item and calculate total', () => {
      const order = createDraftOrder();
      order.addItem(ProductId.from('p1'), 'Book', Money.create(29.99, Currency.USD), Quantity.create(3));
      expect(order.itemCount).toBe(1);
      expect(order.totalAmount.amount).toBe(89.97);
    });

    it('should reject duplicate product', () => {
      const order = createDraftOrder();
      const pid = ProductId.from('p1');
      order.addItem(pid, 'Book', Money.create(10, Currency.USD), Quantity.create(1));
      expect(() => order.addItem(pid, 'Book', Money.create(10, Currency.USD), Quantity.create(1)))
        .toThrow(DuplicateOrderItemError);
    });

    it('should reject when not Draft', () => {
      const order = createDraftOrder(); addItem(order); order.place();
      expect(() => order.addItem(ProductId.from('p2'), 'Pen', Money.create(5, Currency.USD), Quantity.create(1)))
        .toThrow(InvalidOrderStateError);
    });
  });

  describe('place()', () => {
    it('should transition to Placed and emit event', () => {
      const order = createDraftOrder(); addItem(order);
      order.place();
      expect(order.status).toBe(OrderStatus.Placed);
      const event = order.domainEvents.find(e => e.eventType === 'order.placed') as OrderPlaced;
      expect(event).toBeDefined();
      expect(event.totalAmount.amount).toBe(59.98);
    });

    it('should reject empty order', () => {
      expect(() => createDraftOrder().place()).toThrow(EmptyOrderError);
    });
  });

  describe('cancel()', () => {
    it('should allow cancel of Placed order', () => {
      const order = createDraftOrder(); addItem(order); order.place();
      order.cancel(CancellationReason.CustomerRequest);
      expect(order.status).toBe(OrderStatus.Cancelled);
    });

    it('should prevent cancel of Shipped order', () => {
      const order = createDraftOrder(); addItem(order);
      order.place(); order.confirm(PaymentId.from('pay-1'));
      order.ship(TrackingNumber.from('TRACK-123'));
      expect(() => order.cancel(CancellationReason.CustomerRequest)).toThrow(InvalidOrderStateError);
    });
  });

  describe('lifecycle', () => {
    it('should follow Draft -> Placed -> Confirmed -> Shipped -> Delivered', () => {
      const order = createDraftOrder(); addItem(order);
      order.place(); order.confirm(PaymentId.from('p1'));
      order.ship(TrackingNumber.from('T1')); order.deliver();
      expect(order.status).toBe(OrderStatus.Delivered);
    });
  });
});

describe('Money', () => {
  it('should add same currency', () => {
    expect(Money.create(10.50, Currency.USD).add(Money.create(5.25, Currency.USD)).amount).toBe(15.75);
  });
  it('should reject different currencies', () => {
    expect(() => Money.create(10, Currency.USD).add(Money.create(5, Currency.EUR)))
      .toThrow(CurrencyMismatchError);
  });
  it('should round to 2 decimals', () => {
    expect(Money.create(10.999, Currency.USD).amount).toBe(11.00);
  });
});

describe('Email', () => {
  it('should normalize to lowercase', () => { expect(Email.create('User@X.COM').value).toBe('user@x.com'); });
  it('should reject invalid', () => { expect(() => Email.create('bad')).toThrow(InvalidEmailError); });
});
// 20+ tests < 100ms. No DB. No Docker. No HTTP.
```

## Case Study: Order Management Bounded Context

### Architecture Overview

```
┌──────────────────────────────────────────────────────┐
│            ORDER MANAGEMENT CONTEXT                   │
│  Client → Controller → CommandHandler → Domain Model  │
│                                        ↓              │
│  ReadModel ← Projections ← Events ← Repository → DB  │
└──────────────────────────────────────────────────────┘
```

### Application Service — full commands

```typescript
class PlaceOrderCommand {
  constructor(
    readonly customerId: string,
    readonly items: Array<{ productId: string; productName: string;
      unitPrice: number; currency: string; quantity: number }>,
    readonly shippingAddress: { street: string; city: string;
      state: string; postalCode: string; country: string },
  ) {}
}

class PlaceOrderHandler {
  constructor(private readonly orderRepo: OrderRepository, private readonly eventBus: DomainEventBus) {}

  async handle(cmd: PlaceOrderCommand): Promise<string> {
    const customerId = CustomerId.from(cmd.customerId);
    const address = Address.create(cmd.shippingAddress);
    const order = Order.create(customerId, address);
    for (const item of cmd.items) {
      order.addItem(ProductId.from(item.productId), item.productName,
        Money.create(item.unitPrice, item.currency as Currency), Quantity.create(item.quantity));
    }
    order.place();
    await this.orderRepo.save(order);
    await this.eventBus.publishAll(order.clearDomainEvents());
    return order.id.value;
  }
}

class CancelOrderHandler {
  constructor(private readonly orderRepo: OrderRepository, private readonly eventBus: DomainEventBus) {}

  async handle(cmd: { orderId: string; reason: string }): Promise<void> {
    const order = await this.orderRepo.findById(OrderId.from(cmd.orderId));
    if (!order) throw new OrderNotFoundError(OrderId.from(cmd.orderId));
    order.cancel(CancellationReason.fromString(cmd.reason));
    await this.orderRepo.save(order);
    await this.eventBus.publishAll(order.clearDomainEvents());
  }
}
```

### Domain Error Hierarchy

```typescript
abstract class DomainError extends Error {
  abstract readonly code: string;
  constructor(message: string) { super(message); this.name = this.constructor.name; }
}

class InvalidOrderStateError extends DomainError {
  readonly code = 'ORDER.INVALID_STATE';
  constructor(status: OrderStatus, action: string) {
    super(`Cannot ${action} order in ${status} status`);
  }
}
class EmptyOrderError extends DomainError { readonly code = 'ORDER.EMPTY'; }
class OrderNotFoundError extends DomainError { readonly code = 'ORDER.NOT_FOUND'; }
class DuplicateOrderItemError extends DomainError { readonly code = 'ORDER.DUPLICATE_ITEM'; }
class InvalidMoneyError extends DomainError { readonly code = 'MONEY.INVALID'; }
class CurrencyMismatchError extends DomainError { readonly code = 'MONEY.CURRENCY_MISMATCH'; }
```

### Event Handlers — cross-context reactions

```typescript
// Order placed → reserve inventory
class ReserveInventoryOnOrderPlaced implements DomainEventHandler<OrderPlaced> {
  async handle(event: OrderPlaced): Promise<void> {
    await this.inventoryClient.reserve({
      orderId: event.orderId.value,
      items: event.items.map(i => ({ productId: i.productId.value, quantity: i.quantity })),
    });
  }
}

// Order cancelled (was confirmed) → process refund
class ProcessRefundOnOrderCancelled implements DomainEventHandler<OrderCancelled> {
  async handle(event: OrderCancelled): Promise<void> {
    if (!event.wasConfirmed) return; // No payment to refund
    await this.paymentClient.refund({ orderId: event.orderId.value, reason: event.reason.value });
  }
}

// Order placed → send confirmation email
class SendConfirmationOnOrderPlaced implements DomainEventHandler<OrderPlaced> {
  async handle(event: OrderPlaced): Promise<void> {
    await this.notificationClient.sendOrderConfirmation({
      customerId: event.customerId.value, orderId: event.orderId.value,
      totalAmount: `${event.totalAmount.currency} ${event.totalAmount.amount}`,
    });
  }
}
```

## Tổng kết

```
DDD In Practice Checklist:

□ Domain layer KHÔNG import infrastructure
□ Mỗi aggregate <= 5 entities. Lớn hơn → tách
□ Reference aggregates bằng ID, không embed
□ 1 transaction = 1 aggregate. Cross-aggregate → events
□ Domain errors rõ ràng, có error codes
□ Business logic trong domain, KHÔNG ở controller
□ Domain tests < 1 giây, không cần infrastructure
□ Value Objects cho mọi domain concept
□ Ubiquitous Language reflect trong class/method names
```

> **Final wisdom**: DDD không phải destination — nó là journey.
> Bắt đầu với Strategic DDD (hiểu domain, chia boundaries),
> thêm Tactical patterns khi complexity đòi hỏi,
> và luôn refine cùng domain experts.
