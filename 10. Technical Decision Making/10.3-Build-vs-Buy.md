## Framework cho Build vs Buy

### Câu hỏi cốt lõi

```
"Đây có phải CORE DIFFERENTIATOR của business không?"
YES → Nghiêng về BUILD     |    NO → Nghiêng về BUY (mạnh mẽ)
Core differentiator = thứ khách hàng CHỌN bạn thay vì competitor
```

### Spectrum of options (không chỉ Build hoặc Buy)

```
FULL BUILD ──────────────────────────────────────── FULL BUY
Build from   Use open-    Fork &      SaaS with     Full managed
scratch      source lib   customize   API           solution

Ví dụ Authentication:
Custom auth  Passport.js  Keycloak    Auth0 API     Auth0/Clerk
framework    + custom UI  self-host   + custom UI   full platform
```

### 7 câu hỏi quyết định

```
1. DIFFERENTIATION — Competitive advantage? Auth: NO → buy
2. COMPLEXITY — Team có expertise build VÀ maintain?
3. TIME — Timeline cho phép build?
4. CUSTOMIZATION — < 20% customize → buy | > 50% → build viable
5. SCALE — Unique scaling challenges?
6. COMPLIANCE — Regulatory requirements?
7. LONG-TERM COST — TCO 3-5 năm là bao nhiêu?
```

## Hidden Costs of Building

> Engineers thường chỉ tính thời gian viết code ban đầu.
> Đó thường là 20-30% tổng chi phí thực tế.

### The iceberg

```
    ╱ Initial build (20-30%) ╲     ← Cái team thấy
~~~~╱~~~~~~~~~~~~~~~~~~~~~~~~╲~~~~
   │ Ongoing maintenance      │    ← Bug fixes, dependency updates
   │ Feature parity           │    ← Catch up với market standards
   │ Security patches         │    ← CVE responses
   │ Opportunity cost         │    ← Features KHÔNG được build
   │ Knowledge concentration  │    ← Bus factor = 1-2 người
   │ On-call & support        │    ← Production issues
    ╲________________________╱
```

**Maintenance cost:** 2-3x initial build effort PER YEAR.

**Opportunity cost:** 2 senior devs build custom tool = 2 senior devs KHÔNG build features.

**Knowledge concentration:** Custom system 1-2 người hiểu. Nghỉ việc = knowledge gap.

**Feature parity trap:**

```
Build custom auth:
  Month 1-3: Username/password, reset, verification ✅
  Month 4+:  Social login, MFA, passwordless, SSO, brute force protection,
             device management, compliance reporting...
  Auth0 có TẤT CẢ từ ngày 1. Chi phí: $23/month cho 1000 MAU.
```

## Hidden Costs of Buying

### Vendor lock-in levels

```
Level 1: API/SDK dependency        → Dễ replace (adapter pattern)
Level 2: Data format lock-in       → Medium (data migration)
Level 3: Workflow lock-in          → Khó (team process phụ thuộc tool)
Level 4: Data hostage              → Cực khó (export hạn chế)
```

### Mitigation: Anti-corruption layer

```typescript
// ❌ Auth0 scattered throughout codebase
import { Auth0Client } from '@auth0/auth0-spa-js';

// ✅ Interface layer — swap vendor bằng cách implement mới
interface AuthProvider {
  login(credentials: LoginCredentials): Promise<AuthResult>;
  logout(): Promise<void>;
  getUser(): Promise<UserProfile | null>;
}

class Auth0Provider implements AuthProvider { /* Auth0 specific */ }
class ClerkProvider implements AuthProvider { /* Chỉ thay file này */ }
```

### Pricing changes — real scenarios

```
- Heroku (2022): Free tier removed → costs jumped 5-10x
- Docker Hub (2023): Rate limits → CI/CD pipelines break
- Redis (2024): License change BSD → dual-license → Valkey fork
- HashiCorp (2023): Terraform BSL → OpenTofu fork

Mitigation: Prefer open-source (MIT/Apache 2.0), budget 2x cho SaaS
```

### Customization limits

```
Phase 1: "SaaS này làm được hết!"
Phase 2: "Cần tweak một chút..."
Phase 3: "Hack workaround vì không support use case"
Phase 4: "Workaround cost > build cost" → re-evaluate
```

## Open Source Evaluation

### SPACE Framework

```
S — Security:     CVE history, response time, audits, dependency chain
P — Popularity:   npm downloads, contributors > 10, Stack Overflow activity
A — Activity:     Last commit < 3 months, regular releases, bus factor > 2
C — Compatibility: TypeScript native, semver compliance, migration guides
E — Ecosystem:    Plugins, docs quality, integrations
```

### License evaluation

```
✅ SAFE:     MIT, Apache 2.0, BSD — dùng thoải mái
⚠️ CẨN THẬN: LGPL (OK nếu chỉ link), MPL 2.0 (file-level copyleft)
❌ RISKY:    GPL/AGPL — code bạn cũng phải GPL | SSPL, BSL — restrict cloud

Rule: Prefer MIT / Apache 2.0. AGPL → consult legal.
```

### Evaluation scorecard ví dụ: ORM cho TypeScript

```
                    Prisma    Drizzle    TypeORM    Kysely

Popularity          5/5       4/5        4/5        3/5
Activity            5/5       5/5        3/5        4/5
Compatibility       5/5       5/5        3/5        5/5
Ecosystem           5/5       4/5        4/5        3/5
TOTAL               24/25     22/25      17/25      19/25
```

## Framework/Library Selection Process

```
BƯỚC 1 (1-2 ngày): Xác định must-have vs nice-to-have requirements
BƯỚC 2 (1 ngày):   Long list 5-10 → filter → short list 3-4
BƯỚC 3 (2-3 ngày): Deep eval (SPACE) + prototype top 2-3
BƯỚC 4 (1 ngày):   Team review, gather concerns
BƯỚC 5 (1 ngày):   Decision + ADR + adoption plan + 3-month review date
```

## When to Build Your Own

```
✅ BUILD khi:
  1. Core differentiator — competitive advantage
  2. Unique requirements — không solution nào đáp ứng
  3. Cost at scale — SaaS quá đắt tại volume cao
  4. Existential risk — vendor dependency unacceptable

🚩 Red flags khi team muốn build:
  - "Not Invented Here" — "library X không tốt bằng mình viết"
  - Resume-Driven Development — "muốn build để học"
  - Underestimating complexity — "auth đơn giản, 2 tuần xong"
  - Overvaluing control — control = responsibility for everything
```

---

## When to Buy/Use Existing

```
✅ BUY khi:
  1. Commodity — ai cũng cần (auth, email, payment, monitoring)
  2. Regulated domain — compliance tốn kém (PCI, HIPAA)
  3. Expertise gap — team không có chuyên môn
  4. Time-to-market — cần ship nhanh
  5. Operational burden — không muốn manage infrastructure
```

## SaaS vs Self-Hosted

```
                    SaaS              Self-Hosted
Setup time          Minutes-hours     Days-weeks
Ops burden          Zero              Medium-High
Customization       Limited           Full
Data location       Vendor cloud      Your infra
Cost (small)        Low ($)           Medium ($$)
Cost (large)        High ($$$$$)      Medium ($$)
Compliance control  Limited           Full

Decision tree:
  Compliance bắt buộc on-premise? → Self-hosted
  Có DevOps expertise? → Evaluate cả hai theo TCO
  Không DevOps? → SaaS (mạnh mẽ)
  Volume > cost threshold? → Self-hosted tiết kiệm
```

## Real-World Examples

### Auth: Build vs Auth0/Clerk

```
B2B SaaS, 500 orgs, 10K users

Build custom:    $135K year 1 (3 months × 2 seniors + security audit)
                 $30K/year ongoing maintenance
Auth0:           $8K year 1 (1 week integration + $2,880/year subscription)
Clerk:           $6.6K year 1 (3 days integration + $3,600/year)

→ BUY. Build chỉ khi: auth IS your product, extreme customization,
  regulatory requirement, hoặc > 1M MAU (SaaS pricing expensive)
```

### Payments: Build vs Stripe

```
Build: PCI DSS compliance $50-200K/year + fraud ML team + legal
       = $500K-1M+ year 1, team 5-10 người
Stripe: 2.9% + 30¢/transaction, integration 1-2 weeks
→ BUY. Break-even: > $15-20M/year processing volume
```

### Search: Build vs Algolia/Typesense

```
E-commerce, 50K products

| Criteria         | Weight | PG FTS | Elastic | Algolia | Typesense |
|------------------|--------|--------|---------|---------|-----------|
| Search quality   | 30%    | 2      | 5       | 5       | 4         |
| Ops effort       | 25%    | 5      | 2       | 5       | 4         |
| Cost (1 year)    | 20%    | 5      | 3       | 3       | 5         |
| Time to implement| 15%    | 4      | 3       | 5       | 4         |
| Scalability      | 10%    | 2      | 5       | 5       | 4         |
| TOTAL            |        | 3.55   | 3.30    | 4.40    | 4.15      |

→ Algolia (budget OK) hoặc Typesense (budget tight)
→ Start PG FTS nếu product chưa validate
```

## Migration Strategy khi Vendor không Work Out

### Signals cần migrate

```
COST tăng nhanh hơn revenue | LIMITATIONS block critical use case
RELIABILITY issues (SLA violated) | STRATEGIC (vendor bị acquire/sunset)
```

### Migration playbook

```
Phase 1: PREPARATION (2-4 weeks) — Audit usage, map data, estimate effort
Phase 2: ABSTRACTION (1-2 weeks) — Interface layer nếu chưa có (CRITICAL)
Phase 3: PARALLEL (2-6 weeks) — Implement new adapter, feature parity check
Phase 4: GRADUAL (2-4 weeks) — Feature flag: 5% → 25% → 50% → 100%
Phase 5: CLEANUP (1 week) — Remove old vendor, cancel subscription, ADR
```

```typescript
// Feature-flag controlled routing
class SearchServiceRouter implements SearchService {
  async search(query: string, options: SearchOptions) {
    if (this.featureFlags.isEnabled('use-typesense')) {
      return this.typesense.search(query, options);
    }
    return this.algolia.search(query, options);
  }
}
```

## Total Cost of Ownership (TCO)

### TCO = Direct + Indirect + Hidden Costs

```
DIRECT:   Build: dev time + infra | Buy: license + integration
INDIRECT: Build: maintenance (20-30%/year), security, docs
          Buy: vendor management, customization workarounds
HIDDEN:   Build: opportunity cost, knowledge risk, tech debt
          Buy: lock-in migration, pricing risk, feature gaps
```

### Example: Logging & Monitoring cho 20-service platform

```
                    ELK Self-managed    Datadog SaaS     Grafana Cloud
Year 0 (setup)     $35K                $6K              $11K
Year 1             $47K                $76K             $15K
Year 2             $44K                $90K             $20K
Year 3             $59K                $120K            $20K
3-Year TCO         ~$186K              ~$292K           ~$66K

→ Startup: Grafana Cloud ($66K, reasonable ops)
→ Enterprise with budget: Datadog ($292K, zero ops, best DX)
→ DevOps expertise: ELK ($186K, full control)
```

## Tổng kết

```
BUILD khi:                          BUY khi:
  ✅ Core differentiator              ✅ Commodity
  ✅ Unique requirements              ✅ Regulated domain (compliance đắt)
  ✅ Volume khiến SaaS đắt            ✅ Time-to-market critical
  ✅ Team có expertise + bandwidth    ✅ Team thiếu domain expertise

LUÔN:
  ✅ Tính TCO 3 năm, không chỉ setup cost
  ✅ Có abstraction layer (prepare for migration)
  ✅ Review checkpoint mỗi 6-12 tháng
  ✅ Document quyết định trong ADR
```

> **"The best code is no code at all. The second best is code someone else maintains."**
> Build khi đó là competitive advantage. Buy khi đó là commodity.
> Và luôn có exit strategy.
