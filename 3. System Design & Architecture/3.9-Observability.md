# 3.9 Observability

> "Observability is the ability to understand the INTERNAL state of a system
> by examining its EXTERNAL outputs." — logs, metrics, traces.
>
> Không có observability, bạn đang debug bằng cách đoán.

## Three Pillars of Observability

```
Logs:    WHAT happened (events, errors, request details)
Metrics: HOW MUCH is happening (counts, latencies, rates)
Traces:  WHERE in the system (request flow across services)

Logs → Debug specific issues ("Why did this request fail?")
Metrics → Monitor system health ("Is latency increasing?")
Traces → Understand request flow ("Where is the bottleneck?")
```

## Structured Logging

### Đừng log plain text

```typescript
// ❌ Unstructured logs — impossible to parse, search, filter
console.log('User john created order 123 for $50.00');
console.log('Error processing payment: timeout');
console.log('Request took 350ms');

// ✅ Structured logs — machine-parseable, searchable, filterable
logger.info('Order placed', {
  userId: 'user_john',
  orderId: 'order_123',
  amount: 50.00,
  currency: 'USD',
  duration_ms: 350,
});

logger.error('Payment processing failed', {
  orderId: 'order_123',
  paymentProvider: 'stripe',
  error: 'timeout',
  retryCount: 2,
  duration_ms: 5000,
});
```

### Production Logger Implementation

```typescript
// Structured JSON logger with context propagation

type LogLevel = 'debug' | 'info' | 'warn' | 'error';

interface LogEntry {
  level: LogLevel;
  message: string;
  timestamp: string;
  service: string;
  environment: string;
  requestId?: string;
  userId?: string;
  traceId?: string;
  spanId?: string;
  duration_ms?: number;
  error?: {
    name: string;
    message: string;
    stack?: string;
  };
  [key: string]: unknown;
}

class Logger {
  private baseContext: Record<string, unknown> = {};

  constructor(
    private readonly service: string,
    private readonly environment: string,
    private readonly minLevel: LogLevel = 'info',
  ) {}

  // Create child logger with additional context
  child(context: Record<string, unknown>): Logger {
    const child = new Logger(this.service, this.environment, this.minLevel);
    child.baseContext = { ...this.baseContext, ...context };
    return child;
  }

  debug(message: string, context?: Record<string, unknown>): void {
    this.log('debug', message, context);
  }

  info(message: string, context?: Record<string, unknown>): void {
    this.log('info', message, context);
  }

  warn(message: string, context?: Record<string, unknown>): void {
    this.log('warn', message, context);
  }

  error(message: string, error?: Error, context?: Record<string, unknown>): void {
    this.log('error', message, {
      ...context,
      error: error ? {
        name: error.name,
        message: error.message,
        stack: error.stack,
      } : undefined,
    });
  }

  private log(level: LogLevel, message: string, context?: Record<string, unknown>): void {
    if (!this.shouldLog(level)) return;

    const entry: LogEntry = {
      level,
      message,
      timestamp: new Date().toISOString(),
      service: this.service,
      environment: this.environment,
      ...this.baseContext,
      ...context,
    };

    // JSON line — 1 log entry = 1 line (important for log aggregation)
    process.stdout.write(JSON.stringify(entry) + '\n');
  }

  private shouldLog(level: LogLevel): boolean {
    const levels: LogLevel[] = ['debug', 'info', 'warn', 'error'];
    return levels.indexOf(level) >= levels.indexOf(this.minLevel);
  }
}

// Request-scoped logging with middleware
function requestLogger(baseLogger: Logger): Middleware {
  return (req, res, next) => {
    const requestId = req.headers['x-request-id'] as string ?? crypto.randomUUID();
    const startTime = performance.now();

    // Create request-scoped logger
    req.logger = baseLogger.child({
      requestId,
      method: req.method,
      path: req.path,
      userAgent: req.headers['user-agent'],
      ip: req.ip,
    });

    req.logger.info('Request started');

    // Log when response finishes
    res.on('finish', () => {
      const duration_ms = Math.round(performance.now() - startTime);

      const logFn = res.statusCode >= 500 ? 'error'
        : res.statusCode >= 400 ? 'warn'
        : 'info';

      req.logger[logFn]('Request completed', {
        statusCode: res.statusCode,
        duration_ms,
        contentLength: res.getHeader('content-length'),
      });
    });

    // Propagate request ID
    res.setHeader('X-Request-Id', requestId);
    next();
  };
}

// Usage in handlers
app.post('/orders', async (req, res) => {
  req.logger.info('Processing order', { itemCount: req.body.items.length });

  try {
    const order = await orderService.place(req.body);
    req.logger.info('Order placed successfully', { orderId: order.id });
    res.json(order);
  } catch (error) {
    req.logger.error('Order placement failed', error as Error, {
      input: { itemCount: req.body.items?.length },
    });
    throw error;
  }
});
```

### Logging Best Practices

```typescript
// ✅ DO: Log at boundaries (request in, response out, external calls)
// ✅ DO: Include correlation IDs (requestId, traceId)
// ✅ DO: Log business events (order placed, payment completed)
// ✅ DO: Log errors with full context
// ✅ DO: Use appropriate log levels

// ❌ DON'T: Log sensitive data (passwords, tokens, credit cards)
// ❌ DON'T: Log inside tight loops (performance impact)
// ❌ DON'T: Log entire request/response bodies (too verbose, PII risk)
// ❌ DON'T: Use string concatenation (structured context instead)

// Sanitize sensitive data
function sanitizeForLogging(data: Record<string, unknown>): Record<string, unknown> {
  const sensitive = new Set(['password', 'token', 'secret', 'authorization', 'creditCard', 'ssn']);
  const sanitized: Record<string, unknown> = {};
  for (const [key, value] of Object.entries(data)) {
    sanitized[key] = sensitive.has(key.toLowerCase()) ? '[REDACTED]' : value;
  }
  return sanitized;
}
```

## Metrics

### 4 Golden Signals (Google SRE)

```
1. Latency:      How long requests take (p50, p95, p99)
2. Traffic:      How many requests per second (throughput)
3. Errors:       Error rate (percentage of failing requests)
4. Saturation:   How "full" your service is (CPU, memory, queue depth)
```

### Custom Metrics Implementation

```typescript
// Prometheus-compatible metrics

class MetricsCollector {
  private counters = new Map<string, number>();
  private histograms = new Map<string, number[]>();
  private gauges = new Map<string, number>();

  // Counter: only goes up (requests, errors, events)
  increment(name: string, labels?: Record<string, string>, value = 1): void {
    const key = this.buildKey(name, labels);
    this.counters.set(key, (this.counters.get(key) ?? 0) + value);
  }

  // Histogram: distribution of values (latency, response sizes)
  observe(name: string, value: number, labels?: Record<string, string>): void {
    const key = this.buildKey(name, labels);
    const existing = this.histograms.get(key) ?? [];
    existing.push(value);
    this.histograms.set(key, existing);
  }

  // Gauge: current value, can go up or down (queue depth, connections)
  set(name: string, value: number, labels?: Record<string, string>): void {
    const key = this.buildKey(name, labels);
    this.gauges.set(key, value);
  }

  // Timer helper
  startTimer(name: string, labels?: Record<string, string>): () => void {
    const start = performance.now();
    return () => {
      const duration = performance.now() - start;
      this.observe(name, duration, labels);
    };
  }

  // Get percentile from histogram
  getPercentile(name: string, percentile: number, labels?: Record<string, string>): number {
    const key = this.buildKey(name, labels);
    const values = this.histograms.get(key) ?? [];
    if (values.length === 0) return 0;
    const sorted = [...values].sort((a, b) => a - b);
    const index = Math.ceil(sorted.length * (percentile / 100)) - 1;
    return sorted[Math.max(0, index)];
  }

  private buildKey(name: string, labels?: Record<string, string>): string {
    if (!labels) return name;
    const labelStr = Object.entries(labels).map(([k, v]) => `${k}="${v}"`).join(',');
    return `${name}{${labelStr}}`;
  }
}

// Global instance
const metrics = new MetricsCollector();

// HTTP metrics middleware
function metricsMiddleware(collector: MetricsCollector): Middleware {
  return (req, res, next) => {
    const stopTimer = collector.startTimer('http_request_duration_ms', {
      method: req.method,
      path: req.route?.path ?? req.path,
    });

    collector.increment('http_requests_total', {
      method: req.method,
      path: req.route?.path ?? req.path,
    });

    res.on('finish', () => {
      stopTimer();

      collector.increment('http_responses_total', {
        method: req.method,
        status: String(res.statusCode),
        path: req.route?.path ?? req.path,
      });

      if (res.statusCode >= 500) {
        collector.increment('http_errors_total', {
          method: req.method,
          path: req.route?.path ?? req.path,
        });
      }
    });

    next();
  };
}

// Business metrics
class OrderService {
  async placeOrder(command: PlaceOrderCommand): Promise<Order> {
    const stopTimer = metrics.startTimer('order_processing_duration_ms');

    try {
      const order = await this.processOrder(command);

      metrics.increment('orders_placed_total', { plan: command.plan });
      metrics.observe('order_value_cents', order.total.cents);

      stopTimer();
      return order;
    } catch (error) {
      metrics.increment('orders_failed_total', { reason: (error as Error).constructor.name });
      stopTimer();
      throw error;
    }
  }
}

// Expose metrics endpoint (for Prometheus scraping)
app.get('/metrics', (_req, res) => {
  res.setHeader('Content-Type', 'text/plain');
  res.send(metrics.toPrometheusFormat());
});
```

### Key Metrics to Track

```
HTTP Layer:
  http_request_duration_ms{method, path, status}  → Latency
  http_requests_total{method, path}                → Traffic
  http_errors_total{method, path, error_code}      → Errors

Database:
  db_query_duration_ms{query_type, table}
  db_connection_pool_size{state: active|idle|waiting}

  cache_hits_total{cache_name}

Business:
  orders_placed_total{plan, payment_method}
```

## Distributed Tracing

### Concept

```
User Request:
  API Gateway (50ms)
    → Auth Service (20ms)
    → Order Service (200ms)
      → Payment Service (150ms)
      → Inventory Service (80ms)
    → Notification Service (30ms)

Trace: entire request journey across all services
Span: individual operation within a trace
Parent-child: Order Service span is parent of Payment + Inventory spans
```

### Implementation with OpenTelemetry

```typescript
// Trace context propagation

interface TraceContext {
  traceId: string;      // Same for entire request journey
  spanId: string;       // Unique per operation
  parentSpanId?: string;
}

// Generate trace context
function createTraceContext(parentCtx?: TraceContext): TraceContext {
  return {
    traceId: parentCtx?.traceId ?? crypto.randomUUID().replace(/-/g, ''),
    spanId: crypto.randomUUID().replace(/-/g, '').substring(0, 16),
    parentSpanId: parentCtx?.spanId,
  };
}

// Propagate via HTTP headers (W3C Trace Context standard)
// traceparent: 00-<traceId>-<spanId>-01

function injectTraceHeaders(headers: Record<string, string>, ctx: TraceContext): void {
  headers['traceparent'] = `00-${ctx.traceId}-${ctx.spanId}-01`;
}

function extractTraceContext(headers: Record<string, string | undefined>): TraceContext | undefined {
  const traceparent = headers['traceparent'];
  if (!traceparent) return undefined;

  const parts = traceparent.split('-');
  if (parts.length !== 4) return undefined;

  return {
    traceId: parts[1],
    spanId: parts[2],
  };
}

// Middleware: extract or create trace context
function tracingMiddleware(): Middleware {
  return (req, _res, next) => {
    const parentCtx = extractTraceContext(req.headers as Record<string, string>);
    const ctx = createTraceContext(parentCtx);
    req.traceContext = ctx;

    // Add to logger
    req.logger = req.logger?.child({
      traceId: ctx.traceId,
      spanId: ctx.spanId,
    });

    next();
  };
}

// When calling other services: propagate trace context
class HttpClient {
  async request<T>(url: string, options: RequestOptions, traceCtx: TraceContext): Promise<T> {
    const childCtx = createTraceContext(traceCtx);
    const headers: Record<string, string> = { ...options.headers };
    injectTraceHeaders(headers, childCtx);

    const start = performance.now();
    const response = await fetch(url, { ...options, headers });
    const duration = performance.now() - start;

    // Record span
    logger.info('Outbound HTTP call', {
      traceId: childCtx.traceId,
      spanId: childCtx.spanId,
      parentSpanId: childCtx.parentSpanId,
      url,
      method: options.method,
      status: response.status,
      duration_ms: Math.round(duration),
    });

    return response.json();
  }
}
```

## Alerting

### Alert on Symptoms, Not Causes

```typescript
// ❌ Alert on causes (too noisy, too many false positives)
// "CPU > 80%" → So what? If latency is fine, CPU is just working hard
// "1 error in logs" → Errors happen. Is it impacting users?

// ✅ Alert on symptoms (user-facing impact)
// "P99 latency > 2 seconds for 5 minutes" → Users are waiting
// "Error rate > 5% for 3 minutes" → Users are getting errors
// "Order success rate < 95% for 5 minutes" → Revenue impact

// Alert configuration (pseudo-config for Grafana/PagerDuty)
const alerts = [
  {
    name: 'High Error Rate',
    condition: 'rate(http_errors_total[5m]) / rate(http_requests_total[5m]) > 0.05',
    duration: '3m',
    severity: 'critical',
    description: 'Error rate above 5% for 3 minutes',
    runbook: 'https://wiki.internal/runbooks/high-error-rate',
  },
  {
    name: 'High Latency',
    condition: 'histogram_quantile(0.99, http_request_duration_ms) > 2000',
    duration: '5m',
    severity: 'warning',
    description: 'P99 latency above 2 seconds for 5 minutes',
    runbook: 'https://wiki.internal/runbooks/high-latency',
  },
  {
    name: 'Database Connection Pool Exhausted',
    condition: 'db_connection_pool_waiting > 0',
    duration: '1m',
    severity: 'critical',
    description: 'Requests waiting for database connections',
    runbook: 'https://wiki.internal/runbooks/db-pool-exhausted',
  },
  {
    name: 'Queue Depth Growing',
    condition: 'rate(queue_depth[10m]) > 100',
    duration: '10m',
    severity: 'warning',
    description: 'Job queue depth growing — workers may be stuck',
    runbook: 'https://wiki.internal/runbooks/queue-backlog',
  },
];
```

## Implementation Checklist

```
Logging:
  □ Structured JSON logging (not plain text)
  □ Request ID propagation across all services
  □ Log at request boundaries (start, end, error)
  □ Sensitive data redacted (passwords, tokens, PII)
  □ Appropriate log levels (debug/info/warn/error)
  □ Log rotation / retention policy

Metrics:
  □ 4 Golden Signals: latency, traffic, errors, saturation
  □ Business metrics (orders, revenue, signups)
  □ Database metrics (query time, pool utilization)
  □ Cache metrics (hit ratio)
  □ Dashboards for each service
  □ P50/P95/P99 latency tracking

Tracing:
  □ Trace context propagation across services
  □ Span creation for external calls (DB, HTTP, queue)
  □ Trace ID in logs (correlate logs with traces)
  □ Sampling strategy for high-traffic services

Alerting:
  □ Alert on symptoms, not causes
  □ Each alert has a runbook
  □ Severity levels (critical → page, warning → ticket)
  □ Alert fatigue prevention (tune thresholds, reduce noise)
  □ On-call rotation defined

Foundation:
  □ Centralized log aggregation (ELK, Datadog, Grafana Loki)
  □ Metrics collection (Prometheus, Datadog, CloudWatch)
  □ Trace collection (Jaeger, Zipkin, Datadog APM)
  □ Dashboard tool (Grafana, Datadog)
  □ Incident management process defined
```
