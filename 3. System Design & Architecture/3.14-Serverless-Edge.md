## Serverless Architecture

### Core Concepts

```
Traditional Server:
  Server runs 24/7 → pay for idle time → you manage scaling, patches, OS

Serverless (Functions as a Service):
  Function spins up on request → executes → shuts down
  Pay only for execution time
  Auto-scales to demand (0 → 10,000 concurrent)
  AWS Lambda, Cloudflare Workers, Vercel Functions, Google Cloud Functions
```

### Lambda/Function Design cho TypeScript

```typescript
// AWS Lambda handler — cold start optimization

import { APIGatewayProxyHandlerV2 } from 'aws-lambda';

// Module-level: initialized ONCE per cold start, reused across invocations
const db = new Pool({ connectionString: process.env.DATABASE_URL, max: 1 });
// ^^^ max: 1 — Lambda has limited connections. Use RDS Proxy for pooling.

// Handler: runs per request
export const handler: APIGatewayProxyHandlerV2 = async (event) => {
  try {
    const userId = event.pathParameters?.id;
    if (!userId) {
      return { statusCode: 400, body: JSON.stringify({ error: 'Missing user ID' }) };
    }

    const result = await db.query('SELECT id, name, email FROM users WHERE id = $1', [userId]);
    const user = result.rows[0];

    if (!user) {
      return { statusCode: 404, body: JSON.stringify({ error: 'User not found' }) };
    }

    return {
      statusCode: 200,
      headers: { 'Content-Type': 'application/json', 'Cache-Control': 'max-age=60' },
      body: JSON.stringify({ data: user }),
    };
  } catch (error) {
    console.error('Handler error:', error);
    return { statusCode: 500, body: JSON.stringify({ error: 'Internal error' }) };
  }
};

// Cold start optimization:
// 1. Keep bundles small (tree-shake, no unnecessary deps)
// 2. Initialize expensive resources at module level (reused across invocations)
// 3. Use provisioned concurrency for latency-critical functions
// 4. Prefer ARM64 architecture (cheaper, often faster for Node.js)
```

## Edge Computing

### Edge Functions

```typescript
// Cloudflare Workers: runs on 300+ edge locations worldwide
// Latency: ~10ms instead of ~200ms for origin server

// Worker: URL shortener with edge KV storage
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    const shortCode = url.pathname.slice(1); // "/abc123" → "abc123"

    if (!shortCode) {
      return new Response('URL Shortener', { status: 200 });
    }

    // KV lookup at edge — sub-millisecond
    const targetUrl = await env.URL_STORE.get(shortCode);

    if (!targetUrl) {
      return new Response('Not found', { status: 404 });
    }

    // 301 redirect — served from nearest edge node
    return Response.redirect(targetUrl, 301);
  },
};

interface Env {
  URL_STORE: KVNamespace;
}
```

### Edge Middleware (Vercel/Next.js)

```typescript
// middleware.ts — runs at the edge BEFORE your application

import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // A/B Testing at the edge (no origin call needed)
  const bucket = request.cookies.get('ab-bucket')?.value
    ?? (Math.random() < 0.5 ? 'control' : 'variant');

  // Geo-based routing
  const country = request.geo?.country ?? 'US';
  if (country === 'CN') {
    return NextResponse.redirect('https://cn.myapp.com' + request.nextUrl.pathname);
  }

  // Bot detection
  const ua = request.headers.get('user-agent') ?? '';
  if (isBot(ua) && !isGoodBot(ua)) {
    return new NextResponse('Forbidden', { status: 403 });
  }

  // Authentication check (without calling origin)
  const token = request.cookies.get('session')?.value;
  if (request.nextUrl.pathname.startsWith('/dashboard') && !token) {
    return NextResponse.redirect(new URL('/login', request.url));
  }

  const response = NextResponse.next();
  response.cookies.set('ab-bucket', bucket, { maxAge: 86400 });
  return response;
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

### Edge Database (Turso, Cloudflare D1, PlanetScale)

```typescript
// SQLite at the edge — replicated globally

import { createClient } from '@libsql/client';

const db = createClient({
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN,
});

// Read at edge: ~1-5ms (local replica)
const users = await db.execute('SELECT * FROM users WHERE active = 1 LIMIT 20');

// Write to primary → replicates to edge (~50-200ms for propagation)
await db.execute({
  sql: 'INSERT INTO page_views (page, timestamp) VALUES (?, ?)',
  args: ['/home', Date.now()],
});
```

## Serverless Patterns trong TypeScript

### Fan-out / Fan-in

```typescript
// Process large batch: split into parallel chunks

// Fan-out: SQS → N Lambda invocations
async function processLargeBatch(items: Item[]): Promise<void> {
  const chunkSize = 100;
  const chunks = [];
  for (let i = 0; i < items.length; i += chunkSize) {
    chunks.push(items.slice(i, i + chunkSize));
  }

  // Send each chunk to SQS → triggers separate Lambda per chunk
  await Promise.all(chunks.map((chunk, i) =>
    sqs.sendMessage({
      QueueUrl: process.env.PROCESSING_QUEUE_URL!,
      MessageBody: JSON.stringify({ chunkId: i, items: chunk }),
    })
  ));
}

// Each Lambda processes its chunk independently
// Fan-in: results aggregated in DynamoDB or S3
```

### Event-Driven Serverless

```typescript
// S3 upload → Lambda → process → store result

// Lambda triggered by S3 event
export const imageProcessor: S3Handler = async (event) => {
  for (const record of event.Records) {
    const bucket = record.s3.bucket.name;
    const key = decodeURIComponent(record.s3.object.key);

    // Download original
    const original = await s3.getObject({ Bucket: bucket, Key: key });
    const buffer = await streamToBuffer(original.Body);

    // Generate thumbnails (parallel)
    const sizes = [
      { name: 'thumb', width: 150, height: 150 },
      { name: 'medium', width: 600, height: 600 },
      { name: 'large', width: 1200, height: 1200 },
    ];

    await Promise.all(sizes.map(async (size) => {
      const resized = await sharp(buffer)
        .resize(size.width, size.height, { fit: 'inside' })
        .webp({ quality: 80 })
        .toBuffer();

      await s3.putObject({
        Bucket: bucket,
        Key: `processed/${size.name}/${key}.webp`,
        Body: resized,
        ContentType: 'image/webp',
      });
    }));
  }
};
```

## Khi nào dùng / Khi nào KHÔNG

### Serverless

| ✅ Dùng khi | ❌ Không phù hợp khi |
|------------|---------------------|
| Traffic bursty/unpredictable | Steady high traffic (containers cheaper) |
| Event processing (S3, SQS triggers) | Long-running processes (>15min Lambda limit) |
| Cron jobs, scheduled tasks | WebSocket/long connections |
| MVPs, prototypes (zero infra management) | Need fine-grained infra control |
| Low/variable traffic APIs | Latency-critical (cold starts add 100-500ms) |

### Edge

| ✅ Dùng khi | ❌ Không phù hợp khi |
|------------|---------------------|
| Geo-routing, redirects | Heavy computation |
| A/B testing, feature flags | Requires large datasets |
| Auth checks (JWT verify) | Write-heavy workloads |
| Personalization, localization | Complex business logic |
| Static asset optimization | Needs full DB access |
| Rate limiting, bot detection | Needs 100% consistency |

### Cost Comparison

```
Scenario: API handling 1M requests/month, avg 200ms execution

AWS Lambda:
  1M requests × $0.20/1M = $0.20
  1M × 200ms × 128MB = 25,000 GB-seconds × $0.0000166667 = $0.42
  Total: ~$0.62/month

Container (ECS Fargate, always-on):
  1 vCPU + 2GB RAM, running 24/7
  ~$30-40/month

Tipping point: ~10M+ requests/month → containers usually cheaper
Below that: serverless wins on cost
```
