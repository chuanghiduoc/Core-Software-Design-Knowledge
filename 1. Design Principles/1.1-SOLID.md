## S — Single Responsibility Principle

> "A module should have one, and only one, reason to change."
> — Robert C. Martin

### Bản chất

SRP **KHÔNG** có nghĩa là "một class chỉ làm một việc". Nó có nghĩa là **một module chỉ chịu trách nhiệm trước một actor (nhóm stakeholder) duy nhất**. "Reason to change" = một actor yêu cầu thay đổi.

### ❌ Vi phạm SRP

```typescript
// user.service.ts — God Service anti-pattern
class UserService {
  // Actor 1: Business/Product team — logic nghiệp vụ
  calculateSubscriptionPrice(user: User): number {
    if (user.plan === 'enterprise') {
      return user.seats * 29.99 * this.getEnterpriseDiscount(user);
    }
    return user.plan === 'pro' ? 19.99 : 0;
  }

  // Actor 2: DBA/Data team — persistence
  async saveUser(user: User): Promise<void> {
    await this.db.query(
      `INSERT INTO users (id, name, email, plan) VALUES ($1, $2, $3, $4)
       ON CONFLICT (id) DO UPDATE SET name=$2, email=$3, plan=$4`,
      [user.id, user.name, user.email, user.plan]
    );
  }

  // Actor 3: DevOps/Infra team — formatting/reporting
  formatUserReport(user: User): string {
    return `User: ${user.name} | Plan: ${user.plan} | MRR: $${this.calculateSubscriptionPrice(user)}`;
  }

  // Actor 4: Security team — authentication
  async validatePassword(email: string, password: string): Promise<boolean> {
    const user = await this.db.query('SELECT password_hash FROM users WHERE email=$1', [email]);
    return bcrypt.compare(password, user.rows[0].password_hash);
  }
}
```

**Vấn đề:** Khi Product team thay đổi pricing logic, bạn phải sửa cùng file mà DBA team cũng đang sửa query optimization. Merge conflicts, testing nightmare, và blast radius lớn.

### ✅ Áp dụng SRP đúng cách

```typescript
// pricing.service.ts — Actor: Product/Business team
interface PricingStrategy {
  calculate(user: User): Money;
}

class SubscriptionPricingService implements PricingStrategy {
  constructor(private readonly discountPolicy: DiscountPolicy) {}

  calculate(user: User): Money {
    const basePrice = this.getBasePrice(user.plan);
    const discount = this.discountPolicy.getDiscount(user);
    return basePrice.multiply(user.seats).applyDiscount(discount);
  }

  private getBasePrice(plan: Plan): Money {
    const prices: Record<Plan, number> = {
      free: 0,
      pro: 19_99,
      enterprise: 29_99,
    };
    return Money.fromCents(prices[plan]);
  }
}

// user.repository.ts — Actor: DBA/Data team
interface UserRepository {
  save(user: User): Promise<void>;
  findByEmail(email: string): Promise<User | null>;
  findById(id: UserId): Promise<User>;
}

class PostgresUserRepository implements UserRepository {
  constructor(private readonly pool: Pool) {}

  async save(user: User): Promise<void> {
    await this.pool.query(
      `INSERT INTO users (id, name, email, plan)
       VALUES ($1, $2, $3, $4)
       ON CONFLICT (id) DO UPDATE SET name=$2, email=$3, plan=$4`,
      [user.id, user.name, user.email, user.plan]
    );
  }

  async findByEmail(email: string): Promise<User | null> {
    const result = await this.pool.query(
      'SELECT * FROM users WHERE email = $1',
      [email]
    );
    return result.rows[0] ? this.toDomain(result.rows[0]) : null;
  }

  async findById(id: UserId): Promise<User> {
    const result = await this.pool.query(
      'SELECT * FROM users WHERE id = $1',
      [id]
    );
    if (!result.rows[0]) throw new UserNotFoundError(id);
    return this.toDomain(result.rows[0]);
  }

  private toDomain(row: UserRow): User {
    return new User(row.id, row.name, row.email, row.plan);
  }
}

// auth.service.ts — Actor: Security team
class AuthenticationService {
  constructor(
    private readonly userRepo: UserRepository,
    private readonly hasher: PasswordHasher,
    private readonly tokenService: TokenService,
  ) {}

  async authenticate(email: string, password: string): Promise<AuthResult> {
    const user = await this.userRepo.findByEmail(email);
    if (!user) return AuthResult.failed('Invalid credentials');

    const valid = await this.hasher.verify(password, user.passwordHash);
    if (!valid) return AuthResult.failed('Invalid credentials');

    const token = this.tokenService.generate(user);
    return AuthResult.success(token);
  }
}
```

### Real-world signal: Khi nào bạn đang vi phạm SRP?

- File có > 300 dòng và ngày càng phình to
- Bạn phải `import` quá nhiều dependencies không liên quan
- Khi sửa bug ở feature A, test của feature B bị fail
- Merge conflicts xảy ra thường xuyên trên cùng file
- Bạn không biết đặt tên class/file gì → nó đang làm quá nhiều việc

## O — Open/Closed Principle

> "Software entities should be open for extension, but closed for modification."
> — Bertrand Meyer

### Bản chất

Khi requirements mới đến, bạn **thêm code mới** thay vì **sửa code cũ**. Điều này giảm risk regression và cho phép nhiều team làm việc song song.

### ❌ Vi phạm OCP — switch/if-else chain

```typescript
// notification.service.ts
class NotificationService {
  async send(userId: string, message: string, channel: string): Promise<void> {
    // Mỗi lần thêm channel mới → sửa function này → risk break channels cũ
    if (channel === 'email') {
      await this.sendGrid.send({ to: userId, body: message });
    } else if (channel === 'sms') {
      await this.twilio.send({ to: userId, body: message });
    } else if (channel === 'slack') {
      await this.slack.postMessage({ channel: userId, text: message });
    } else if (channel === 'push') {
      // Mới thêm tuần trước, phải sửa function đang chạy tốt
      await this.firebase.send({ token: userId, notification: { body: message } });
    }
    // Tuần sau thêm WhatsApp? Lại sửa file này...
  }
}
```

### ✅ Áp dụng OCP — Strategy Pattern + Registry

```typescript
// notification-channel.ts — Interface contract (đóng cho modification)
interface NotificationChannel {
  readonly channelType: string;
  send(recipient: Recipient, message: NotificationMessage): Promise<DeliveryResult>;
  supports(recipient: Recipient): boolean;
}

// email-channel.ts — Extension (mở cho extension)
class EmailChannel implements NotificationChannel {
  readonly channelType = 'email';

  constructor(private readonly sendGrid: SendGridClient) {}

  supports(recipient: Recipient): boolean {
    return !!recipient.email && recipient.preferences.emailEnabled;
  }

  async send(recipient: Recipient, message: NotificationMessage): Promise<DeliveryResult> {
    const response = await this.sendGrid.send({
      to: recipient.email,
      subject: message.subject,
      html: message.htmlBody,
    });
    return DeliveryResult.fromSendGrid(response);
  }
}

// sms-channel.ts — Thêm channel mới = thêm file mới, KHÔNG sửa code cũ
class SmsChannel implements NotificationChannel {
  readonly channelType = 'sms';

  constructor(private readonly twilio: TwilioClient) {}

  supports(recipient: Recipient): boolean {
    return !!recipient.phone && recipient.preferences.smsEnabled;
  }

  async send(recipient: Recipient, message: NotificationMessage): Promise<DeliveryResult> {
    const response = await this.twilio.messages.create({
      to: recipient.phone,
      body: message.plainText,
    });
    return DeliveryResult.fromTwilio(response);
  }
}

// notification.service.ts — Orchestrator (đóng cho modification)
class NotificationService {
  constructor(private readonly channels: ReadonlyArray<NotificationChannel>) {}

  async send(recipient: Recipient, message: NotificationMessage): Promise<DeliveryReport> {
    const applicableChannels = this.channels.filter(ch => ch.supports(recipient));

    const results = await Promise.allSettled(
      applicableChannels.map(ch => ch.send(recipient, message))
    );

    return new DeliveryReport(applicableChannels, results);
  }
}
```

### OCP trong TypeScript thực tế — Discriminated Unions

OCP không chỉ là class. Trong TypeScript, discriminated unions + exhaustive switch cũng là một dạng OCP:

```typescript
// Approach: Dùng type system để enforce completeness khi extend

// events.ts — Thêm event mới ở đây
type DomainEvent =
  | { type: 'USER_CREATED'; payload: { userId: string; email: string } }
  | { type: 'USER_UPGRADED'; payload: { userId: string; newPlan: Plan } }
  | { type: 'USER_DELETED'; payload: { userId: string; reason: string } };
  // Thêm event mới → compiler sẽ báo lỗi ở tất cả handler chưa xử lý

// Exhaustive check helper
function assertNever(x: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(x)}`);
}

// event-handler.ts
function handleEvent(event: DomainEvent): void {
  switch (event.type) {
    case 'USER_CREATED':
      sendWelcomeEmail(event.payload.email);
      break;
    case 'USER_UPGRADED':
      provisionNewFeatures(event.payload.userId, event.payload.newPlan);
      break;
    case 'USER_DELETED':
      scheduleDataDeletion(event.payload.userId);
      break;
    default:
      // Nếu thêm event mới mà quên xử lý → COMPILE ERROR
      assertNever(event);
  }
}
```

### Real-world: Plugin Architecture

```typescript
// Ví dụ: Payment gateway plugin system (như Stripe, PayPal, VNPay...)

interface PaymentGateway {
  readonly name: string;
  charge(amount: Money, source: PaymentSource): Promise<ChargeResult>;
  refund(chargeId: string, amount?: Money): Promise<RefundResult>;
  createCustomer(info: CustomerInfo): Promise<GatewayCustomerId>;
}

// Plugin registry — cho phép runtime extension
class PaymentGatewayRegistry {
  private readonly gateways = new Map<string, PaymentGateway>();

  register(gateway: PaymentGateway): void {
    if (this.gateways.has(gateway.name)) {
      throw new DuplicateGatewayError(gateway.name);
    }
    this.gateways.set(gateway.name, gateway);
  }

  get(name: string): PaymentGateway {
    const gateway = this.gateways.get(name);
    if (!gateway) throw new GatewayNotFoundError(name);
    return gateway;
  }

  listAvailable(): ReadonlyArray<string> {
    return Array.from(this.gateways.keys());
  }
}
```

## L — Liskov Substitution Principle

> "Objects of a superclass should be replaceable with objects of its subclasses without affecting the correctness of the program."
> — Barbara Liskov

### Bản chất

Nếu `B extends A`, thì mọi nơi dùng `A` phải có thể thay bằng `B` mà **không có hành vi bất ngờ**. Đây là nguyên lý bị vi phạm nhiều nhất và khó phát hiện nhất.

### ❌ Vi phạm LSP kinh điển — Rectangle/Square

```typescript
class Rectangle {
  constructor(protected width: number, protected height: number) {}

  setWidth(w: number): void { this.width = w; }
  setHeight(h: number): void { this.height = h; }
  getArea(): number { return this.width * this.height; }
}

class Square extends Rectangle {
  setWidth(w: number): void {
    // Vi phạm LSP: thay đổi behavior của parent
    this.width = w;
    this.height = w; // Side effect bất ngờ!
  }

  setHeight(h: number): void {
    this.width = h;
    this.height = h; // Side effect bất ngờ!
  }
}

// Client code expects Rectangle behavior
function doubleWidth(rect: Rectangle): void {
  const originalHeight = rect.getArea() / rect.getArea(); // giả sử lấy height
  rect.setWidth(rect.getArea() / 10 * 2); // Logic dựa trên Rectangle contract
  // Nếu truyền Square vào → height cũng thay đổi → KẾT QUẢ SAI
}
```

### ✅ Giải quyết LSP — Immutable Value Objects

```typescript
// Cách đúng: dùng immutable objects, tránh mutable inheritance

interface Shape {
  readonly area: number;
  readonly perimeter: number;
}

class Rectangle implements Shape {
  constructor(
    readonly width: number,
    readonly height: number,
  ) {}

  get area(): number { return this.width * this.height; }
  get perimeter(): number { return 2 * (this.width + this.height); }

  withWidth(w: number): Rectangle { return new Rectangle(w, this.height); }
  withHeight(h: number): Rectangle { return new Rectangle(this.width, h); }
}

class Square implements Shape {
  constructor(readonly side: number) {}

  get area(): number { return this.side ** 2; }
  get perimeter(): number { return 4 * this.side; }

  withSide(s: number): Square { return new Square(s); }
}

// Không có inheritance → không có LSP violation
// Cả hai implement Shape → polymorphism qua interface, không qua class hierarchy
```

### ❌ Vi phạm LSP trong TypeScript thực tế — Throwing unexpectedly

```typescript
interface UserRepository {
  findById(id: string): Promise<User | null>;
}

// Implementation A — đúng contract
class PostgresUserRepository implements UserRepository {
  async findById(id: string): Promise<User | null> {
    const row = await this.db.query('SELECT * FROM users WHERE id=$1', [id]);
    return row ? this.toUser(row) : null;
  }
}

// Implementation B — VI PHẠM LSP
class CachedUserRepository implements UserRepository {
  async findById(id: string): Promise<User | null> {
    const cached = await this.redis.get(`user:${id}`);
    if (!cached) {
      // Vi phạm: throw thay vì return null
      // Caller expect null, nhận được exception
      throw new CacheMissError(id);
    }
    return JSON.parse(cached);
  }
}
```

### ✅ LSP đúng cách — Contract consistency

```typescript
interface UserRepository {
  /**
   * @returns User if found, null if not found
   * @throws RepositoryError only for infrastructure failures (DB down, network error)
   */
  findById(id: string): Promise<User | null>;
}

class CachedUserRepository implements UserRepository {
  constructor(
    private readonly cache: CacheClient,
    private readonly fallback: UserRepository, // Decorator pattern
  ) {}

  async findById(id: string): Promise<User | null> {
    // Cache miss → delegate to fallback, KHÔNG throw
    const cached = await this.cache.get(`user:${id}`);
    if (cached) return this.deserialize(cached);

    const user = await this.fallback.findById(id);
    if (user) await this.cache.set(`user:${id}`, this.serialize(user));
    return user;
  }
}
```

### LSP Checklist cho TypeScript

| Rule | Mô tả |
|------|--------|
| **Preconditions** | Subtype KHÔNG được yêu cầu nhiều hơn parent (params chặt hơn) |
| **Postconditions** | Subtype KHÔNG được trả về ít hơn parent (return lỏng hơn) |
| **Invariants** | Subtype phải giữ mọi invariant của parent |
| **Exceptions** | Subtype KHÔNG được throw exception types mà parent không throw |
| **History constraint** | Subtype KHÔNG được cho phép state changes mà parent không cho phép |

## I — Interface Segregation Principle

> "No client should be forced to depend on methods it does not use."
> — Robert C. Martin

### Bản chất

Interface lớn → split thành nhiều interface nhỏ, mỗi cái phục vụ một nhóm client cụ thể. Trong TypeScript, đây là nguyên lý dễ áp dụng nhất nhờ structural typing.

### ❌ Vi phạm ISP — Fat Interface

```typescript
// ❌ Mọi storage provider đều phải implement TẤT CẢ methods
interface FileStorage {
  upload(file: Buffer, path: string): Promise<string>;
  download(path: string): Promise<Buffer>;
  delete(path: string): Promise<void>;
  list(prefix: string): Promise<string[]>;
  getSignedUrl(path: string, expiry: number): Promise<string>;
  setAcl(path: string, acl: AclPolicy): Promise<void>;
  enableVersioning(bucket: string): Promise<void>;
  getMetadata(path: string): Promise<FileMetadata>;
  copyBetweenBuckets(src: string, dest: string): Promise<void>;
}

// Local file system không hỗ trợ signed URLs hay ACL
class LocalFileStorage implements FileStorage {
  async getSignedUrl(): Promise<string> {
    throw new Error('Not supported'); // ISP violation → client phải handle exception
  }
  async setAcl(): Promise<void> {
    throw new Error('Not supported'); // ISP violation
  }
  async enableVersioning(): Promise<void> {
    throw new Error('Not supported'); // ISP violation
  }
  // ... phải implement hàng loạt method vô nghĩa
}
```

### ✅ Áp dụng ISP — Segregated Interfaces

```typescript
// Core operations — mọi storage đều phải hỗ trợ
interface FileReader {
  download(path: string): Promise<Buffer>;
  getMetadata(path: string): Promise<FileMetadata>;
}

interface FileWriter {
  upload(file: Buffer, path: string): Promise<string>;
  delete(path: string): Promise<void>;
}

interface FileLister {
  list(prefix: string): Promise<string[]>;
}

// Cloud-specific capabilities
interface SignedUrlProvider {
  getSignedUrl(path: string, expiry: number): Promise<string>;
}

interface AclManager {
  setAcl(path: string, acl: AclPolicy): Promise<void>;
}

interface VersioningManager {
  enableVersioning(bucket: string): Promise<void>;
}

// Compose interfaces cho từng use case
type BasicStorage = FileReader & FileWriter & FileLister;
type CloudStorage = BasicStorage & SignedUrlProvider & AclManager;

// S3 implement full cloud capabilities
class S3Storage implements CloudStorage {
  async download(path: string): Promise<Buffer> { /* ... */ }
  async upload(file: Buffer, path: string): Promise<string> { /* ... */ }
  async delete(path: string): Promise<void> { /* ... */ }
  async list(prefix: string): Promise<string[]> { /* ... */ }
  async getMetadata(path: string): Promise<FileMetadata> { /* ... */ }
  async getSignedUrl(path: string, expiry: number): Promise<string> { /* ... */ }
  async setAcl(path: string, acl: AclPolicy): Promise<void> { /* ... */ }
}

// Local chỉ implement những gì cần thiết
class LocalStorage implements BasicStorage {
  async download(path: string): Promise<Buffer> { /* fs.readFile */ }
  async upload(file: Buffer, path: string): Promise<string> { /* fs.writeFile */ }
  async delete(path: string): Promise<void> { /* fs.unlink */ }
  async list(prefix: string): Promise<string[]> { /* fs.readdir */ }
  async getMetadata(path: string): Promise<FileMetadata> { /* fs.stat */ }
}

// Client chỉ depend on interfaces mà nó THỰC SỰ dùng
class ThumbnailService {
  // Chỉ cần đọc và ghi, không cần ACL hay signed URLs
  constructor(
    private readonly reader: FileReader,
    private readonly writer: FileWriter,
  ) {}

  async generateThumbnail(sourcePath: string): Promise<string> {
    const original = await this.reader.download(sourcePath);
    const thumbnail = await sharp(original).resize(200, 200).toBuffer();
    return this.writer.upload(thumbnail, `thumbnails/${sourcePath}`);
  }
}

// API endpoint cần signed URLs → declare dependency explicitly
class FileShareController {
  constructor(private readonly urlProvider: SignedUrlProvider) {}

  async createShareLink(path: string): Promise<{ url: string }> {
    const url = await this.urlProvider.getSignedUrl(path, 3600);
    return { url };
  }
}
```

## D — Dependency Inversion Principle

> "High-level modules should not depend on low-level modules. Both should depend on abstractions."
> — Robert C. Martin

### Bản chất

Đây là nguyên lý **QUAN TRỌNG NHẤT** trong SOLID. Nó là foundation cho testability, flexibility, và clean architecture. Flow of control và flow of dependency **đi ngược chiều nhau**.

### ❌ Vi phạm DIP — Direct dependency

```typescript
// order.service.ts — High-level module trực tiếp depend on low-level modules
import { Pool } from 'pg';                    // Direct DB dependency
import Stripe from 'stripe';                  // Direct payment dependency
import { SESClient } from '@aws-sdk/client-ses'; // Direct email dependency

class OrderService {
  private db = new Pool({ connectionString: process.env.DATABASE_URL });
  private stripe = new Stripe(process.env.STRIPE_KEY!);
  private ses = new SESClient({ region: 'us-east-1' });

  async placeOrder(userId: string, items: CartItem[]): Promise<Order> {
    // Vấn đề 1: Không thể test mà không có real DB + Stripe + SES
    // Vấn đề 2: Đổi từ Stripe sang PayPal → sửa file này
    // Vấn đề 3: Đổi từ SES sang SendGrid → sửa file này
    // Vấn đề 4: Business logic bị trộn lẫn với infrastructure

    const order = this.calculateOrder(items);
    await this.db.query('INSERT INTO orders ...', [order]);
    await this.stripe.charges.create({ amount: order.total });
    await this.ses.send(/* ... */);
    return order;
  }
}
```

### ✅ Áp dụng DIP — Depend on abstractions

```typescript
// ports/order.repository.ts — Abstraction (owned by high-level module)
interface OrderRepository {
  save(order: Order): Promise<void>;
  findById(id: OrderId): Promise<Order>;
  findByUser(userId: UserId): Promise<ReadonlyArray<Order>>;
}

// ports/payment.gateway.ts
interface PaymentGateway {
  charge(amount: Money, customerId: CustomerId): Promise<PaymentResult>;
  refund(paymentId: PaymentId): Promise<RefundResult>;
}

// ports/notification.service.ts
interface OrderNotifier {
  notifyOrderPlaced(order: Order): Promise<void>;
  notifyOrderShipped(order: Order, tracking: TrackingInfo): Promise<void>;
}

// order.service.ts — High-level module depends ONLY on abstractions
class OrderService {
  constructor(
    private readonly orders: OrderRepository,
    private readonly payment: PaymentGateway,
    private readonly notifier: OrderNotifier,
    private readonly eventBus: EventBus,
  ) {}

  async placeOrder(userId: UserId, items: ReadonlyArray<CartItem>): Promise<Order> {
    const order = Order.create(userId, items);

    const paymentResult = await this.payment.charge(order.total, userId);
    if (!paymentResult.success) {
      throw new PaymentFailedError(paymentResult.error);
    }

    order.markPaid(paymentResult.paymentId);
    await this.orders.save(order);

    // Fire-and-forget notification
    this.notifier.notifyOrderPlaced(order).catch(err =>
      console.error('Failed to notify order placed', err)
    );

    await this.eventBus.publish(new OrderPlacedEvent(order));

    return order;
  }
}

// adapters/postgres-order.repository.ts — Low-level module implements abstraction
class PostgresOrderRepository implements OrderRepository {
  constructor(private readonly pool: Pool) {}

  async save(order: Order): Promise<void> {
    await this.pool.query(
      `INSERT INTO orders (id, user_id, total, status, payment_id, created_at)
```

## SOLID trong thực tế: Khi nào bẻ cong?

### Khi nào KHÔNG cần SOLID

| Tình huống | Lý do |
|-----------|-------|
| Script one-off, CLI tool nhỏ | Chi phí abstraction > lợi ích. Viết thẳng, chạy xong xoá |
| Prototype / PoC | Mục tiêu là validate idea, không phải maintainability |
| Glue code giữa 2 hệ thống | Đôi khi direct coupling rõ ràng hơn abstract coupling |
| Performance-critical hot path | Abstraction có cost. Trong tight loop, direct call nhanh hơn virtual dispatch |

### SOLID Anti-patterns phổ biến

| Anti-pattern | Vấn đề |
|-------------|--------|
| **Interface cho mọi class** | 1 interface : 1 implementation = noise, không phải SOLID |
| **Abstract quá sớm** | Chưa có 2 implementations → chưa cần interface |
| **Layer cake** | Controller → Service → Repository → DAO → Entity khi app chỉ là CRUD |
| **DI container everywhere** | Service locator pattern ẩn dependencies, khó debug hơn constructor injection |

### Nguyên tắc vàng

> **Đừng SOLID vì SOLID. SOLID vì nó giải quyết vấn đề thực tế bạn đang gặp.**
>
> Nếu bạn chỉ có 1 loại database và không có kế hoạch thay đổi, đừng tạo `DatabasePort` abstract.
> Nhưng nếu bạn cần test mà không muốn spin up Postgres → abstract là hợp lý.
>
> **Rule of Three**: Chờ đến khi bạn cần lần thứ 3 mới abstract. Lần 1 viết thẳng, lần 2 copy, lần 3 refactor.
