## Tại sao cần Architecture?

Architecture tốt cho phép bạn **delay decisions** (chọn DB sau, chọn framework sau) và **isolate change** (sửa 1 phần không phá phần khác).

### Dấu hiệu architecture tệ

- Sửa API endpoint → phải sửa business logic
- Đổi database → phải rewrite toàn bộ service layer
- Test 1 function → phải spin up database + Redis + 3rd party APIs
- Thêm 1 feature → phải sửa 15 files ở 8 folders khác nhau
- Import cycles (`A imports B imports C imports A`)

## Layered Architecture (N-Tier)

Cách tổ chức truyền thống nhất. Tách code thành layers, mỗi layer chỉ gọi layer ngay bên dưới.

```
┌─────────────────────────┐
│   Presentation Layer    │  Controllers, Views, DTOs
├─────────────────────────┤
│   Business Logic Layer  │  Services, Domain Models
├─────────────────────────┤
│   Data Access Layer     │  Repositories, ORMs
├─────────────────────────┤
│   Database              │  PostgreSQL, Redis, etc.
└─────────────────────────┘

Dependency flow: Top → Bottom (Presentation → Data Access)
```

### Implementation trong TypeScript

```typescript
// === Presentation Layer ===
// controllers/user.controller.ts
class UserController {
  constructor(private readonly userService: UserService) {}

  async getUser(req: Request, res: Response): Promise<void> {
    const user = await this.userService.findById(req.params.id);
    if (!user) {
      res.status(404).json({ error: 'User not found' });
      return;
    }
    res.json(UserDto.from(user));
  }

  async createUser(req: Request, res: Response): Promise<void> {
    const input = CreateUserSchema.parse(req.body);
    const user = await this.userService.create(input);
    res.status(201).json(UserDto.from(user));
  }
}

// === Business Logic Layer ===
// services/user.service.ts
class UserService {
  constructor(private readonly userRepo: UserRepository) {}

  async findById(id: string): Promise<User | null> {
    return this.userRepo.findById(id);
  }

  async create(input: CreateUserInput): Promise<User> {
    const existing = await this.userRepo.findByEmail(input.email);
    if (existing) throw new DuplicateEmailError(input.email);

    const user = User.create(input.name, input.email);
    await this.userRepo.save(user);
    return user;
  }
}

// === Data Access Layer ===
// repositories/user.repository.ts
class UserRepository {
  constructor(private readonly db: Knex) {}

  async findById(id: string): Promise<User | null> {
    const row = await this.db('users').where({ id }).first();
    return row ? this.toDomain(row) : null;
  }

  async save(user: User): Promise<void> {
    await this.db('users').insert(this.toRow(user))
      .onConflict('id').merge();
  }
}
```

### Vấn đề của Layered Architecture

| Vấn đề | Giải thích |
|--------|------------|
| **Database-driven** | Dependency chạy từ trên xuống → DB là trung tâm, domain phụ thuộc vào DB schema |
| **Leaky abstractions** | ORM entities leak vào service layer, Prisma types leak vào controllers |
| **Test khó** | Service layer depend trực tiếp vào concrete Repository (cần DB để test) |
| **Rigid coupling** | Đổi từ Prisma sang Drizzle → phải rewrite services |

## Hexagonal Architecture (Ports & Adapters)

> "Allow an application to equally be driven by users, programs, automated tests, or batch scripts,
> and to be developed and tested in isolation from its eventual runtime devices and databases."
> — Alistair Cockburn (2005)

### Core Concept

Application ở **trung tâm**, giao tiếp với thế giới bên ngoài qua **Ports** (interfaces) và **Adapters** (implementations).

```
                    ┌──────────────────┐
                    │   REST Adapter   │
                    │   (Express)      │
                    └────────┬─────────┘
                             │
┌──────────────┐    ┌────────▼─────────┐    ┌──────────────┐
│  CLI Adapter │───►│                  │◄───│ Queue Adapter│
│              │    │   APPLICATION    │    │  (BullMQ)    │
└──────────────┘    │                  │    └──────────────┘
                    │   ┌──────────┐   │
┌──────────────┐    │   │  DOMAIN  │   │    ┌──────────────┐
│ gRPC Adapter │───►│   │  (Core)  │   │◄───│ Cron Adapter │
│              │    │   └──────────┘   │    │              │
└──────────────┘    │                  │    └──────────────┘
                    └──┬──────────┬────┘
                       │          │
              ┌────────▼──┐  ┌────▼────────┐
              │ DB Adapter│  │ Email Adapter│
              │ (Postgres)│  │ (SendGrid)   │
              └───────────┘  └─────────────┘

Driving Adapters (left): drive the application (HTTP, CLI, Queue)
Driven Adapters (right): driven BY the application (DB, Email, Cache)
```

### Ports — Interfaces owned by the domain

```typescript

// ports/driving/user.use-cases.ts

// Mỗi use case = 1 port method (hoặc 1 port interface)
interface CreateUserUseCase {
  execute(command: CreateUserCommand): Promise<UserId>;
}

interface GetUserUseCase {
  execute(query: GetUserQuery): Promise<UserView | null>;
}

interface ListUsersUseCase {
  execute(query: ListUsersQuery): Promise<PaginatedResult<UserView>>;
}

interface SuspendUserUseCase {
  execute(command: SuspendUserCommand): Promise<void>;
}

// Commands & Queries — immutable value objects
class CreateUserCommand {
  constructor(
    readonly name: string,
    readonly email: string,
    readonly role: Role = 'viewer',
  ) {
    // Fail fast validation
    if (!name.trim()) throw new ValidationError('name', 'Name is required');
    if (!email.includes('@')) throw new ValidationError('email', 'Invalid email');
  }
}

class ListUsersQuery {
  constructor(
    readonly page: number = 1,
    readonly pageSize: number = 20,
    readonly status?: UserStatus,
    readonly search?: string,
  ) {
    if (page < 1) throw new ValidationError('page', 'Must be >= 1');
    if (pageSize < 1 || pageSize > 100) throw new ValidationError('pageSize', 'Must be 1-100');
  }
}

// === DRIVEN PORTS (Secondary) — Interfaces the app REQUIRES from outside ===
// ports/driven/user.repository.ts

interface UserRepository {
  findById(id: UserId): Promise<User | null>;
  findByEmail(email: Email): Promise<User | null>;
  save(user: User): Promise<void>;
  delete(id: UserId): Promise<void>;
  findAll(criteria: UserSearchCriteria): Promise<PaginatedResult<User>>;
}
```

### Domain — Business logic, ZERO external dependencies

```typescript
// domain/user.ts
// KHÔNG import từ express, prisma, redis, hoặc BẤT KỲ library nào

class User {
  private readonly _domainEvents: DomainEvent[] = [];

  private constructor(
    readonly id: UserId,
    private _name: string,
    private _email: Email,
    private _role: Role,
    private _status: UserStatus,
    readonly createdAt: Date,
    private _updatedAt: Date,
  ) {}

  static create(id: UserId, name: string, email: Email, role: Role = 'viewer'): User {
    const user = new User(id, name, email, role, 'active', new Date(), new Date());
    user.addEvent(new UserCreatedEvent(id, name, email));
    return user;
  }

  static reconstitute(props: UserProps): User {
    // Factory method cho hydration từ DB (không emit events)
    return new User(
      props.id, props.name, props.email,
      props.role, props.status, props.createdAt, props.updatedAt,
    );
  }

  get name(): string { return this._name; }
  get email(): Email { return this._email; }
  get role(): Role { return this._role; }
  get status(): UserStatus { return this._status; }

  changeName(newName: string): void {
    if (!newName.trim()) throw new DomainError('Name cannot be empty');
    if (newName === this._name) return;
    this._name = newName;
    this._updatedAt = new Date();
  }

  changeEmail(newEmail: Email): void {
    if (newEmail === this._email) return;
    const oldEmail = this._email;
    this._email = newEmail;
    this._updatedAt = new Date();
    this.addEvent(new UserEmailChangedEvent(this.id, oldEmail, newEmail));
  }

  promote(newRole: Role): void {
    if (this._status !== 'active') {
      throw new DomainError(`Cannot promote ${this._status} user`);
    }
    this._role = newRole;
    this._updatedAt = new Date();
  }

  suspend(reason: string): void {
    if (this._status === 'suspended') throw new DomainError('User already suspended');
    if (this._role === 'admin') throw new DomainError('Cannot suspend admin');
    this._status = 'suspended';
    this._updatedAt = new Date();
    this.addEvent(new UserSuspendedEvent(this.id, reason));
  }

  reactivate(): void {
    if (this._status !== 'suspended') throw new DomainError('User is not suspended');
    this._status = 'active';
    this._updatedAt = new Date();
  }

  get domainEvents(): ReadonlyArray<DomainEvent> {
    return this._domainEvents;
  }

  clearEvents(): void {
    this._domainEvents.length = 0;
  }

  private addEvent(event: DomainEvent): void {
    this._domainEvents.push(event);
  }
}

// domain/value-objects/email.ts
class Email {
  private constructor(readonly value: string) {}

  static create(raw: string): Email {
    const normalized = raw.trim().toLowerCase();
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(normalized)) {
      throw new DomainError(`Invalid email: ${raw}`);
    }
    return new Email(normalized);
  }

  get domain(): string {
    return this.value.split('@')[1];
  }

  equals(other: Email): boolean {
    return this.value === other.value;
  }

  toString(): string {
    return this.value;
  }
}
```

### Application — Use case orchestration

```typescript
// application/create-user.use-case.ts
class CreateUserService implements CreateUserUseCase {
  constructor(
    private readonly userRepo: UserRepository,        // Driven port
    private readonly eventPublisher: DomainEventPublisher, // Driven port
    private readonly idGenerator: IdGenerator,         // Driven port
  ) {}

  async execute(command: CreateUserCommand): Promise<UserId> {
    const email = Email.create(command.email);

    // Business rule: unique email
    const existing = await this.userRepo.findByEmail(email);
    if (existing) throw new DuplicateEmailError(email);

    // Create domain object
    const userId = this.idGenerator.generate();
    const user = User.create(userId, command.name, email, command.role);

    // Persist
    await this.userRepo.save(user);

    // Publish domain events
    await this.eventPublisher.publishAll(user.domainEvents);
    user.clearEvents();

    return userId;
  }
}

// application/suspend-user.use-case.ts
class SuspendUserService implements SuspendUserUseCase {
  constructor(
    private readonly userRepo: UserRepository,
    private readonly eventPublisher: DomainEventPublisher,
  ) {}

  async execute(command: SuspendUserCommand): Promise<void> {
    const user = await this.userRepo.findById(command.userId);
    if (!user) throw new UserNotFoundError(command.userId);

    user.suspend(command.reason); // Domain logic decides if valid

    await this.userRepo.save(user);
    await this.eventPublisher.publishAll(user.domainEvents);
    user.clearEvents();
  }
}
```

### Adapters — Connect to the real world

```typescript
// === DRIVING ADAPTER: Express HTTP ===
// adapters/driving/http/user.routes.ts
function createUserRoutes(deps: {
  createUser: CreateUserUseCase;
  getUser: GetUserUseCase;
  listUsers: ListUsersUseCase;
  suspendUser: SuspendUserUseCase;
}): Router {
  const router = Router();

  router.post('/users', async (req, res, next) => {
    try {
      const command = new CreateUserCommand(req.body.name, req.body.email, req.body.role);
      const userId = await deps.createUser.execute(command);
      res.status(201).json({ id: userId });
    } catch (error) {
      next(error);
    }
  });

  router.get('/users/:id', async (req, res, next) => {
    try {
      const query = new GetUserQuery(req.params.id as UserId);
      const user = await deps.getUser.execute(query);
      if (!user) {
        res.status(404).json({ error: 'User not found' });
        return;
      }
      res.json(user);
    } catch (error) {
      next(error);
    }
  });

  router.get('/users', async (req, res, next) => {
    try {
      const query = new ListUsersQuery(
        Number(req.query.page) || 1,
        Number(req.query.pageSize) || 20,
        req.query.status as UserStatus | undefined,
        req.query.search as string | undefined,
      );
      const result = await deps.listUsers.execute(query);
      res.json(result);
    } catch (error) {
      next(error);
    }
  });

  router.post('/users/:id/suspend', async (req, res, next) => {
    try {
      const command = new SuspendUserCommand(req.params.id as UserId, req.body.reason);
      await deps.suspendUser.execute(command);
      res.status(204).end();
    } catch (error) {
      next(error);
    }
  });

  return router;
}

// === DRIVEN ADAPTER: PostgreSQL ===
// adapters/driven/postgres/postgres-user.repository.ts
class PostgresUserRepository implements UserRepository {
  constructor(private readonly db: Knex) {}

  async findById(id: UserId): Promise<User | null> {
    const row = await this.db('users').where({ id }).first();
    return row ? this.toDomain(row) : null;
  }

  async findByEmail(email: Email): Promise<User | null> {
    const row = await this.db('users').where({ email: email.value }).first();
    return row ? this.toDomain(row) : null;
  }

  async save(user: User): Promise<void> {
    await this.db('users')
      .insert({
        id: user.id,
        name: user.name,
        email: user.email.value,
        role: user.role,
        status: user.status,
        created_at: user.createdAt,
        updated_at: new Date(),
      })
      .onConflict('id')
      .merge(['name', 'email', 'role', 'status', 'updated_at']);
  }

  async delete(id: UserId): Promise<void> {
    await this.db('users').where({ id }).delete();
  }

  async findAll(criteria: UserSearchCriteria): Promise<PaginatedResult<User>> {
    let query = this.db('users');

    if (criteria.status) query = query.where('status', criteria.status);
    if (criteria.search) {
      query = query.where(function () {
        this.whereILike('name', `%${criteria.search}%`)
          .orWhereILike('email', `%${criteria.search}%`);
      });
    }

    const [{ count }] = await query.clone().count('* as count');
    const rows = await query
      .orderBy('created_at', 'desc')
      .limit(criteria.pageSize)
      .offset((criteria.page - 1) * criteria.pageSize);

    return {
      data: rows.map(this.toDomain),
      total: Number(count),
      page: criteria.page,
      pageSize: criteria.pageSize,
    };
  }

  private toDomain(row: any): User {
    return User.reconstitute({
      id: row.id,
      name: row.name,
      email: Email.create(row.email),
      role: row.role,
      status: row.status,
      createdAt: row.created_at,
      updatedAt: row.updated_at,
    });
  }
}

// === DRIVEN ADAPTER: In-Memory (for tests) ===
// adapters/driven/in-memory/in-memory-user.repository.ts
class InMemoryUserRepository implements UserRepository {
  private users = new Map<string, User>();

  async findById(id: UserId): Promise<User | null> {
    return this.users.get(id) ?? null;
  }

  async findByEmail(email: Email): Promise<User | null> {
    for (const user of this.users.values()) {
      if (user.email.equals(email)) return user;
    }
    return null;
  }

  async save(user: User): Promise<void> {
    this.users.set(user.id, user);
  }

  async delete(id: UserId): Promise<void> {
    this.users.delete(id);
  }

  async findAll(criteria: UserSearchCriteria): Promise<PaginatedResult<User>> {
    let results = [...this.users.values()];
    if (criteria.status) results = results.filter(u => u.status === criteria.status);
    if (criteria.search) {
      const s = criteria.search.toLowerCase();
      results = results.filter(u =>
        u.name.toLowerCase().includes(s) || u.email.value.includes(s)
      );
    }
    const total = results.length;
    const start = (criteria.page - 1) * criteria.pageSize;
    return {
      data: results.slice(start, start + criteria.pageSize),
      total,
      page: criteria.page,
      pageSize: criteria.pageSize,
    };
  }

  // Test helper
  clear(): void {
    this.users.clear();
  }
}

// adapters/driven/rabbitmq/rabbitmq-event-publisher.ts
class RabbitMQEventPublisher implements DomainEventPublisher {
  constructor(private readonly channel: Channel) {}

  async publish(event: DomainEvent): Promise<void> {
    const message = Buffer.from(JSON.stringify({
      type: event.type,
      data: event,
      timestamp: new Date().toISOString(),
    }));
    this.channel.publish('domain-events', event.type, message, { persistent: true });
  }

  async publishAll(events: ReadonlyArray<DomainEvent>): Promise<void> {
    for (const event of events) {
      await this.publish(event);
    }
  }
}
```

### Composition Root — Wire everything together

```typescript
// composition-root.ts (hoặc main.ts)
// Nơi DUY NHẤT biết concrete implementations

import { createApp } from './app';
import { PostgresUserRepository } from './adapters/driven/postgres/postgres-user.repository';
import { RabbitMQEventPublisher } from './adapters/driven/rabbitmq/rabbitmq-event-publisher';
import { UuidIdGenerator } from './adapters/driven/uuid/uuid-id-generator';
import { CreateUserService } from './application/create-user.use-case';
import { SuspendUserService } from './application/suspend-user.use-case';
import { createUserRoutes } from './adapters/driving/http/user.routes';

async function bootstrap(): Promise<void> {
  // Infrastructure
  const db = knex({ client: 'pg', connection: config.databaseUrl });
  const rabbitConn = await amqp.connect(config.rabbitUrl);
  const channel = await rabbitConn.createChannel();

  // Driven adapters
  const userRepo = new PostgresUserRepository(db);
  const eventPublisher = new RabbitMQEventPublisher(channel);
  const idGenerator = new UuidIdGenerator();

  // Application services (use cases)
  const createUser = new CreateUserService(userRepo, eventPublisher, idGenerator);
  const suspendUser = new SuspendUserService(userRepo, eventPublisher);
  const getUser = new GetUserService(userRepo);
  const listUsers = new ListUsersService(userRepo);

  // Driving adapters
  const userRoutes = createUserRoutes({ createUser, getUser, listUsers, suspendUser });

  // App
  const app = createApp();
  app.use('/api', userRoutes);
  app.listen(config.port);
}

bootstrap().catch(console.error);
```

## Clean Architecture

Robert C. Martin's Clean Architecture là phiên bản cụ thể hơn của Hexagonal, với **Dependency Rule** rõ ràng: dependencies chỉ point **inward**.

```
┌─────────────────────────────────────────────────┐
│         Frameworks & Drivers (outermost)         │
│  Express, PostgreSQL, Redis, SendGrid, AWS SDK   │
├─────────────────────────────────────────────────┤
│         Interface Adapters                       │
│  Controllers, Presenters, Gateways, Repos        │
├─────────────────────────────────────────────────┤
│         Application Business Rules               │
│  Use Cases, Application Services                 │
├─────────────────────────────────────────────────┤
│         Enterprise Business Rules (innermost)    │
│  Entities, Value Objects, Domain Services        │
└─────────────────────────────────────────────────┘

Dependency Rule: Source code dependencies point INWARD only.
Inner circles NEVER mention outer circles.
```

### Clean Architecture = Hexagonal, nhưng:

| Aspect | Hexagonal | Clean Architecture |
|--------|-----------|-------------------|
| Focus | Ports & Adapters symmetry | Dependency Rule |
| Layers | Application + Domain | 4 concentric circles |
| Use Cases | Implicit trong application | Explicit layer |
| Data flow | Bidirectional through ports | Unidirectional inward |

Trong thực tế TypeScript, sự khác biệt nhỏ. Cả hai đều enforce:
- Domain không depend on infrastructure
- Infrastructure implement domain interfaces
- Composition ở outer layer

```typescript
  constructor(
    private readonly db: Knex,
    private readonly eventBus: EventBus,
  ) {}

  async handle(command: CreateUserCommand): Promise<{ id: string }> {
    // Check duplicate
    const existing = await this.db('users')
      .where('email', command.email.toLowerCase())
      .first();
    if (existing) throw new DuplicateEmailError(command.email);

    // Create
    const id = crypto.randomUUID();
    await this.db('users').insert({
      id,
      name: command.name,
      email: command.email.toLowerCase(),
      role: command.role,
      status: 'active',
      created_at: new Date(),
    });

    await this.eventBus.publish({ type: 'UserCreated', userId: id });

    return { id };
  }
}

// features/create-user/create-user.route.ts
export function createUserRoute(handler: CreateUserHandler): Router {
  const router = Router();

  router.post('/users', async (req, res, next) => {
    try {
      const command = new CreateUserCommand(req.body.name, req.body.email, req.body.role);
      const result = await handler.handle(command);
      res.status(201).json(result);
    } catch (error) {
      next(error);
    }
  });

  return router;
}
```

### Vertical Slice: Khi nào?

| Ưu điểm | Nhược điểm |
|---------|-----------|
| Thêm/xoá feature = thêm/xoá folder | Code duplication giữa features nếu không cẩn thận |
| Low coupling giữa features | Shared logic cần convention rõ (`shared/`) |
| Dễ assign feature cho team member | Team cần discipline để maintain shared code |
| Test dễ — test 1 folder | Harder to enforce consistency across features |

## So sánh và chọn Architecture

| Tiêu chí | Layered | Hexagonal/Clean | Vertical Slice |
|----------|---------|-----------------|----------------|
| **Complexity** | Low | Medium-High | Low-Medium |
| **Team size** | 1-5 | 5+ | 3+ |
| **Domain complexity** | Simple CRUD | Complex business rules | Mixed |
| **Testability** | Medium (mock DB) | High (in-memory adapters) | High (isolated features) |
| **Flexibility** | Low (DB-driven) | High (swap anything) | High (per feature) |
| **Learning curve** | Low | High | Medium |
| **Best for** | MVPs, CRUD apps, admin panels | Core business services, payment, billing | Feature-rich apps, rapid iteration |

### Decision Framework

```
Bắt đầu project mới?
├── CRUD app / Admin panel / MVP
│   → Layered (simple, fast to build)
│
├── Complex domain (billing, healthcare, logistics)
│   → Hexagonal / Clean Architecture
│
├── Feature-heavy app, multiple teams
│   → Vertical Slice hoặc Modular Monolith
│
└── Không chắc?
    → Modular Layered (tách module, giữ layers đơn giản)
    → Refactor sang Hexagonal khi domain phức tạp dần
```

### Nguyên tắc

> **Architecture tốt nhất là architecture đơn giản nhất giải quyết được vấn đề của bạn HÔM NAY, và đủ linh hoạt để evolve cho NGÀY MAI.**
>
> Đừng dùng Clean Architecture cho TODO app.
> Đừng dùng Layered Architecture cho payment processing system.
