## CAP Theorem trong thực tế

```
CAP Theorem: Trong hệ thống phân tán, khi có NETWORK PARTITION (P),
bạn chỉ có thể chọn MỘT trong hai: Consistency (C) hoặc Availability (A).

Thực tế: P luôn xảy ra → bạn chọn giữa CP hoặc AP.

CP (Consistency + Partition tolerance):
  Khi partition xảy ra → system từ chối requests thay vì trả stale data
  Ví dụ: Banking (chấp nhận downtime hơn sai balance)
  Tools: PostgreSQL (single primary), ZooKeeper, etcd

AP (Availability + Partition tolerance):
  Khi partition xảy ra → system vẫn respond, có thể stale
  Ví dụ: Social feed (OK nếu miss 1 post, đừng down cả app)
  Tools: Cassandra, DynamoDB, DNS

THỰC TẾ: Không phải binary choice.
  Mỗi FEATURE trong hệ thống có thể chọn khác nhau:
  - Payment processing: CP (consistency bắt buộc)
  - Product catalog: AP (stale data OK)
  - Inventory count: CP cho writes, AP cho reads (hiển thị "~50 left")
  - User sessions: AP (lose session = minor inconvenience)
```

## Consistency Models

### Strong Consistency

```typescript
// Read luôn thấy write gần nhất. Đắt nhưng simple mental model.

// PostgreSQL with serializable isolation
async function transferMoney(fromId: string, toId: string, amount: Money): Promise<void> {
  await db.transaction(async (trx) => {
    // SELECT FOR UPDATE: lock rows, prevent concurrent modification
    const from = await trx('accounts').where('id', fromId).forUpdate().first();
    const to = await trx('accounts').where('id', toId).forUpdate().first();

    if (!from || !to) throw new AccountNotFoundError();
    if (from.balance < amount.cents) throw new InsufficientFundsError();

    await trx('accounts').where('id', fromId).update({
      balance: from.balance - amount.cents,
    });
    await trx('accounts').where('id', toId).update({
      balance: to.balance + amount.cents,
    });
  });
  // Sau transaction: mọi reader thấy balances mới
}
```

### Eventual Consistency

```typescript
// Write propagates eventually. Readers MAY see stale data temporarily.

// Ví dụ: User profile update → cache propagation

class UserProfileService {
  async updateProfile(userId: string, data: ProfileUpdate): Promise<void> {
    // 1. Write to primary DB (source of truth)
    await this.db('users').where('id', userId).update(data);

    // 2. Invalidate cache (but other caches may still be stale)
    await this.cache.del(`user:${userId}`);

    // 3. Publish event (other services update eventually)
    await this.events.publish(new UserProfileUpdatedEvent(userId, data));

    // 4. Reindex search (happens async, may take seconds)
    await this.searchQueue.add('reindex-user', { userId });

    // Window of inconsistency:
    // - Cache on other servers: stale until TTL expires or event arrives
    // - Search index: stale until reindex completes
    // - Read replicas: stale until replication lag catches up (~ms to seconds)
  }
}

// Consumer phải handle stale reads gracefully:
// - Show "last updated: 2 seconds ago" instead of pretending data is fresh
// - Use optimistic UI: show change immediately, reconcile later
```

### Read-Your-Writes Consistency

```typescript
// Guarantee: after writing, YOU see your own write. Others may still see old data.
// Good balance between strong and eventual consistency.

class UserService {
  constructor(
    private readonly primaryDb: Pool,     // Writes + read-after-write
    private readonly replicaDb: Pool,     // General reads
    private readonly cache: Redis,
  ) {}

  async updateUser(userId: string, data: UpdateInput): Promise<User> {
    // Write to primary
    const updated = await this.primaryDb.query(
      'UPDATE users SET name=$1, email=$2 WHERE id=$3 RETURNING *',
      [data.name, data.email, userId],
    );

    // Cache updated version with short TTL
    await this.cache.set(`user:${userId}`, JSON.stringify(updated.rows[0]), 'EX', 30);

    // Mark that this user has recent writes (for read routing)
    await this.cache.set(`user:recent-write:${userId}`, '1', 'EX', 5);

    return updated.rows[0];
  }

  async getUser(userId: string, requestingUserId?: string): Promise<User | null> {
    // If requesting user just wrote → read from primary (read-your-writes)
    if (requestingUserId) {
      const recentWrite = await this.cache.get(`user:recent-write:${userId}`);
      if (recentWrite) {
        const result = await this.primaryDb.query('SELECT * FROM users WHERE id=$1', [userId]);
        return result.rows[0] ?? null;
      }
    }

    // Otherwise → read from replica (faster, may be slightly stale)
    const cached = await this.cache.get(`user:${userId}`);
    if (cached) return JSON.parse(cached);

    const result = await this.replicaDb.query('SELECT * FROM users WHERE id=$1', [userId]);
    return result.rows[0] ?? null;
  }
}
```

## Distributed Transactions

### Two-Phase Commit (2PC)

```
Coordinator → Participant A: "Prepare to commit"
Coordinator → Participant B: "Prepare to commit"
Participant A → Coordinator: "Ready"
Participant B → Coordinator: "Ready"

If ALL ready:
  Coordinator → All: "Commit"
Else:
  Coordinator → All: "Rollback"

Vấn đề:
- Coordinator down = participants stuck in "prepared" state
- Blocking: all participants lock resources during prepare
- Slow: requires coordination across network
→ AVOID in microservices. Dùng Saga thay thế.
```

### Saga Pattern Implementation

```typescript
// Orchestration Saga — step-by-step with compensation

interface SagaStep<TContext> {
  name: string;
  execute(context: TContext): Promise<TContext>;
  compensate(context: TContext): Promise<TContext>;
}

class SagaOrchestrator<TContext> {
  private steps: SagaStep<TContext>[] = [];

  addStep(step: SagaStep<TContext>): this {
    this.steps.push(step);
    return this;
  }

  async execute(initialContext: TContext): Promise<SagaResult<TContext>> {
    let context = initialContext;
    const completedSteps: SagaStep<TContext>[] = [];

    for (const step of this.steps) {
      try {
        context = await step.execute(context);
        completedSteps.push(step);
      } catch (error) {
        // Compensation: undo completed steps in reverse order
        console.error(`Saga step "${step.name}" failed:`, error);

        for (const completed of completedSteps.reverse()) {
          try {
            context = await completed.compensate(context);
          } catch (compError) {
            // Compensation failure — needs manual intervention
            console.error(`CRITICAL: Compensation for "${completed.name}" failed:`, compError);
            return SagaResult.compensationFailed(context, error as Error, compError as Error);
          }
        }

        return SagaResult.rolledBack(context, error as Error);
      }
    }

    return SagaResult.completed(context);
  }
}

// Define saga steps
interface OrderSagaContext {
  orderId: string;
  customerId: string;
  items: OrderItem[];
  totalCents: number;
  paymentId?: string;
  reservationId?: string;
  shipmentId?: string;
}

const placeOrderSaga = new SagaOrchestrator<OrderSagaContext>()
  .addStep({
    name: 'charge-payment',
    async execute(ctx) {
      const result = await paymentService.charge(ctx.totalCents, ctx.customerId);
      return { ...ctx, paymentId: result.id };
    },
    async compensate(ctx) {
      if (ctx.paymentId) await paymentService.refund(ctx.paymentId);
      return { ...ctx, paymentId: undefined };
    },
  })
  .addStep({
    name: 'reserve-inventory',
    async execute(ctx) {
      const result = await inventoryService.reserve(ctx.items, ctx.orderId);
      return { ...ctx, reservationId: result.id };
    },
    async compensate(ctx) {
      if (ctx.reservationId) await inventoryService.cancelReservation(ctx.reservationId);
      return { ...ctx, reservationId: undefined };
    },
  })
  .addStep({
    name: 'create-shipment',
    async execute(ctx) {
      const result = await shippingService.createShipment(ctx.orderId, ctx.items);
      return { ...ctx, shipmentId: result.id };
    },
    async compensate(ctx) {
      if (ctx.shipmentId) await shippingService.cancelShipment(ctx.shipmentId);
      return { ...ctx, shipmentId: undefined };
    },
  });

// Execute
const result = await placeOrderSaga.execute({
  orderId: 'ord_123',
  customerId: 'cust_456',
  items: orderItems,
  totalCents: 9999,
});

if (result.status === 'completed') {
  console.log('Order placed successfully');
} else if (result.status === 'rolled_back') {
  console.log('Order failed, all changes rolled back');
} else {
  // CRITICAL: manual intervention needed
  alertOpsTeam('Saga compensation failed', result);
}
```

## Data Partitioning Strategies

### Partitioning by Key (Hash)

```typescript
// Distribute data evenly across partitions

function getPartition(key: string, numPartitions: number): number {
  // Consistent hashing: same key always maps to same partition
  const hash = crypto.createHash('md5').update(key).digest();
  return hash.readUInt32BE(0) % numPartitions;
}

// User data partitioned by user ID
// Partition 0: users whose ID hashes to 0
// Partition 1: users whose ID hashes to 1
// ...

// Pro: even distribution
// Con: cross-partition queries expensive
```

### Partitioning by Range (Time-based)

```typescript
// Common for time-series data: partition by time period

// PostgreSQL native partitioning
/*
CREATE TABLE events (
  id UUID,
  type VARCHAR(100),
  data JSONB,
  created_at TIMESTAMPTZ
) PARTITION BY RANGE (created_at);

CREATE TABLE events_2024_q1 PARTITION OF events
  FOR VALUES FROM ('2024-01-01') TO ('2024-04-01');
CREATE TABLE events_2024_q2 PARTITION OF events
  FOR VALUES FROM ('2024-04-01') TO ('2024-07-01');

-- Queries with WHERE created_at between X and Y → only scan relevant partition
-- Old partitions: detach and archive to cold storage
*/

// Application-level routing
class TimePartitionedRepository {
  private getTableName(date: Date): string {
    const year = date.getFullYear();
    const quarter = Math.ceil((date.getMonth() + 1) / 3);
    return `events_${year}_q${quarter}`;
  }

  async insert(event: Event): Promise<void> {
    const table = this.getTableName(event.createdAt);
    await this.db(table).insert(event);
  }

  async query(from: Date, to: Date): Promise<Event[]> {
    // Determine which partitions to query
    const tables = this.getTablesInRange(from, to);
    const results = await Promise.all(
      tables.map(table =>
        this.db(table).where('created_at', '>=', from).where('created_at', '<', to)
      ),
    );
    return results.flat().sort((a, b) => a.createdAt.getTime() - b.createdAt.getTime());
  }
}
```

## Conflict Resolution

### Last-Write-Wins (LWW)

```typescript
// Simple nhưng có thể lost data

// Update with timestamp comparison
await db.query(`
  UPDATE user_profiles
  SET bio = $1, updated_at = $2
  WHERE id = $3 AND updated_at < $2
`, [newBio, timestamp, userId]);
// Nếu updated_at >= timestamp → write rejected (older write)
```

### Merge / CRDT-inspired

```typescript
// Conflict-free merge: cho phép concurrent writes mà không mất data

// Shopping cart: merge = union of items, max quantities
function mergeShoppingCarts(
  cartA: CartItem[],
  cartB: CartItem[],
): CartItem[] {
  const merged = new Map<string, CartItem>();

  for (const item of [...cartA, ...cartB]) {
    const existing = merged.get(item.productId);
    if (!existing || item.quantity > existing.quantity) {
      merged.set(item.productId, item);
    }
  }

  return Array.from(merged.values());
}

// Tags/labels: merge = union
function mergeTags(tagsA: string[], tagsB: string[]): string[] {
  return [...new Set([...tagsA, ...tagsB])];
}
```

// Problem: Dashboard cần data từ 5 services
// Solution: BFF/Gateway composes responses

class DashboardComposer {
  async getAdminDashboard(): Promise<AdminDashboard> {
    // Parallel calls to multiple services
    const [users, orders, revenue, tickets, systemHealth] = await Promise.allSettled([

  }
}

### Materialized Views Across Services

```typescript
// Service A publishes events → Service B maintains its own view

// Order Service publishes OrderPlaced events
// Analytics Service maintains denormalized view:
//   customer_orders_summary(customer_id, total_orders, total_spent, last_order_date)

class AnalyticsProjection {
  async handleOrderPlaced(event: OrderPlacedEvent): Promise<void> {
    await this.db.raw(`
      INSERT INTO customer_orders_summary (customer_id, total_orders, total_spent, last_order_date)
      VALUES (?, 1, ?, ?)
      ON CONFLICT (customer_id) DO UPDATE SET
        total_orders = customer_orders_summary.total_orders + 1,
        total_spent = customer_orders_summary.total_spent + EXCLUDED.total_spent,
        last_order_date = GREATEST(customer_orders_summary.last_order_date, EXCLUDED.last_order_date)
    `, [event.customerId, event.totalCents, event.occurredAt]);
  }
}

// Analytics queries are fast: query own local materialized view
// No cross-service calls needed for dashboards
```
