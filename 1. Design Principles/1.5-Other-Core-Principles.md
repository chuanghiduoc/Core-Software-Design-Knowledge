## Law of Demeter (LoD)

> "Only talk to your immediate friends. Don't talk to strangers."
> — Karl Lieberherr (1987)

### Bản chất

Một method M của object O chỉ nên gọi methods của:
1. O chính nó
2. Parameters của M
3. Objects được tạo trong M
4. Direct components (fields) của O

**KHÔNG** gọi methods trên objects được trả về từ methods khác → `a.b().c().d()` là vi phạm.

### ❌ Vi phạm LoD — Train Wreck

```typescript
// "Train wreck" — chain of method calls trên objects không phải "bạn"

class InvoiceService {
  calculateShipping(order: Order): Money {
    // Vi phạm: navigate qua 3 objects
    const city = order.getCustomer().getAddress().getCity();
    const zip = order.getCustomer().getAddress().getZipCode();
    const weight = order.getItems().reduce((sum, item) =>
      sum + item.getProduct().getWeight() * item.getQuantity(), 0);

    // InvoiceService biết internal structure của:
    // Order → Customer → Address → City/ZipCode
    // Order → Items → Product → Weight
    // Nếu Address thay đổi structure → phá InvoiceService!
  }
}

// Frontend version
function getUserDisplayName(order: Order): string {
  // Navigate deep: order → user → profile → displayName
  return order.user?.profile?.settings?.displayName
    ?? order.user?.profile?.firstName
    ?? order.user?.email
    ?? 'Unknown';
}
```

### ✅ Áp dụng LoD — Tell, don't navigate

```typescript
// Order expose thông tin cần thiết, KHÔNG expose internal structure

class Order {
  constructor(
    private readonly customer: Customer,
    private readonly items: ReadonlyArray<OrderItem>,
  ) {}

  // Delegate: Order "biết" cách lấy shipping info
  get shippingAddress(): ShippingAddress {
    return this.customer.shippingAddress;
  }

  get totalWeight(): number {
    return this.items.reduce((sum, item) => sum + item.totalWeight, 0);
  }

  get displayName(): string {
    return this.customer.displayName;
  }
}

class Customer {
  get shippingAddress(): ShippingAddress {
    return this.address.toShipping();
  }

  get displayName(): string {
    return this.profile?.displayName ?? this.email;
  }
}

class InvoiceService {
  calculateShipping(order: Order): Money {
    // ✅ Chỉ talk to immediate friend (order parameter)
    const address = order.shippingAddress;
    const weight = order.totalWeight;
    return this.shippingCalculator.calculate(address, weight);
  }
}
```

### LoD + TypeScript: Khi nào chấp nhận "chain"?

```typescript
// ✅ OK: Fluent API / Builder pattern — designed to chain
const query = db.select('*').from('users').where('active', true).orderBy('name').limit(10);

// ✅ OK: Data transformation pipeline — working with data, not navigating objects
const result = users
  .filter(u => u.active)
  .map(u => u.name)
  .sort();

// ✅ OK: Optional chaining trên plain data (DTO, API response)
const city = apiResponse?.data?.address?.city ?? 'Unknown';

// ❌ NOT OK: Navigating live objects with behavior
const fee = order.getCustomer().getSubscription().getPlan().getDiscountPolicy().apply(basePrice);
```

## Tell, Don't Ask

> "Tell objects what to do, don't ask them for data and do the work yourself."
> — Pragmatic Programmers

### Bản chất

Thay vì **hỏi** object về state rồi **tự quyết định**, hãy **bảo** object làm việc. Object có data → object nên có behavior.

### ❌ Ask then decide

```typescript
// Procedural style: lấy data rồi tự xử lý

class PaymentProcessor {
  processRefund(order: Order): void {
    // ASK: lấy data từ order
    if (order.status === 'shipped') {
      if (order.daysSinceShipping > 30) {
        // Quá 30 ngày → từ chối
        throw new RefundDeniedError('Past return window');
      }
      // Trả partial (trừ shipping fee)
      const refundAmount = order.total - order.shippingFee;
      this.gateway.refund(order.paymentId, refundAmount);
      order.status = 'refunded'; // Directly mutating → encapsulation broken
    } else if (order.status === 'pending') {
      // Cancel + full refund
      this.gateway.refund(order.paymentId, order.total);
      order.status = 'cancelled';
    } else {
      throw new RefundDeniedError(`Cannot refund order with status: ${order.status}`);
    }
  }
}

// Vấn đề:
// 1. Business rules (30-day window, partial refund) nằm NGOÀI Order
// 2. Nếu thêm trạng thái mới → phải sửa PaymentProcessor
// 3. Order.status bị mutate từ bên ngoài → encapsulation broken
// 4. Logic này có thể bị duplicate ở controller, API, batch job...
```

### ✅ Tell — Let the object decide

```typescript
// Order biết rules của chính nó

class Order {
  requestRefund(): RefundRequest {
    // TELL: Order tự quyết định refund type
    switch (this.status) {
      case 'pending':
        this.cancel();
        return RefundRequest.full(this.paymentId, this.total);

      case 'shipped':
        this.assertWithinReturnWindow();
        this.markRefundRequested();
        return RefundRequest.partial(
          this.paymentId,
          this.total.subtract(this.shippingFee),
        );

      case 'delivered':
        this.assertWithinReturnWindow();
        this.markRefundRequested();
        return RefundRequest.partial(
          this.paymentId,
          this.total.subtract(this.shippingFee),
        );

      default:
        throw new RefundDeniedError(`Cannot refund order with status: ${this.status}`);
    }
  }

  private assertWithinReturnWindow(): void {
    const daysSinceShipped = differenceInDays(new Date(), this.shippedAt!);
    if (daysSinceShipped > 30) {
      throw new RefundDeniedError('Past 30-day return window');
    }
  }

  private cancel(): void {
    this._status = 'cancelled';
  }

  private markRefundRequested(): void {
    this._status = 'refund_requested';
  }
}

class PaymentProcessor {
  async processRefund(order: Order): Promise<void> {
    // TELL order to create refund request — it handles its own rules
    const request = order.requestRefund();

    // PaymentProcessor chỉ xử lý payment concern
    await this.gateway.refund(request.paymentId, request.amount);
  }
}
```

## Fail Fast

> "If something is going to fail, fail as early and loudly as possible."

### Bản chất

Detect lỗi SỚM NHẤT có thể và báo lỗi RÕ RÀNG. Đừng để invalid state lan truyền sâu vào hệ thống rồi mới crash với error message khó hiểu.

### ❌ Fail Slow — Silent corruption

```typescript
function processPayment(data: any): any {
  // Không validate → invalid data lan truyền
  const amount = data.amount; // could be string, null, NaN, negative...

  // 20 dòng code sau...
  const fee = amount * 0.029; // NaN * 0.029 = NaN, string "100" * 0.029 = 2.9 (JS coercion!)

  // 50 dòng code sau, somewhere in DB layer...
  // INSERT INTO transactions (amount, fee) VALUES (NaN, NaN)
  // → Silent data corruption. Discovered weeks later in financial report.
}
```

### ✅ Fail Fast — Validate at boundaries

```typescript
// Value Object: validates at construction, ALWAYS valid afterward

class Money {
  private constructor(
    readonly cents: number,
    readonly currency: Currency,
  ) {}

  static fromCents(cents: number, currency: Currency = 'USD'): Money {
    // Fail fast: validate IMMEDIATELY
    if (!Number.isInteger(cents)) {
      throw new InvalidMoneyError(`Cents must be integer, got: ${cents}`);
    }
    if (cents < 0) {
      throw new InvalidMoneyError(`Money cannot be negative: ${cents}`);
    }
    return new Money(cents, currency);
  }

  static fromDollars(dollars: number, currency: Currency = 'USD'): Money {
    if (!Number.isFinite(dollars)) {
      throw new InvalidMoneyError(`Invalid dollar amount: ${dollars}`);
    }
    return Money.fromCents(Math.round(dollars * 100), currency);
  }

  add(other: Money): Money {
    this.assertSameCurrency(other);
    return new Money(this.cents + other.cents, this.currency);
  }

  subtract(other: Money): Money {
    this.assertSameCurrency(other);
    const result = this.cents - other.cents;
    if (result < 0) {
      throw new InsufficientFundsError(this, other);
    }
    return new Money(result, this.currency);
  }

  multiply(factor: number): Money {
    if (!Number.isFinite(factor) || factor < 0) {
      throw new InvalidMoneyError(`Invalid multiplication factor: ${factor}`);
    }
    return new Money(Math.round(this.cents * factor), this.currency);
  }

  private assertSameCurrency(other: Money): void {
    if (this.currency !== other.currency) {
      throw new CurrencyMismatchError(this.currency, other.currency);
    }
  }
}

// Usage: once constructed, Money is ALWAYS valid
const price = Money.fromDollars(19.99);  // ✅ Valid
const tax = price.multiply(0.08);        // ✅ Valid
const total = price.add(tax);            // ✅ Valid

Money.fromDollars(NaN);     // 💥 Throws immediately — easy to debug
Money.fromDollars(-5);      // 💥 Throws immediately
price.add(Money.fromDollars(10, 'EUR')); // 💥 Currency mismatch — caught early
```

```typescript
// Boundary 1: HTTP Input → Validate ngay
const CreateOrderSchema = z.object({

  const input = CreateOrderSchema.parse(req.body); // 💥 Fail fast nếu invalid

class OrderItem {
  constructor(
    readonly productId: ProductId,
    readonly quantity: number,

    if (quantity <= 0 || quantity > 100) {

    }
  }
}

function loadConfig(): AppConfig {
```

## Principle of Least Astonishment (POLA)

> "If a necessary feature has a high astonishment factor, it may be necessary to redesign the feature."

### Bản chất

Code nên behave **đúng như người đọc expect**. Tên function nên mô tả chính xác. Side effects phải transparent.

### ❌ Astonishing behavior

```typescript
// Tên nói "get" nhưng thực tế modify
function getUser(id: string): User {
  const user = db.findUser(id);
  user.lastAccessedAt = new Date(); // Side effect! "get" implies read-only
  db.save(user);                     // Writing to DB! Caller doesn't expect this
  analytics.track('user_accessed');   // External side effect!
  return user;
}

// Tên nói "validate" nhưng thực tế transform
function validateEmail(email: string): string {
  if (!email.includes('@')) throw new Error('Invalid');
  return email.toLowerCase().trim(); // Returns modified value! "validate" implies boolean
}

// Array method trả về unexpected type
class UserList {
  private users: User[] = [];

  add(user: User): number {
    this.users.push(user);
    return this.users.length; // add() trả về length? Expect void hoặc User
  }
}
```

### ✅ No surprises

```typescript
// Tên chính xác mô tả behavior

// "get" = read-only, no side effects
function getUser(id: string): User {
  return db.findUser(id);
}

// "record" = clearly implies a write/side effect
function recordUserAccess(userId: string): void {
  db.updateLastAccess(userId, new Date());
  analytics.track('user_accessed', { userId });
}

// "validate" = returns boolean or throws, NO transformation
function isValidEmail(email: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
}

// "normalize" = clearly implies transformation
function normalizeEmail(email: string): string {
  return email.toLowerCase().trim();
}

// Methods return what you'd expect
class UserList {
  add(user: User): void {        // void — no surprise
    this.users.push(user);
  }

  count(): number {              // Separate method for count
    return this.users.length;
  }
}
```

### Naming Conventions cho POLA

| Prefix | Expectation |
|--------|-------------|
| `get`, `find`, `fetch` | Read-only, returns data, no mutation |
| `create`, `add`, `insert` | Creates something new, may write to DB |
| `update`, `set`, `modify` | Mutates existing state |
| `delete`, `remove`, `destroy` | Removes something |
| `is`, `has`, `can`, `should` | Returns boolean, no side effects |
| `to`, `parse`, `format`, `normalize` | Transforms data, returns new value |
| `validate`, `check`, `assert` | Validates, throws on failure OR returns result |
| `on`, `handle`, `process` | Event handler / callback |
| `ensure`, `require` | Guarantees a condition, throws if not met |

## Hollywood Principle

> "Don't call us, we'll call you."

### Bản chất

High-level modules control flow. Low-level modules cung cấp hooks/callbacks mà high-level sẽ gọi. Đây là foundation của frameworks, event systems, và dependency injection.

### Ví dụ: Plugin System

```typescript
// Framework defines lifecycle — plugins implement hooks

interface Plugin {
  readonly name: string;
  onInit?(app: App): Promise<void>;
  onRequest?(ctx: RequestContext): Promise<void>;
  onError?(error: Error, ctx: RequestContext): Promise<void>;
  onShutdown?(): Promise<void>;
}

class App {
  private plugins: Plugin[] = [];

  use(plugin: Plugin): this {
    this.plugins.push(plugin);
    return this;
  }

  // Framework calls plugins — plugins don't call framework
  async start(): Promise<void> {
    for (const plugin of this.plugins) {
      await plugin.onInit?.(this);
    }
    // Start server...
  }

  private async handleRequest(ctx: RequestContext): Promise<void> {
    for (const plugin of this.plugins) {
      await plugin.onRequest?.(ctx);
    }
  }

  async shutdown(): Promise<void> {
    // Reverse order for graceful shutdown
    for (const plugin of [...this.plugins].reverse()) {
      await plugin.onShutdown?.();
    }
  }
}

// Plugin implementation — only implements hooks, doesn't control flow
const corsPlugin: Plugin = {
  name: 'cors',
  async onRequest(ctx) {
    ctx.setHeader('Access-Control-Allow-Origin', '*');
  },
};

const rateLimitPlugin: Plugin = {
  name: 'rate-limit',
  onInit: async () => { /* setup rate limiter */ },
  onRequest: async (ctx) => { /* check rate limit */ },
};

// Usage
const app = new App()
  .use(corsPlugin)
  .use(rateLimitPlugin)
  .use(authPlugin);
```

## Encapsulation

> "Hide the internal state and require all interaction to be performed through well-defined interfaces."

### Beyond getters/setters

```typescript
// ❌ "Encapsulation" qua getter/setter — vô nghĩa, chỉ là ceremony
class Account {
  private _balance: number;

  getBalance(): number { return this._balance; }
  setBalance(value: number): void { this._balance = value; } // Anyone can set any value!
}

// Client code
account.setBalance(account.getBalance() - 100); // Encapsulation? Không.
account.setBalance(-999999); // Oops.

// ✅ Real encapsulation — expose BEHAVIORS, not STATE
class Account {
  private balance: Money;
  private readonly transactions: Transaction[] = [];

  constructor(
    readonly id: AccountId,
    initialBalance: Money,
  ) {
    this.balance = initialBalance;
  }

  // Expose behavior, not raw state
  deposit(amount: Money): void {
    if (amount.isNegativeOrZero()) {
      throw new InvalidAmountError('Deposit amount must be positive');
    }
    this.balance = this.balance.add(amount);
    this.transactions.push(Transaction.deposit(amount, new Date()));
  }

  withdraw(amount: Money): void {
    if (amount.isNegativeOrZero()) {
      throw new InvalidAmountError('Withdrawal amount must be positive');
    }
    if (this.balance.lessThan(amount)) {
      throw new InsufficientFundsError(this.balance, amount);
    }
    this.balance = this.balance.subtract(amount);
    this.transactions.push(Transaction.withdrawal(amount, new Date()));
  }

  transfer(amount: Money, to: Account): void {
    this.withdraw(amount);  // Reuses withdrawal rules
    to.deposit(amount);     // Reuses deposit rules
    // Invariant: total money in system unchanged
  }

  // Read-only access to state
  get currentBalance(): Money {
    return this.balance; // Money is immutable → safe to expose
  }

  get recentTransactions(): ReadonlyArray<Transaction> {
    return this.transactions.slice(-10); // Return copy, not internal array
  }
}
```

## Command-Query Separation (CQS)

> "A method should either be a command that performs an action, or a query that returns data, but not both."
> — Bertrand Meyer

### Bản chất

- **Command**: thay đổi state, return void (hoặc status/id)
- **Query**: trả về data, KHÔNG thay đổi state

### ❌ Mixed command + query

```typescript
class ShoppingCart {
  // Vi phạm CQS: removes item AND returns remaining count
  removeItem(productId: string): number {
    this.items = this.items.filter(i => i.productId !== productId);
    return this.items.length; // Mutation + Query mixed
  }

  // Vi phạm CQS: stack.pop() returns AND modifies
  checkout(): Order {
    const order = Order.from(this.items);
    this.items = []; // Side effect!
    return order;    // Returns data!
  }
}
```

### ✅ Separated commands and queries

```typescript
class ShoppingCart {
  // Command: only mutates, returns void
  removeItem(productId: string): void {
    this.items = this.items.filter(i => i.productId !== productId);
  }

  // Query: only reads, no mutation
  get itemCount(): number {
    return this.items.length;
  }

  // Command: create order from cart
  checkout(): Order {
    const order = Order.from(this.items);
    this.items = [];
    return order; // Exception: returning the created entity ID/reference is acceptable
  }
}

// CQS at API level
class UserController {
  // Command endpoint: POST → creates, returns created ID
  @Post('/users')
  async createUser(@Body() input: CreateUserInput): Promise<{ id: string }> {
    const id = await this.userService.create(input);
    return { id }; // Only returns identifier, not full entity
  }

  // Query endpoint: GET → reads, no side effects
  @Get('/users/:id')
  async getUser(@Param('id') id: string): Promise<UserDto> {
    return this.userService.findById(id);
  }
}
```

## Immutability First

> "Shared mutable state is the root of all evil." — Many engineers, many times

### Tại sao Immutability?

```typescript
// ❌ Mutable state → surprising behavior
const config = { timeout: 5000, retries: 3 };
setupClient(config);
config.timeout = 100; // Caller modifies → client behavior changes silently!

const users = getActiveUsers();
users.push(adminUser); // Mutating the returned array → side effects on source
```

### ✅ Immutable by default trong TypeScript

```typescript
// 1. Use readonly everywhere
interface AppConfig {
  readonly port: number;
  readonly database: {
    readonly host: string;
    readonly port: number;
    readonly name: string;
  };
  readonly features: ReadonlyArray<string>;
}

// 2. as const for literal types
const HTTP_STATUS = {
  OK: 200,
  CREATED: 201,
  BAD_REQUEST: 400,
  NOT_FOUND: 404,
  INTERNAL_ERROR: 500,
} as const;

// 3. Readonly utility types
function processItems(items: ReadonlyArray<Item>): ReadonlyArray<Result> {
  // Cannot push/pop/splice items
  return items.map(item => transform(item)); // Returns new array
}

// 4. Immutable updates with spread
function updateUser(user: User, changes: Partial<Pick<User, 'name' | 'email'>>): User {
  return { ...user, ...changes, updatedAt: new Date() };
}

// 5. ReadonlyMap and ReadonlySet
function getPermissions(): ReadonlyMap<Role, ReadonlySet<Permission>> {
  return new Map([
    ['admin', new Set(['read', 'write', 'delete'])],
    ['viewer', new Set(['read'])],
  ]);
}

// 6. Immutable domain objects
class Temperature {
  private constructor(
    readonly celsius: number,
  ) {
    Object.freeze(this); // Runtime immutability
  }

  static fromCelsius(c: number): Temperature {
    return new Temperature(c);
  }

  static fromFahrenheit(f: number): Temperature {
    return new Temperature((f - 32) * 5 / 9);
  }

  toFahrenheit(): number {
    return this.celsius * 9 / 5 + 32;
  }

  // Returns NEW instance, doesn't mutate
  add(other: Temperature): Temperature {
    return new Temperature(this.celsius + other.celsius);
  }

  isAbove(other: Temperature): boolean {
    return this.celsius > other.celsius;
  }
}
```

### Khi nào mutable OK?

```typescript
// 1. Performance-critical hot paths (measure first!)
// Building large arrays: push is faster than spread
function buildLargeArray(n: number): number[] {
  const result: number[] = []; // Mutable internally
  for (let i = 0; i < n; i++) {
    result.push(i * 2);
  }
  return result; // Return as immutable to outside world
}

// 2. Builder pattern (mutable internally, immutable result)
class QueryBuilder {
  private conditions: string[] = [];
  private params: unknown[] = [];

  where(condition: string, ...params: unknown[]): this {
    this.conditions.push(condition);
    this.params.push(...params);
    return this;
  }

  build(): Readonly<{ sql: string; params: ReadonlyArray<unknown> }> {
    return {
      sql: `SELECT * FROM users WHERE ${this.conditions.join(' AND ')}`,
      params: [...this.params],
    };
  }
}

// 3. Local mutation within a function (functional core, imperative shell)
function sortAndDeduplicate(items: ReadonlyArray<string>): ReadonlyArray<string> {
  const sorted = [...items].sort(); // Copy then mutate locally
  return sorted.filter((item, i) => i === 0 || item !== sorted[i - 1]);
}
```

### Nguyên tắc

> **Default to immutable. Opt-in to mutable khi có lý do cụ thể (performance, ergonomics).**
> Mutable state bên trong function/class OK, miễn là không leak ra ngoài.
