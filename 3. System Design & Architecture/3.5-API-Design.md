## REST API Design

### Resource-Oriented Design

```typescript
// URLs = resources (nouns), HTTP methods = actions (verbs)

// ✅ RESTful
// GET    /api/users              → List users
// POST   /api/users              → Create user
// GET    /api/users/:id          → Get user by ID
// PATCH  /api/users/:id          → Partial update user
// PUT    /api/users/:id          → Full replace user
// DELETE /api/users/:id          → Delete user

// Nested resources
// GET    /api/users/:id/orders   → User's orders
// POST   /api/users/:id/orders   → Create order for user
// GET    /api/orders/:id/items   → Order's items

// ❌ RPC-style URLs (NOT RESTful)
// POST   /api/getUser
// POST   /api/createUser
// POST   /api/deleteUser
// POST   /api/getUserOrders

// Actions that don't map to CRUD → sub-resource or custom verb
// POST   /api/users/:id/suspend       → Suspend user (state change)
// POST   /api/orders/:id/cancel       → Cancel order
// POST   /api/reports/:id/generate    → Trigger report generation
```

### Response Structure

```typescript
// Consistent response envelope

// Success response
interface ApiSuccess<T> {
  data: T;
  meta?: {
    requestId: string;
    timestamp: string;
    pagination?: PaginationMeta;
  };
}

// Error response
interface ApiError {
  error: {
    code: string;           // Machine-readable: "VALIDATION_ERROR"
    message: string;        // Human-readable: "Invalid input data"
    details?: unknown;      // Additional context
    requestId: string;      // For debugging
  };
}

// Implementation
class ApiResponseBuilder {
  static success<T>(data: T, req: Request): ApiSuccess<T> {
    return {
      data,
      meta: {
        requestId: req.id,
        timestamp: new Date().toISOString(),
      },
    };
  }

  static paginated<T>(
    data: ReadonlyArray<T>,
    pagination: PaginationMeta,
    req: Request,
  ): ApiSuccess<ReadonlyArray<T>> {
    return {
      data: [...data],
      meta: {
        requestId: req.id,
        timestamp: new Date().toISOString(),
        pagination,
      },
    };
  }

  static error(code: string, message: string, req: Request, details?: unknown): ApiError {
    return {
      error: {
        code,
        message,
        details,
        requestId: req.id,
      },
    };
  }
}

// Controller
app.get('/api/users/:id', async (req, res) => {
  const user = await userService.findById(req.params.id);
  if (!user) {
    return res.status(404).json(
      ApiResponseBuilder.error('USER_NOT_FOUND', `User ${req.params.id} not found`, req)
    );
  }
  res.json(ApiResponseBuilder.success(UserDto.from(user), req));
});
```

### HTTP Status Codes — Dùng đúng

```typescript
// Success
// 200 OK             → GET, PATCH, PUT thành công
// 201 Created        → POST tạo resource mới (+ Location header)
// 204 No Content     → DELETE thành công, không trả body

// Client errors
// 400 Bad Request    → Input validation failed
// 401 Unauthorized   → Chưa authenticate (missing/invalid token)
// 403 Forbidden      → Đã authenticate nhưng không đủ quyền
// 404 Not Found      → Resource không tồn tại
// 409 Conflict       → Conflict (duplicate email, version mismatch)
// 422 Unprocessable  → Valid JSON nhưng business rule violation
// 429 Too Many Req   → Rate limited

// Server errors
// 500 Internal       → Unexpected server error
// 502 Bad Gateway    → Upstream service failed
// 503 Unavailable    → Service temporarily down (maintenance)
// 504 Gateway Timeout → Upstream timed out

// Implementation
const errorMiddleware: ErrorRequestHandler = (err, req, res, _next) => {
  if (err instanceof ValidationError) {
    return res.status(400).json(
      ApiResponseBuilder.error('VALIDATION_ERROR', err.message, req, err.fields)
    );
  }
  if (err instanceof NotFoundError) {
    return res.status(404).json(
      ApiResponseBuilder.error('NOT_FOUND', err.message, req)
    );
  }
  if (err instanceof DuplicateError) {
    return res.status(409).json(
      ApiResponseBuilder.error('CONFLICT', err.message, req)
    );
  }
  if (err instanceof ForbiddenError) {
    return res.status(403).json(
      ApiResponseBuilder.error('FORBIDDEN', err.message, req)
    );
  }

  // Unexpected errors — don't leak internals
  console.error('Unhandled error:', err);
  res.status(500).json(
    ApiResponseBuilder.error('INTERNAL_ERROR', 'An unexpected error occurred', req)
  );
};
```

## GraphQL

### Khi nào GraphQL thắng REST

- Client cần **flexible data fetching** (mobile vs web vs admin khác nhau)
- **Nested data** relationships (user → orders → items → product)
- **Over-fetching/under-fetching** là vấn đề với REST
- Multiple client types với requirements khác nhau

```typescript
// Schema-first approach

// schema.graphql
const typeDefs = `
  type User {
    id: ID!
    name: String!
    email: String!
    role: Role!
    orders(first: Int = 10, after: String): OrderConnection!
    stats: UserStats!
  }

  type UserStats {
    totalOrders: Int!
    totalSpent: Float!
    memberSince: String!
  }

  type Order {
    id: ID!
    status: OrderStatus!
    items: [OrderItem!]!
    total: Float!
    createdAt: String!
    shippingAddress: Address!
  }

  type OrderItem {
    product: Product!
    quantity: Int!
    unitPrice: Float!
  }

  type OrderConnection {
    edges: [OrderEdge!]!
    pageInfo: PageInfo!
  }

  type OrderEdge {
    node: Order!
    cursor: String!
  }

  type PageInfo {
    hasNextPage: Boolean!
    endCursor: String
  }

  type Query {
    user(id: ID!): User
    users(first: Int, after: String, filter: UserFilter): UserConnection!
    order(id: ID!): Order
  }

  type Mutation {
    createUser(input: CreateUserInput!): User!
    updateUser(id: ID!, input: UpdateUserInput!): User!
    placeOrder(input: PlaceOrderInput!): Order!
    cancelOrder(id: ID!): Order!
  }

  input UserFilter {
    status: UserStatus
    role: Role
    search: String
  }
`;

// Resolvers
const resolvers = {
  Query: {
    user: async (_: unknown, { id }: { id: string }, ctx: Context) => {
      return ctx.dataSources.users.findById(id);
    },

    users: async (_: unknown, args: ListArgs, ctx: Context) => {
      return ctx.dataSources.users.findAll(args);
    },
  },

  User: {
    // Field resolver — chỉ chạy khi client request field này
    orders: async (user: User, args: PaginationArgs, ctx: Context) => {
      return ctx.dataSources.orders.findByUserId(user.id, args);
    },

    stats: async (user: User, _: unknown, ctx: Context) => {
      return ctx.dataSources.analytics.getUserStats(user.id);
    },
  },

  Mutation: {
    createUser: async (_: unknown, { input }: { input: CreateUserInput }, ctx: Context) => {
      ctx.requireAuth(); // Guard
      return ctx.services.users.create(input);
    },

    placeOrder: async (_: unknown, { input }: { input: PlaceOrderInput }, ctx: Context) => {
      ctx.requireAuth();
      return ctx.services.orders.place(ctx.userId, input);
    },
  },
};
```

### DataLoader — N+1 Problem Solution

```typescript
// Vấn đề: Query users → each user resolve orders → N+1 queries

// ❌ Without DataLoader: 1 + N queries
// Query users (1 query)
// For each user: query orders (N queries)

// ✅ With DataLoader: 2 queries total
import DataLoader from 'dataloader';

function createDataLoaders(db: Knex) {
  return {
    userOrders: new DataLoader<string, Order[]>(async (userIds) => {
      // 1 batch query for ALL user IDs
      const orders = await db('orders')
        .whereIn('user_id', userIds as string[])
        .orderBy('created_at', 'desc');

      // Group by user_id and return in same order as userIds
      const ordersByUser = new Map<string, Order[]>();
      for (const order of orders) {
        const existing = ordersByUser.get(order.user_id) ?? [];
        existing.push(order);
        ordersByUser.set(order.user_id, existing);
      }

      return userIds.map(id => ordersByUser.get(id) ?? []);
    }),

    products: new DataLoader<string, Product>(async (productIds) => {
      const products = await db('products').whereIn('id', productIds as string[]);
      const map = new Map(products.map(p => [p.id, p]));
      return productIds.map(id => map.get(id)!);
    }),
  };
}

// Create per-request (important: DataLoader caches per-request)
app.use((req, _res, next) => {
  req.dataLoaders = createDataLoaders(db);
  next();
});
```

## tRPC

### End-to-end Type Safety — Zero codegen

```typescript
// tRPC: define API on server, get full types on client. No schemas to sync.

// === Server ===
import { initTRPC, TRPCError } from '@trpc/server';
import { z } from 'zod';

const t = initTRPC.context<Context>().create();

const userRouter = t.router({
  // Query: GET equivalent
  getById: t.procedure
    .input(z.object({ id: z.string().uuid() }))
    .query(async ({ input, ctx }) => {
      const user = await ctx.db.users.findById(input.id);
      if (!user) throw new TRPCError({ code: 'NOT_FOUND', message: 'User not found' });
      return user;
    }),

  // Query: List with filters
  list: t.procedure
    .input(z.object({
      page: z.number().int().positive().default(1),
      pageSize: z.number().int().min(1).max(100).default(20),
      status: z.enum(['active', 'suspended']).optional(),
      search: z.string().optional(),
    }))
    .query(async ({ input, ctx }) => {
      return ctx.db.users.findAll(input);
    }),

  // Mutation: POST/PUT/DELETE equivalent
  create: t.procedure
    .input(z.object({
      name: z.string().min(2).max(100),
      email: z.string().email(),
      role: z.enum(['viewer', 'editor', 'admin']).default('viewer'),
    }))
    .mutation(async ({ input, ctx }) => {
      return ctx.services.users.create(input);
    }),

  suspend: t.procedure
    .input(z.object({
      userId: z.string().uuid(),
      reason: z.string().min(10),
    }))
    .mutation(async ({ input, ctx }) => {
      ctx.requireRole('admin');
      return ctx.services.users.suspend(input.userId, input.reason);
    }),
});

export const appRouter = t.router({
  users: userRouter,
  orders: orderRouter,
  billing: billingRouter,
});

export type AppRouter = typeof appRouter;

// === Client (Next.js, React, etc.) ===
import { createTRPCReact } from '@trpc/react-query';
import type { AppRouter } from '../server/router';

const trpc = createTRPCReact<AppRouter>();

function UserProfile({ userId }: { userId: string }) {
  // Full autocomplete, type checking, error types — ZERO codegen
  const { data: user, isLoading } = trpc.users.getById.useQuery({ id: userId });
  // user is fully typed: { id: string, name: string, email: string, ... }

  const suspendMutation = trpc.users.suspend.useMutation();

  const handleSuspend = () => {
    suspendMutation.mutate({
      userId,
      reason: 'Violation of terms of service',
    });
  };

  if (isLoading) return <Skeleton />;
  return <div>{user?.name}</div>;
}
```

## gRPC

### Khi nào dùng gRPC

- **Service-to-service** communication (internal)
- **High performance** needed (binary protocol, HTTP/2, streaming)
- **Strong contracts** (protobuf schema)
- **Multi-language** systems (proto generates clients for any language)

```protobuf
// user.proto
syntax = "proto3";
package user;

service UserService {
  rpc GetUser (GetUserRequest) returns (User);
  rpc ListUsers (ListUsersRequest) returns (ListUsersResponse);
  rpc CreateUser (CreateUserRequest) returns (User);
  rpc StreamUserEvents (StreamRequest) returns (stream UserEvent);
}

message User {
  string id = 1;
  string name = 2;
  string email = 3;
  string role = 4;
  string status = 5;
  google.protobuf.Timestamp created_at = 6;
}

message GetUserRequest {
  string id = 1;
}

message ListUsersRequest {
  int32 page = 1;
  int32 page_size = 2;
  optional string status = 3;
}

message ListUsersResponse {
  repeated User users = 1;
  int32 total = 2;
}
```

## API Versioning

```typescript
// === Strategy 1: URL Versioning (most common) ===
// /api/v1/users
// /api/v2/users
app.use('/api/v1', v1Router);
app.use('/api/v2', v2Router);

// === Strategy 2: Header Versioning ===
// Accept: application/vnd.myapp.v2+json
app.use('/api/users', (req, res, next) => {
  const version = parseVersion(req.headers.accept) ?? 'v1';
  req.apiVersion = version;
  next();
});

// === Strategy 3: Query Parameter ===
// /api/users?version=2

// === Recommendation ===
// URL versioning: simplest, most discoverable
// Header versioning: "purist" REST approach
// Whichever you choose: BE CONSISTENT

// === Backward Compatibility ===
// Adding fields → NOT breaking (clients ignore unknown fields)
// Removing fields → BREAKING
// Changing field types → BREAKING
// Adding optional query params → NOT breaking
// Changing required params → BREAKING

// Deprecation strategy
app.use('/api/v1/*', (req, res, next) => {
  res.setHeader('Deprecation', 'true');
  res.setHeader('Sunset', 'Sat, 01 Jun 2025 00:00:00 GMT');
  res.setHeader('Link', '</api/v2>; rel="successor-version"');
  next();
});
```

## Pagination

```typescript
// === Offset-based (simple, most common) ===
// GET /api/users?page=3&pageSize=20

interface OffsetPaginatedResult<T> {
  data: ReadonlyArray<T>;
  pagination: {
    page: number;
    pageSize: number;
    total: number;
    totalPages: number;
    hasNextPage: boolean;
    hasPreviousPage: boolean;
  };
}

async function paginateOffset<T>(
  queryBuilder: Knex.QueryBuilder,
  page: number,
  pageSize: number,
): Promise<OffsetPaginatedResult<T>> {
  const [{ count }] = await queryBuilder.clone().count('* as count');
  const total = Number(count);
  const data = await queryBuilder.limit(pageSize).offset((page - 1) * pageSize);

  return {
    data,
    pagination: {
      page,
      pageSize,
      total,
      totalPages: Math.ceil(total / pageSize),
      hasNextPage: page * pageSize < total,
      hasPreviousPage: page > 1,
    },
  };
}

// Pros: simple, supports "go to page 50"
// Cons: inconsistent with concurrent writes, slow for deep pages (OFFSET 10000)

// === Cursor-based (scalable, consistent) ===
// GET /api/users?first=20&after=eyJpZCI6MTAwfQ==

interface CursorPaginatedResult<T> {
  edges: ReadonlyArray<{ node: T; cursor: string }>;
  pageInfo: {
    hasNextPage: boolean;
    hasPreviousPage: boolean;
    startCursor: string | null;
    endCursor: string | null;
  };
}

function encodeCursor(data: Record<string, unknown>): string {
  return Buffer.from(JSON.stringify(data)).toString('base64url');
}

function decodeCursor(cursor: string): Record<string, unknown> {
  return JSON.parse(Buffer.from(cursor, 'base64url').toString());
}

async function paginateCursor<T extends { id: string; createdAt: Date }>(
  queryBuilder: Knex.QueryBuilder,
  first: number,
  after?: string,
): Promise<CursorPaginatedResult<T>> {
  let query = queryBuilder.orderBy('created_at', 'desc').orderBy('id', 'desc');

  if (after) {
    const cursor = decodeCursor(after);
    query = query.where(function () {
      this.where('created_at', '<', cursor.createdAt)
        .orWhere(function () {
          this.where('created_at', '=', cursor.createdAt)
            .where('id', '<', cursor.id);
        });
    });
  }

  // Fetch one extra to determine hasNextPage
  const rows = await query.limit(first + 1) as T[];
  const hasNextPage = rows.length > first;
  const data = rows.slice(0, first);

  const edges = data.map(node => ({
    node,
    cursor: encodeCursor({ id: node.id, createdAt: node.createdAt }),
  }));

  return {
    edges,
    pageInfo: {
      hasNextPage,
      hasPreviousPage: !!after,
      startCursor: edges[0]?.cursor ?? null,
      endCursor: edges[edges.length - 1]?.cursor ?? null,
    },
  };
}

// Pros: consistent, performant for any depth, works with real-time data
// Cons: can't "jump to page 50", slightly more complex
```

## So sánh và chọn API style

| | REST | GraphQL | tRPC | gRPC |
|--|------|---------|------|------|
| **Protocol** | HTTP/JSON | HTTP/JSON | HTTP/JSON | HTTP/2 + Protobuf |
| **Type safety** | Manual (OpenAPI) | Schema-first | Full (zero codegen) | Proto codegen |
| **Best for** | Public APIs | Flexible client queries | Full-stack TS monorepo | Service-to-service |
| **Performance** | Good | Good (but N+1 risk) | Good | Best (binary) |
| **Learning curve** | Low | Medium | Low (TS devs) | Medium |
| **Caching** | Built-in (HTTP cache) | Complex (no native cache) | React Query | Manual |
| **File upload** | Native | Complex (multipart) | Via HTTP | Streaming |
| **Browser support** | Native | Native | Via adapter | grpc-web needed |

### Decision

```
Public API for external consumers? → REST (+ OpenAPI docs)
Full-stack TypeScript monorepo? → tRPC
Mobile + Web + different data needs? → GraphQL
Internal service-to-service, high perf? → gRPC
Simple CRUD, small team? → REST
```
