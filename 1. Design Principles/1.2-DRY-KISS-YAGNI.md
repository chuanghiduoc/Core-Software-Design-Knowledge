## DRY — Don't Repeat Yourself

> "Every piece of **knowledge** must have a single, unambiguous, authoritative representation within a system."
> — The Pragmatic Programmer

### Bản chất (hay bị hiểu sai)

DRY **KHÔNG** có nghĩa là "không được có code giống nhau". DRY nói về **knowledge** (kiến thức, business rule), không phải **code text**.

Hai đoạn code trông giống nhau nhưng thay đổi vì **lý do khác nhau** → **KHÔNG phải duplication**. Gộp chúng lại sẽ tạo **coupling sai** (wrong abstraction).

### ❌ DRY sai — Premature Abstraction

```typescript
// Hai function trông "giống nhau" → junior dev gộp lại

// Trước khi gộp (đúng)
function validateRegistrationEmail(email: string): ValidationResult {
  if (!email.includes('@')) return invalid('Invalid email format');
  if (email.endsWith('.test')) return invalid('Test emails not allowed');
  if (await isDisposableEmail(email)) return invalid('Disposable emails not allowed');
  return valid();
}

function validateNewsletterEmail(email: string): ValidationResult {
  if (!email.includes('@')) return invalid('Invalid email format');
  if (email.endsWith('.test')) return invalid('Test emails not allowed');
  // Newsletter cho phép disposable emails — business rule khác
  return valid();
}

// ❌ Sau khi gộp (sai — coupling 2 business rules khác nhau)
function validateEmail(email: string, context: 'registration' | 'newsletter'): ValidationResult {
  if (!email.includes('@')) return invalid('Invalid email format');
  if (email.endsWith('.test')) return invalid('Test emails not allowed');

  // Context flag → dấu hiệu coupling sai
  if (context === 'registration') {
    if (await isDisposableEmail(email)) return invalid('Disposable emails not allowed');
  }
  // Sau này: newsletter cần check khác, registration thêm rule...
  // Function phình to với if/else cho mỗi context
  return valid();
}
```

### ✅ DRY đúng — Extract shared KNOWLEDGE, không phải shared CODE

```typescript
// Shared knowledge: email format validation rules
// Đây là kiến thức chung thực sự — email format không thay đổi theo context
const EmailFormat = {
  isValid(email: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
  },

  isTestDomain(email: string): boolean {
    return email.endsWith('.test') || email.endsWith('.example');
  },
} as const;

// Business rules riêng cho từng context — KHÔNG gộp
function validateRegistrationEmail(email: string): ValidationResult {
  if (!EmailFormat.isValid(email)) return invalid('Invalid email format');
  if (EmailFormat.isTestDomain(email)) return invalid('Test emails not allowed');
  if (await isDisposableEmail(email)) return invalid('Disposable emails not allowed');
  return valid();
}

function validateNewsletterEmail(email: string): ValidationResult {
  if (!EmailFormat.isValid(email)) return invalid('Invalid email format');
  if (EmailFormat.isTestDomain(email)) return invalid('Test emails not allowed');
  return valid();
}
```

### DRY ở các tầng khác nhau

#### 1. Knowledge Duplication (DRY thực sự — PHẢI fix)

```typescript
// ❌ Business rule "free plan = 5 projects" xuất hiện ở 3 nơi
// Sửa 1 nơi, quên 2 nơi còn lại → bug

// pricing.ts
const FREE_PROJECT_LIMIT = 5; // Nơi 1
```

#### 2. Type Duplication (DRY thực sự — PHẢI fix)

```typescript
// ❌ Duplicate type definitions giữa client và server
// server/types.ts
interface ApiResponse {
  users: Array<{ id: string; name: string; email: string; createdAt: string }>;
  total: number;
}

// client/types.ts — copy paste, sẽ drift over time
interface UsersResponse {
  users: Array<{ id: string; name: string; email: string; createdAt: string }>;
  total: number;
}

// ✅ Single source: shared schema hoặc codegen
// Approach 1: Shared package (monorepo)
// packages/shared/src/api-types.ts
export interface User {
  id: string;
  name: string;
  email: string;
  createdAt: string;
}

export interface PaginatedResponse<T> {
  data: ReadonlyArray<T>;
  total: number;
  page: number;
  pageSize: number;
}

export type UsersResponse = PaginatedResponse<User>;

// Approach 2: Zod schema → derive types (single source = schema)
import { z } from 'zod';

const UserSchema = z.object({
  id: z.string().uuid(),
  name: z.string().min(1).max(100),
  email: z.string().email(),
  createdAt: z.string().datetime(),
});

const PaginatedResponseSchema = <T extends z.ZodType>(itemSchema: T) =>
  z.object({
    data: z.array(itemSchema),
    total: z.number().int().nonnegative(),
    page: z.number().int().positive(),
    pageSize: z.number().int().positive(),
  });

// Types derived from schema — ZERO duplication
type User = z.infer<typeof UserSchema>;
type UsersResponse = z.infer<ReturnType<typeof PaginatedResponseSchema<typeof UserSchema>>>;
```

#### 3. Structural Similarity (KHÔNG phải DRY — đừng gộp)

```typescript
// Hai function trông giống nhau nhưng phục vụ actors khác nhau
// Chúng sẽ evolve theo hướng khác nhau → đừng gộp

// admin-api: lấy tất cả users, bao gồm disabled
async function getAdminUserList(filters: AdminFilters): Promise<AdminUserView[]> {
  const users = await db.query(`
    SELECT id, name, email, status, created_at, last_login, role
    FROM users
    WHERE status = ANY($1)
    ORDER BY created_at DESC
    LIMIT $2 OFFSET $3
  `, [filters.statuses, filters.limit, filters.offset]);

  return users.map(toAdminView);
}

// public-api: chỉ lấy active users, ẩn thông tin nhạy cảm
async function getPublicUserList(filters: PublicFilters): Promise<PublicUserView[]> {
  const users = await db.query(`
    SELECT id, name, avatar_url
    FROM users
    WHERE status = 'active'
    ORDER BY name ASC
    LIMIT $1 OFFSET $2
  `, [filters.limit, filters.offset]);

  return users.map(toPublicView);
}

// Trông "duplicate" nhưng thay đổi vì lý do khác nhau:
// - Admin cần thêm field → sửa getAdminUserList
// - Compliance yêu cầu ẩn thêm data → sửa getPublicUserList
// Gộp lại = coupling 2 concerns khác nhau
```

### DRY Litmus Test

> Trước khi refactor "duplicate code", hỏi:
> 1. Hai đoạn này thay đổi vì **cùng lý do** hay **lý do khác nhau**?
> 2. Nếu tôi sửa một chỗ, chỗ kia **nhất thiết** phải sửa theo?
> 3. Chúng thuộc về **cùng actor/domain** hay khác?
>
> Nếu trả lời "khác" cho bất kỳ câu nào → **đừng gộp**. Duplicate code tốt hơn wrong abstraction.

## KISS — Keep It Simple, Stupid

> "Simplicity is the ultimate sophistication." — Leonardo da Vinci
>
> "Debugging is twice as hard as writing the code in the first place. Therefore, if you write the code as cleverly as possible, you are, by definition, not smart enough to debug it." — Brian Kernighan

### Bản chất

Chọn giải pháp đơn giản nhất mà vẫn đúng. Đơn giản ≠ dễ. Đơn giản = ít moving parts, dễ hiểu, dễ debug, dễ thay đổi.

### ❌ Over-engineering — Abstract Factory cho 1 case

```typescript
// Yêu cầu: Parse config từ JSON file
// "Senior" dev: "Cần Factory Pattern cho tương lai hỗ trợ YAML, TOML..."

interface ConfigParser {
  parse(content: string): Config;
}

interface ConfigParserFactory {
  createParser(format: ConfigFormat): ConfigParser;
}

class JsonConfigParser implements ConfigParser {
  parse(content: string): Config {
    return JSON.parse(content);
  }
}

class ConfigParserFactoryImpl implements ConfigParserFactory {
  private readonly parsers = new Map<ConfigFormat, new () => ConfigParser>();

  register(format: ConfigFormat, parserClass: new () => ConfigParser): void {
    this.parsers.set(format, parserClass);
  }

  createParser(format: ConfigFormat): ConfigParser {
    const ParserClass = this.parsers.get(format);
    if (!ParserClass) throw new UnsupportedFormatError(format);
    return new ParserClass();
  }
}

// Registry setup
const factory = new ConfigParserFactoryImpl();
factory.register('json', JsonConfigParser);

// Usage
const parser = factory.createParser('json');
const config = parser.parse(rawContent);
```

### ✅ KISS — Just parse the JSON

```typescript
// Hiện tại chỉ cần JSON → viết đúng cái cần
function loadConfig(filePath: string): Config {
  const content = fs.readFileSync(filePath, 'utf-8');
  return JSON.parse(content) as Config;
}

// Nếu SAU NÀY cần YAML → refactor KHI CẦN, mất 5 phút
// Bạn đã tiết kiệm 50 dòng code, 1 interface, 2 classes, 1 factory
```

### ❌ Type Gymnastics — Over-complex Generics

```typescript
// "Type-safe" nhưng không ai hiểu

type DeepPartial<T> = T extends object
  ? { [P in keyof T]?: DeepPartial<T[P]> }
  : T;

type PathKeys<T, Prefix extends string = ''> = T extends object
  ? {
      [K in keyof T & string]: T[K] extends object
        ? PathKeys<T[K], `${Prefix}${K}.`> | `${Prefix}${K}`
        : `${Prefix}${K}`;
    }[keyof T & string]
  : never;

type PathValue<T, P extends string> = P extends `${infer K}.${infer Rest}`
  ? K extends keyof T
    ? PathValue<T[K], Rest>
    : never
  : P extends keyof T
    ? T[P]
    : never;

function getNestedValue<T, P extends PathKeys<T>>(
  obj: T,
  path: P,
): PathValue<T, P> {
  return path.split('.').reduce((acc: any, key) => acc?.[key], obj);
}
```

### ✅ KISS — Good enough type safety

```typescript
// Đơn giản, dễ hiểu, đủ type-safe cho 99% use cases

function get<T>(obj: Record<string, unknown>, path: string): T | undefined {
  return path.split('.').reduce<unknown>(
    (acc, key) => (acc as Record<string, unknown>)?.[key],
    obj,
  ) as T | undefined;
}

// Hoặc tốt hơn: dùng optional chaining thay vì utility function
const value = config?.database?.connection?.poolSize;
// Nếu object nesting > 3 levels → flatten structure thay vì viết getter phức tạp
```

### KISS trong Architecture Decisions

```typescript
// ❌ KISS violation: Microservices cho team 3 người
// User Service → API Gateway → Auth Service → Email Service → Queue → Worker

// ✅ KISS: Monolith modular cho team nhỏ
// src/
//   modules/
//     users/
//     auth/
//     email/
//   shared/
//   main.ts

// Khi nào tách microservice? Khi bạn CÓ DỮ LIỆU chứng minh monolith là bottleneck
// - Team > 15 người và merge conflicts liên tục
// - Module cần scale independently (thực sự, không phải giả thuyết)
// - Deployment coupling gây incident
```

### Complexity Budget

> Mỗi project có một "budget phức tạp" hữu hạn. Mỗi abstraction, pattern, framework bạn thêm vào
> đều tiêu tốn budget này. Dùng budget cho những chỗ THỰC SỰ phức tạp, giữ phần còn lại đơn giản.
>
> Ví dụ: Nếu domain logic phức tạp → cho phép phức tạp ở domain layer, giữ infra layer đơn giản.
> Nếu infrastructure phức tạp (multi-region, high availability) → giữ domain logic đơn giản.

## YAGNI — You Aren't Gonna Need It

> "Always implement things when you actually need them, never when you just foresee that you need them."
> — Ron Jeffries (co-founder of XP)

### Bản chất

Đừng implement tính năng cho tương lai. Code bạn viết hôm nay cho "tương lai" thường sai vì bạn chưa hiểu đủ requirements tương lai. Code đó phải maintain, test, và sẽ ảnh hưởng đến mọi decision sau này.

### Chi phí thực sự của code "cho tương lai"

```
Code viết hôm nay cho tương lai:
├── Thời gian viết: 4 giờ
├── Thời gian review: 1 giờ
├── Thời gian viết tests: 2 giờ
├── Thời gian maintain mỗi tháng: 30 phút
├── Cognitive load cho dev mới đọc code: +15 phút/lần
├── Probability thực sự dùng: ~20%
├── Probability dùng đúng như thiết kế: ~5%
└── Probability phải rewrite khi thực sự cần: ~80%

→ Expected value: NEGATIVE. Bạn mất thời gian chắc chắn cho lợi ích không chắc chắn.
```

### ✅ YAGNI — Just export CSV

```typescript
// Viết đúng cái cần. Khi cần PDF → refactor 5 phút.

function exportToCsv(data: ReportData): string {
  const headers = Object.keys(data.rows[0] ?? {}).join(',');
  const rows = data.rows.map(row =>
    Object.values(row)
      .map(v => `"${String(v).replace(/"/g, '""')}"`)
      .join(',')
  );
  return [headers, ...rows].join('\n');
}

// Usage
app.get('/reports/:id/export', async (req, res) => {

  const csv = exportToCsv(report);
  res.setHeader('Content-Type', 'text/csv');
  res.setHeader('Content-Disposition', `attachment; filename="${report.name}.csv"`);
  res.send(csv);
});

// Tổng: ~15 dòng. Done. Ship it.
```

### YAGNI ≠ Không nghĩ về tương lai

YAGNI không có nghĩa là viết code cẩu thả. Nó có nghĩa là:

```typescript
// ✅ YAGNI-compatible: Code sạch, dễ thay đổi SAU NÀY

// Tách function rõ ràng → dễ refactor khi cần
function formatReportRow(row: Record<string, unknown>): string {
  return Object.values(row)
    .map(v => `"${String(v).replace(/"/g, '""')}"`)
    .join(',');
}

function exportToCsv(data: ReportData): string {
  const headers = Object.keys(data.rows[0] ?? {}).join(',');
  const rows = data.rows.map(formatReportRow);
  return [headers, ...rows].join('\n');
}

// Khi cần thêm PDF: thêm function exportToPdf(), KHÔNG cần refactor code hiện tại
// Khi cần thêm format thứ 3: LÚC ĐÓ extract interface nếu thấy pattern
```

### Khi nào YAGNI KHÔNG áp dụng

| Tình huống | Lý do |
|-----------|-------|
| **Database schema** | Schema migration đắt đỏ. Suy nghĩ trước hợp lý |
| **Public API contracts** | Breaking changes ảnh hưởng consumers. Design cẩn thận |
| **Security** | Đừng nói "YAGNI" cho auth, encryption, input validation |
| **Data model fundamentals** | Chuyển từ single-tenant sang multi-tenant sau này rất đau |
| **Accessibility** | Thêm a11y sau = rewrite. Làm từ đầu |

## Khi 3 nguyên lý xung đột nhau

### DRY vs KISS

```typescript
// DRY nói: "Gộp lại!"
// KISS nói: "Đừng tạo abstraction phức tạp!"

// Resolution: KISS thắng. Duplicate code đơn giản tốt hơn abstraction phức tạp.
// "Duplication is far cheaper than the wrong abstraction." — Sandi Metz
```

### DRY vs YAGNI

```typescript
// DRY nói: "Extract shared utility!"
// YAGNI nói: "Chỉ dùng 2 lần, đừng abstract!"

// Resolution: Rule of Three.
// Lần 1: Viết inline
// Lần 2: Copy (đánh dấu TODO)
// Lần 3: Refactor extract
```

### KISS vs Feature Requirements

```typescript
// KISS nói: "Dùng simple solution!"
// Requirement nói: "Cần handle 47 edge cases!"

// Resolution: Simple KHÔNG có nghĩa là easy hay incomplete.
// Simple = giải pháp rõ ràng nhất CHO ĐỘ PHỨC TẠP YÊU CẦU.
// Nếu domain phức tạp → code phức tạp là chấp nhận được,
// miễn là nó không phức tạp HƠN MỨC CẦN THIẾT.
```

### Decision Framework

```
Khi phải chọn, ưu tiên theo thứ tự:

1. Correctness — Code PHẢI đúng
2. KISS — Giữ đơn giản nhất có thể
3. YAGNI — Chỉ làm cái cần NGAY BÂY GIỜ
4. DRY — Loại bỏ knowledge duplication (không phải code duplication)

Nếu DRY yêu cầu abstraction phức tạp → chọn duplicate code (KISS > DRY)
Nếu "chuẩn bị cho tương lai" thêm complexity → đừng (YAGNI + KISS)
Nếu simplicity sacrifice correctness → chọn correct (Correctness > KISS)
```
