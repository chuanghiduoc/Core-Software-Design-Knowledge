## 1. Document Databases (MongoDB)

Document DB lưu data dạng JSON-like documents. Không cần fixed schema.

**Dùng khi:** Schema thay đổi thường xuyên, nested/hierarchical data, rapid prototyping, read-heavy denormalized workloads.

**KHÔNG dùng khi:** Nhiều relationships (social graph), cần ACID across collections, heavy aggregation/OLAP, data consistency critical (financial).

### Embedding vs Referencing

```typescript
// ❌ Embed mọi thứ: data thay đổi thường xuyên, grow unbounded
interface BadOrder {
  _id: ObjectId;
  customer: { name: string; email: string; };  // ← Duplicate, stale khi customer update
  items: Array<{
    product: { name: string; price: number; description: string; images: string[]; };  // ← Product thay đổi giá = update triệu orders
    quantity: number;
  }>;
  comments: Array<{ userId: ObjectId; text: string; }>;  // ← Unbounded growth → 16MB limit
}

// ✅ Embed cái KHÔNG thay đổi, reference cái thay đổi
interface Order {
  _id: ObjectId;
  customerId: ObjectId;  // Reference: customer data thay đổi
  items: Array<{
    productId: ObjectId;  // Reference back
    name: string;          // Snapshot tại thời điểm mua (KHÔNG đổi)
    unitPrice: number;     // Snapshot giá tại thời điểm mua
    quantity: number;
  }>;
  shippingAddress: {       // Embed 1:1, bounded
    street: string; city: string; postalCode: string; country: string;
  };
  status: string;
  totalAmount: number;
  createdAt: Date;
}

// Comments: separate collection (unbounded growth)
interface OrderComment {
  _id: ObjectId;
  orderId: ObjectId;
  userId: ObjectId;
  text: string;
  createdAt: Date;
}
```

```typescript
// ✅ Access pattern driven queries
class OrderRepository {
  // 1 query: order với embedded data
  async getOrder(id: string) {
    return this.orders.findOne({ _id: new ObjectId(id) });
  }

  // $lookup = LEFT JOIN khi cần cross-collection
  async getOrderWithCustomer(id: string) {
    return this.orders.aggregate([
      { $match: { _id: new ObjectId(id) } },
      { $lookup: { from: 'customers', localField: 'customerId', foreignField: '_id', as: 'customer' } },
      { $unwind: '$customer' },
    ]).toArray();
  }
}
```

### Schema Patterns

```typescript
// ✅ Bucket Pattern: group data points vào time buckets
// 1 doc/point → 86,400 docs/day/sensor
// 1 bucket/hour → 24 docs/day/sensor (3600x ít)
interface SensorBucket {
  sensorId: string;
  startTime: Date;
  count: number;
  readings: Array<{ timestamp: Date; temperature: number; humidity: number; }>;
  summary: { avgTemp: number; maxTemp: number; minTemp: number; };
}

// ✅ Computed Pattern: pre-compute aggregates
interface Product {
  _id: ObjectId;
  name: string;
  reviewStats: {
    totalReviews: number; averageRating: number;
    distribution: { '1': number; '2': number; '3': number; '4': number; '5': number; };
  };
}
// Update atomically: db.products.updateOne({ _id }, { $inc: { 'reviewStats.totalReviews': 1 } })

// ✅ Outlier Pattern: embed first N, overflow to separate collection
interface BookWithReviews {
  _id: ObjectId; title: string;
  reviews: Array<Review>;   // First 20 embedded
  reviewCount: number;
  hasOverflow: boolean;      // Flag: more in overflow collection
}
```

## 2. Key-Value Stores (Redis)

Toàn bộ data in-memory → extremely fast. Values có nhiều data structures.

**Dùng:** Caching, rate limiting, leaderboards, pub/sub, simple queues, distributed locks.
**KHÔNG dùng:** Primary database, complex queries, data > RAM, ACID transactions.

### Data Structures & Use Cases

```typescript
import Redis from 'ioredis';
const redis = new Redis(process.env.REDIS_URL);

// ✅ Strings: Caching
async function getCachedUser(userId: string): Promise<User | null> {
  const cached = await redis.get(`user:${userId}`);
  if (cached) return JSON.parse(cached);
  const user = await db.query('SELECT * FROM users WHERE id = $1', [userId]);
  if (user) await redis.set(`user:${userId}`, JSON.stringify(user), 'EX', 300);
  return user;
}

// ✅ Sorted Sets: Leaderboard
async function addScore(userId: string, score: number) {
  await redis.zadd('leaderboard', score, userId);
}
async function getTopN(n: number) {
  const results = await redis.zrevrange('leaderboard', 0, n - 1, 'WITHSCORES');
  const entries: Array<{ userId: string; score: number }> = [];
  for (let i = 0; i < results.length; i += 2)
    entries.push({ userId: results[i], score: parseFloat(results[i + 1]) });
  return entries;
}

// ✅ Rate Limiting (sliding window with sorted sets)
async function checkRateLimit(userId: string, limit: number, windowSec: number) {
  const key = `ratelimit:${userId}`;
  const now = Date.now();
  const pipe = redis.pipeline();
  pipe.zremrangebyscore(key, 0, now - windowSec * 1000);
  pipe.zadd(key, now, `${now}`);
  pipe.zcard(key);
  pipe.expire(key, windowSec);
  const results = await pipe.exec();
  const count = results![2][1] as number;
  return { allowed: count <= limit, remaining: Math.max(0, limit - count) };
}

// ✅ Hashes: Session storage (partial read/write)
async function updateSession(sessionId: string, data: Partial<SessionData>) {
  await redis.hset(`session:${sessionId}`, ...Object.entries(data).flat());
  await redis.expire(`session:${sessionId}`, 3600);
}

// ✅ Lists: Recent activity (capped)
async function addActivity(userId: string, activity: Activity) {
  const key = `activity:${userId}`;
  await redis.lpush(key, JSON.stringify(activity));
  await redis.ltrim(key, 0, 99);  // Keep last 100
  await redis.expire(key, 86400);
}
```

## 3. Wide-Column Stores (Cassandra/ScyllaDB)

Data tổ chức theo partition key → clustering columns. Thiết kế hoàn toàn **query-driven**.

**Dùng khi:** Write-heavy (IoT, logs), massive scale (PB), known query patterns, multi-datacenter.
**KHÔNG dùng khi:** Ad-hoc queries, cần JOINs, strong consistency, small datasets (<100GB).

### Partition Key Design

```sql
-- ❌ Partition key cardinality thấp → hot partition
CREATE TABLE events (
  country TEXT,     -- US, CN chiếm 50%+ data → node overloaded
  event_id UUID, PRIMARY KEY (country, event_id)
);

-- ✅ Compound partition key phân bố đều
CREATE TABLE user_events (
  user_id UUID, event_date DATE, event_id TIMEUUID,
  event_type TEXT, data TEXT,
  PRIMARY KEY ((user_id, event_date), event_id)
) WITH CLUSTERING ORDER BY (event_id DESC);
-- Mỗi user mỗi ngày = 1 partition (bounded size)
```

### Query-Driven Modeling: 1 query = 1 table

```typescript
// ✅ Cassandra: duplicate data across tables optimized per query
// Query 1: "User's recent orders" → Table: orders_by_user
// Query 2: "Pending orders today" → Table: orders_by_status
// Application MUST write to BOTH tables

class OrderService {
  async createOrder(order: Order) {
    await cassandra.execute(`
      BEGIN BATCH
        INSERT INTO orders_by_user (user_id, order_date, order_id, status, total)
        VALUES (?, ?, ?, ?, ?);
        INSERT INTO orders_by_status (status, order_date, order_id, user_id, total)
        VALUES (?, ?, ?, ?, ?);
      APPLY BATCH;
    `, [order.userId, order.date, order.id, order.status, order.total,
        order.status, order.date, order.id, order.userId, order.total]);
  }
}
```

## 4. Graph Databases (Neo4j)

Nodes (entities) + Relationships (edges), cả hai có properties. Tối ưu cho traversal.

**Dùng khi:** Relationships là first-class (social networks, recommendations), variable-length path queries, pattern matching (fraud detection).
**KHÔNG dùng khi:** Bulk aggregation/OLAP, simple CRUD, high-volume writes, tabular data.

```sql
-- ❌ "Mutual friends" trong PostgreSQL → recursive JOINs, chậm exponentially
WITH user_friends AS (SELECT friend_id FROM friendships WHERE user_id = 'alice'),
friend_friends AS (SELECT f.friend_id FROM friendships f JOIN user_friends uf ON f.user_id = uf.friend_id)
SELECT friend_id, COUNT(*) FROM friend_friends GROUP BY 1;
-- 3 levels = 3 JOINs. 6 levels = unmanageable
```

```cypher
// ✅ Cypher: natural graph queries
// Mutual friends
MATCH (alice:User {id: 'alice'})-[:FRIENDS_WITH]-(friend)-[:FRIENDS_WITH]-(fof)
WHERE NOT (alice)-[:FRIENDS_WITH]-(fof) AND fof <> alice
RETURN fof.name, COUNT(friend) AS mutualFriends ORDER BY mutualFriends DESC;

// Shortest path
MATCH path = shortestPath((a:User {id: 'alice'})-[:FRIENDS_WITH*..6]-(b:User {id: 'bob'}))
RETURN path;

// Recommendations
MATCH (u:User {id: 'alice'})-[:PURCHASED]->(p)<-[:PURCHASED]-(similar)-[:PURCHASED]->(rec)
WHERE NOT (u)-[:PURCHASED]->(rec)
RETURN rec.name, COUNT(similar) AS score ORDER BY score DESC LIMIT 5;
```

```typescript
// ✅ TypeScript: Neo4j driver
class SocialGraphService {
  async getMutualFriends(userId: string, targetId: string) {
    const session = this.driver.session();
    try {
      const result = await session.run(
        `MATCH (a:User {id: $userId})-[:FRIENDS_WITH]-(mutual)-[:FRIENDS_WITH]-(b:User {id: $targetId})
         RETURN mutual.id AS id, mutual.name AS name`, { userId, targetId });
      return result.records.map(r => ({ id: r.get('id'), name: r.get('name') }));
    } finally { await session.close(); }
  }
}
```

## 5. Search Engines (Elasticsearch)

Inverted index → full-text search cực nhanh. **KHÔNG phải** primary database — dùng song song.

**Dùng:** Full-text search + relevance, log aggregation, autocomplete, faceted search.
**KHÔNG dùng:** Primary data store, simple LIKE queries (PG tsvector đủ), strong consistency.

### Mapping Design

```typescript
// ❌ Dynamic mapping: ES tự đoán types → sai, không tối ưu
// ✅ Explicit mapping
const productMapping = {
  mappings: {
    properties: {

          keyword: { type: 'keyword' },  // Sorting, aggregation

  settings: {
    analysis: {
      analyzer: {
        autocomplete_analyzer: {
          type: 'custom', tokenizer: 'edge_ngram_tokenizer', filter: ['lowercase'],
        },
```

```typescript
// ✅ Search with filters, facets, highlights
async function searchProducts(params: SearchParams) {
  const { query, category, minPrice, maxPrice, page = 1, size = 20 } = params;
  const must: any[] = query ? [{ multi_match: { query, fields: ['name^3', 'description', 'tags^2'], fuzziness: 'AUTO' } }] : [{ match_all: {} }];
  const filter: any[] = [{ term: { inStock: true } }];
  if (category) filter.push({ term: { category } });
  if (minPrice || maxPrice) filter.push({ range: { price: { ...(minPrice && { gte: minPrice }), ...(maxPrice && { lte: maxPrice }) } } });

  return es.search({
    index: 'products',
    body: {
      query: { bool: { must, filter } },
      aggs: { categories: { terms: { field: 'category', size: 20 } } },
      from: (page - 1) * size, size,
      highlight: { fields: { name: {}, description: { fragment_size: 150 } } },
    },
  });
}
```

## 6. Time-Series Databases

Optimized cho **append-heavy, time-ordered data**. Tự động compress và downsample.

**Dùng:** IoT sensors, application metrics, financial ticks, event analytics.

### Bucket Pattern

```typescript
// ❌ 1 row/data point: 1 sensor x 1/sec x 86400/day = 86,400 rows/day/sensor
// ✅ 1 bucket/hour: 24 rows/day/sensor (3600x ít documents)
interface MetricBucket {
  sensorId: string; bucketStart: Date;
  measurements: Array<{ timestamp: Date; value: number; }>;
  count: number; sum: number; min: number; max: number; avg: number;
}
```

```sql
-- ✅ TimescaleDB: automatic bucketing
CREATE TABLE metrics (time TIMESTAMPTZ NOT NULL, sensor_id TEXT NOT NULL, temperature DOUBLE PRECISION);
SELECT create_hypertable('metrics', 'time');

-- Continuous aggregate
CREATE MATERIALIZED VIEW metrics_hourly WITH (timescaledb.continuous) AS
SELECT time_bucket('1 hour', time) AS bucket, sensor_id,
  AVG(temperature) AS avg_temp, MAX(temperature) AS max_temp, COUNT(*) AS samples
FROM metrics GROUP BY 1, 2;
```

### Downsampling Strategy

```
Raw data (per-second):    keep 7 days
1-minute aggregates:      keep 30 days
1-hour aggregates:        keep 1 year
1-day aggregates:         keep forever
```

## 7. Polyglot Persistence

Sử dụng **DB phù hợp nhất cho từng use case** trong cùng hệ thống.

```typescript
// ❌ Ép mọi thứ vào PostgreSQL
// Sessions → PG: unnecessary durability. Leaderboard → PG: slow. Search → PG tsvector: limited.

// ✅ Right tool for the job
// PostgreSQL:     Users, Orders, Payments (ACID, referential integrity)
// Redis:          Sessions, Cache, Rate limiting, Leaderboards (sub-ms latency)
// Elasticsearch:  Product search, Log aggregation (full-text, relevance)
// TimescaleDB:    Metrics, IoT data (auto-partition, compression)
// Neo4j:          Social graph, Recommendations (native traversal)
```

```typescript
// ✅ Unified service abstracting multiple DBs
class ProductService {
  constructor(private pg: Pool, private redis: Redis, private es: EsClient) {}

  async getProduct(id: string): Promise<Product | null> {
    const cached = await this.redis.get(`product:${id}`);
    if (cached) return JSON.parse(cached);                     // Redis: <1ms
    const { rows } = await this.pg.query('SELECT * FROM products WHERE id = $1', [id]);  // PG: source of truth
    if (rows[0]) await this.redis.set(`product:${id}`, JSON.stringify(rows[0]), 'EX', 300);
    return rows[0] ?? null;
  }

  async search(query: string) {
    return this.es.search({                                    // ES: full-text
      index: 'products',
      body: { query: { multi_match: { query, fields: ['name', 'description'] } } },
    });
  }

  async update(id: string, data: UpdateInput) {
    const { rows } = await this.pg.query('UPDATE products SET name=$1 WHERE id=$2 RETURNING *', [data.name, id]);
    await this.redis.del(`product:${id}`);                     // Invalidate cache
    await this.es.index({ index: 'products', id, body: rows[0] });  // Sync search
    return rows[0];
  }
}
```

### Decision Matrix

| Access Pattern | DB | Ví dụ |
|---------------|-----|-------|
| ACID, JOINs, complex queries | PostgreSQL | Orders, Users, Payments |
| Sub-ms key-value lookup | Redis | Sessions, Cache, Rate limits |
| Full-text + relevance | Elasticsearch | Search, Logs |
| High-volume time-ordered writes | TimescaleDB/InfluxDB | Metrics, IoT |
| Graph traversal | Neo4j | Social, Recommendations |
| Massive scale, known queries | Cassandra/ScyllaDB | Event logs at scale |
| Flexible schema, documents | MongoDB | CMS, Product catalogs |
