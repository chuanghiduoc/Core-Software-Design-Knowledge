## How DNS Works

> DNS là distributed system lâu đời nhất, lớn nhất, và thành công nhất thế giới.
> Mỗi ngày xử lý hàng nghìn tỷ queries, eventually consistent, hierarchical.

### Architecture

```
Lookup: www.example.com

Client → Recursive Resolver (ISP/8.8.8.8) → Root Server (.)
                                            → TLD Server (.com)
                                            → Authoritative Server (example.com)
                                            → IP: 93.184.216.34

Caching tại MỌI tầng:
  - Browser cache (seconds-minutes)
  - OS resolver cache (minutes)
  - Recursive resolver cache (TTL-based, hours)
  - CDN/anycast cache (varies)
```

### DNS như một Distributed System

```typescript
    // 1. Check cache
    const cached = this.cache.get(cacheKey);
    if (cached && cached.expiresAt > Date.now()) {
      return cached.record; // Cache HIT — eventually consistent!

    // 2. Cache miss → recursive resolution
    const record = await this.recursiveResolve(domain, type);

    // 3. Cache với TTL
    if (record) {
      this.cache.set(cacheKey, {
        record,
        expiresAt: Date.now() + record.ttl * 1000,
      });
    }

    return record;
  }

  private async recursiveResolve(
    domain: string,
    type: DNSRecord['type'],
  ): Promise<DNSRecord | null> {

    // Mỗi bước có thể cached tại recursive resolver
    return null; // simplified
  }
}
```

### Partitions, Replicas, ISR

```typescript
// Kafka concepts mapped to TypeScript

interface KafkaTopic {
  name: string;
  partitions: KafkaPartition[];
  replicationFactor: number;       // Mỗi partition có bao nhiêu replicas
  config: {
    'min.insync.replicas': number; // Minimum ISR để accept writes
    'retention.ms': number;         // Data retention
  };
}

interface KafkaPartition {
  id: number;
  leader: BrokerId;                // Broker chịu trách nhiệm reads/writes
  replicas: BrokerId[];            // Tất cả brokers giữ copy
  isr: BrokerId[];                 // In-Sync Replicas — đã catch up với leader
}

type BrokerId = number;

// ISR (In-Sync Replicas) — Core concept
// ISR = replicas đã replicate hết messages từ leader
//
// Ví dụ: Partition 0 có replicas [1, 2, 3], leader = 1
//   - Broker 2 đã replicate hết → ISR = [1, 2, 3]
//   - Broker 3 lag behind → ISR = [1, 2] ← broker 3 bị loại
//   - Broker 3 catch up → ISR = [1, 2, 3] ← broker 3 quay lại

// Write Acknowledgment Modes:
// acks=0:   Producer không đợi ACK → nhanh nhất, có thể mất data
// acks=1:   Đợi leader ACK → leader crash = mất data chưa replicate
// acks=all: Đợi TẤT CẢ ISR ACK → chậm nhất, an toàn nhất

// Configuration thực tế:
// acks=all + min.insync.replicas=2 + replication.factor=3
// → Tolerate 1 broker failure without data loss
// → 2 trong 3 replicas phải ACK trước khi write thành công
```

## How Redis Cluster Works

### Hash Slots

```
Redis Cluster chia keyspace thành 16384 hash slots.
Mỗi node chịu trách nhiệm một phần hash slots.

Key → CRC16(key) % 16384 → hash slot → node

3 master nodes:
  Node A: slots 0-5460
  Node B: slots 5461-10922
  Node C: slots 10923-16383

Thêm Node D:
  Migrate 1/4 slots từ A, B, C sang D
  A: 0-4095, B: 5461-9557, C: 10923-14287, D: 4096-5460,9558-10922,14288-16383
```

```typescript
// Redis Cluster client — hash slot routing

class RedisClusterClient {
  private slotMap = new Map<number, RedisNode>(); // slot → node

  constructor(private readonly nodes: RedisNode[]) {}

  async initialize(): Promise<void> {
    // CLUSTER SLOTS command: lấy mapping slot → node
    const slotRanges = await this.nodes[0].clusterSlots();
    for (const range of slotRanges) {
      for (let slot = range.start; slot <= range.end; slot++) {
        this.slotMap.set(slot, range.master);
      }
    }
  }

  async get(key: string): Promise<string | null> {
    const node = this.getNodeForKey(key);
    try {
      return await node.get(key);
    } catch (error) {
      if (this.isMovedError(error)) {
        // MOVED 3999 127.0.0.1:6381
        // Slot đã migrate sang node khác → update mapping và retry
        const newNode = this.parseMovedError(error);
        this.slotMap.set(this.hashSlot(key), newNode);
        return newNode.get(key);
      }
      if (this.isAskError(error)) {
        // ASK 3999 127.0.0.1:6381
        // Slot đang migrate → redirect tạm thời (không update mapping)
        const targetNode = this.parseAskError(error);
        await targetNode.asking(); // Gửi ASKING command trước
        return targetNode.get(key);
      }
      throw error;
    }
  }

  async set(key: string, value: string, ttl?: number): Promise<void> {
    const node = this.getNodeForKey(key);
    await node.set(key, value, ttl);
  }

  private getNodeForKey(key: string): RedisNode {
    const slot = this.hashSlot(key);
    const node = this.slotMap.get(slot);
    if (!node) throw new Error(`No node for slot ${slot}`);
    return node;
  }

  // CRC16 hash → slot number
  private hashSlot(key: string): number {
    // Hash tag support: {user:123}.name → hash chỉ phần {user:123}
    // → keys cùng hash tag → cùng slot → cùng node
    const hashTag = key.match(/\{([^}]+)\}/)?.[1];
    const hashKey = hashTag ?? key;
    return this.crc16(hashKey) % 16384;
  }

  private crc16(str: string): number {
    let crc = 0;
    for (let i = 0; i < str.length; i++) {
      crc = ((crc << 8) & 0xffff) ^ CRC16_TABLE[((crc >> 8) ^ str.charCodeAt(i)) & 0xff];
    }
    return crc;
  }

  private isMovedError(error: unknown): boolean {
    return error instanceof Error && error.message.startsWith('MOVED');
  }

  private isAskError(error: unknown): boolean {
    return error instanceof Error && error.message.startsWith('ASK');
  }

  private parseMovedError(error: unknown): RedisNode {
    // Parse "MOVED 3999 127.0.0.1:6381" → find node
    return this.nodes[0]; // simplified
  }

  private parseAskError(error: unknown): RedisNode {
    return this.nodes[0]; // simplified
  }
}

// Hash tag: keys liên quan phải ở cùng node để dùng multi-key commands
// WRONG: user:123:profile, user:123:settings → có thể ở khác node
// RIGHT: {user:123}:profile, {user:123}:settings → cùng slot
```

### Redis Cluster Failover

```typescript
// Failover flow:
// 1. Master node crash
// 2. Replica detect master unreachable (cluster-node-timeout)
// 3. Replica request votes từ other masters
// 4. Majority masters vote OK → replica promote thành master
// 5. Cluster update slot mapping

// Vấn đề: Async replication → có thể mất data
// Master write → ACK client → crash TRƯỚC KHI replicate → data lost

// Mitigation:
// WAIT command: đợi N replicas ACK trước khi return
class SafeRedisWriter {
  constructor(private readonly redis: Redis) {}

  async writeWithDurability(
    key: string,
    value: string,
    minReplicas: number = 1,
    timeoutMs: number = 1000,
  ): Promise<WriteResult> {
    // 1. Write to master
    await this.redis.set(key, value);

    // 2. WAIT: đợi ít nhất minReplicas acknowledge
    const ackedReplicas = await this.redis.wait(minReplicas, timeoutMs);

    if (ackedReplicas < minReplicas) {
      // Không đủ replicas ACK trong timeout
      // Trade-off: accept risk hay rollback?
      return {
        success: true,
        durability: 'partial',
        ackedReplicas,
        warning: `Only ${ackedReplicas}/${minReplicas} replicas acknowledged`,
      };
    }

    return { success: true, durability: 'full', ackedReplicas };
  }
}

interface WriteResult {
  success: boolean;
  durability: 'full' | 'partial';
  ackedReplicas: number;
  warning?: string;
}
```

## How PostgreSQL Replication Works

### Streaming Replication (Physical)

```
Primary (read/write) → WAL stream → Standby (read-only)

WAL = Write-Ahead Log
  Mọi thay đổi được ghi vào WAL TRƯỚC KHI apply vào data files
  Primary stream WAL records tới standbys
  Standbys replay WAL → dữ liệu giống primary

2 modes:
  Async: Primary không đợi standby → nhanh, có thể mất data
  Sync:  Primary đợi standby ACK  → chậm hơn, không mất data
```

```typescript
// PostgreSQL replication-aware application

interface PgReplicaConfig {
  primary: DatabasePoolConfig;       // Read/write
  replicas: DatabasePoolConfig[];     // Read-only
  maxAcceptableLagBytes: number;      // Max WAL lag
}

class PgReplicaRouter {
  private primaryPool: DatabasePool;
  private replicaPools: DatabasePool[];

  constructor(config: PgReplicaConfig) {
    this.primaryPool = createPool(config.primary);
    this.replicaPools = config.replicas.map(createPool);
  }

  // Write → luôn primary
  async write(query: string, params: unknown[]): Promise<QueryResult> {
    return this.primaryPool.query(query, params);
  }

  // Read → replica (nếu healthy) hoặc primary (fallback)
  async read(
    query: string,
    params: unknown[],
    options: { requireFresh?: boolean } = {},
  ): Promise<QueryResult> {
    if (options.requireFresh) {
      return this.primaryPool.query(query, params);
    }

    // Round-robin across healthy replicas
    const healthyReplica = await this.pickHealthyReplica();
    if (healthyReplica) {
      return healthyReplica.query(query, params);
    }

    // Fallback to primary
    console.warn('All replicas unhealthy, falling back to primary');
    return this.primaryPool.query(query, params);
  }

  // Pattern: Write-then-read consistency
  // Sau khi write, đọc từ primary trong N seconds
  async writeAndRead<T>(
    writeQuery: string,
    writeParams: unknown[],
    readQuery: string,
    readParams: unknown[],
  ): Promise<T> {
    await this.primaryPool.query(writeQuery, writeParams);
    // Đọc từ PRIMARY ngay sau write → đảm bảo read-your-writes
    const result = await this.primaryPool.query(readQuery, readParams);
    return result.rows[0] as T;
  }

  private async pickHealthyReplica(): Promise<DatabasePool | null> {
    for (const replica of this.shuffled(this.replicaPools)) {
      try {
        const lag = await this.getReplicationLag(replica);
        if (lag.lagBytes < 1_000_000) { // < 1MB lag
          return replica;
        }
      } catch {
        continue; // Replica unavailable
      }
    }
    return null;
  }

  private async getReplicationLag(
    replica: DatabasePool,
  ): Promise<{ lagBytes: number; lagSeconds: number }> {
    const result = await replica.query(`
      SELECT
        COALESCE(pg_wal_lsn_diff(
          pg_last_wal_receive_lsn(),
          pg_last_wal_replay_lsn()
        ), 0) AS lag_bytes,
        COALESCE(EXTRACT(EPOCH FROM (
          now() - pg_last_xact_replay_timestamp()
        )), 0) AS lag_seconds
    `);

    return {
      lagBytes: Number(result.rows[0].lag_bytes),
      lagSeconds: Number(result.rows[0].lag_seconds),
    };
  }

  private shuffled<T>(arr: T[]): T[] {
    const copy = [...arr];
    for (let i = copy.length - 1; i > 0; i--) {
      const j = Math.floor(Math.random() * (i + 1));
      [copy[i], copy[j]] = [copy[j], copy[i]];
    }
    return copy;
  }
}
```

### Logical Replication

```
Logical Replication: replicate ở mức TABLE/ROW thay vì WAL byte stream.

Use cases:
  - Replicate chỉ một số tables (không phải toàn bộ DB)

```

## Network Partitions in Practice

### Các loại partition

```
1. Total partition:    Node A hoàn toàn không liên lạc được Node B
2. Partial partition:  A → B OK, B → A FAIL (asymmetric)
3. Intermittent:       Connection flap (up-down-up-down)
4. Slow network:       Không mất packet, nhưng latency 10x bình thường

Trong practice, #3 và #4 phổ biến nhất và KHÓ HANDLE nhất
```

## Designing for Failure

### Idempotency Keys

```typescript
// Idempotency: gọi N lần cho kết quả giống gọi 1 lần
// CRITICAL cho mọi write operation trong distributed systems

interface IdempotencyStore {
  get(key: string): Promise<StoredResult | null>;
  set(key: string, result: StoredResult, ttl: number): Promise<void>;
}

class IdempotentRequestHandler {
  constructor(
    private readonly store: IdempotencyStore,
    private readonly ttl: number = 24 * 60 * 60, // 24 hours
  ) {}

  async handle<T>(
    idempotencyKey: string,
    handler: () => Promise<T>,
  ): Promise<T> {
    // 1. Check: đã xử lý request này chưa?
    const existing = await this.store.get(idempotencyKey);
    if (existing) {
      if (existing.status === 'completed') {
        return existing.result as T; // Return cached result
      }
      if (existing.status === 'processing') {
        throw new ConflictError('Request is being processed');
      }
    }

    // 2. Mark as processing (prevent concurrent duplicate)
    await this.store.set(idempotencyKey, {
      status: 'processing',
      startedAt: Date.now(),
      result: null,
    }, this.ttl);

    try {
      // 3. Process request
      const result = await handler();

      // 4. Store result
      await this.store.set(idempotencyKey, {
        status: 'completed',
        startedAt: Date.now(),
        result,
      }, this.ttl);

      return result;
    } catch (error) {
      // 5. Clear processing state on failure → allow retry
      await this.store.set(idempotencyKey, {
        status: 'failed',
        startedAt: Date.now(),
        result: null,
        error: String(error),
      }, 60); // Short TTL for failed — allow quick retry

      throw error;
    }
  }
}

interface StoredResult {
  status: 'processing' | 'completed' | 'failed';
  startedAt: number;
  result: unknown;
  error?: string;
}

class ConflictError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'ConflictError';
  }
}

// === Usage: Payment API ===
class PaymentController {
  constructor(
    private readonly idempotent: IdempotentRequestHandler,
    private readonly paymentService: PaymentService,
  ) {}

  async createCharge(req: HttpRequest): Promise<HttpResponse> {
    // Client gửi idempotency key qua header
    const idempotencyKey = req.headers['idempotency-key'];
    if (!idempotencyKey) {
      return { status: 400, body: { error: 'Idempotency-Key header required' } };
    }

    const result = await this.idempotent.handle(
      idempotencyKey,
      () => this.paymentService.charge(req.body),
    );

    return { status: 200, body: result };

    // Retry: Gửi cùng Idempotency-Key → nhận cùng response
    // Stripe, PayPal, tất cả payment API đều hoạt động như vậy
  }
}
```

### Deduplication

```typescript
// Deduplication: loại bỏ duplicate messages/events

class MessageDeduplicator {
  private processedIds: Set<string>;
  private slidingWindow: Array<{ id: string; timestamp: number }>;

  constructor(
    private readonly windowSizeMs: number = 3600_000, // 1 hour window
    private readonly maxEntries: number = 1_000_000,
  ) {
    this.processedIds = new Set();
    this.slidingWindow = [];
  }

  isDuplicate(messageId: string): boolean {
    // Cleanup expired entries
    this.cleanup();

    if (this.processedIds.has(messageId)) {
      return true; // DUPLICATE
    }

    // Mark as processed
    this.processedIds.add(messageId);
    this.slidingWindow.push({
      id: messageId,
      timestamp: Date.now(),
    });

    return false; // NEW message
  }

  private cleanup(): void {
    const cutoff = Date.now() - this.windowSizeMs;
    while (
      this.slidingWindow.length > 0 &&
      this.slidingWindow[0].timestamp < cutoff
    ) {
      const entry = this.slidingWindow.shift()!;
      this.processedIds.delete(entry.id);
    }

    // Safety: cap memory usage
    if (this.processedIds.size > this.maxEntries) {
      const toRemove = this.slidingWindow.splice(
        0,
        Math.floor(this.maxEntries * 0.1),
      );
      for (const entry of toRemove) {
        this.processedIds.delete(entry.id);
      }
    }
  }
}

// Usage with Kafka consumer
class DeduplicatedConsumer {
  private dedup = new MessageDeduplicator();

  async processMessage(message: KafkaMessage): Promise<void> {
    const messageId = message.headers['message-id']?.toString()
      ?? `${message.topic}:${message.partition}:${message.offset}`;

    if (this.dedup.isDuplicate(messageId)) {
      console.log(`Skipping duplicate message: ${messageId}`);
      return; // Skip duplicate
    }

    // Process normally
    await this.handleMessage(message);
  }

  private async handleMessage(message: KafkaMessage): Promise<void> {
    // Business logic
  }
}
```

### Delivery Semantics

```typescript
// At-most-once:  Message xử lý tối đa 1 lần (có thể mất)
// At-least-once: Message xử lý ít nhất 1 lần (có thể duplicate)
// Exactly-once:  Message xử lý đúng 1 lần (khó nhất, đắt nhất)

// At-most-once: Commit TRƯỚC khi process
class AtMostOnceConsumer {
  async process(message: KafkaMessage): Promise<void> {
    await this.commitOffset(message);  // Commit TRƯỚC
    await this.handleMessage(message); // Process SAU
    // Nếu crash ở đây → message bị mất (đã committed)
  }
}

// At-least-once: Commit SAU khi process
class AtLeastOnceConsumer {
  async process(message: KafkaMessage): Promise<void> {
    await this.handleMessage(message); // Process TRƯỚC
    await this.commitOffset(message);  // Commit SAU
    // Nếu crash ở đây → message sẽ re-process (chưa committed)
    // → Cần idempotent handler!
  }
}

// Exactly-once: Transactional processing
// Kafka Transactions: write result + commit offset trong 1 transaction
class ExactlyOnceProcessor {
  async process(message: KafkaMessage): Promise<void> {
    // BEGIN TRANSACTION
    await this.producer.beginTransaction();

    try {
      // Process message và produce result
      const result = await this.transform(message);

      // Produce result tới output topic
      await this.producer.send({
        topic: 'output-topic',
        messages: [{ value: JSON.stringify(result) }],
      });

      // Commit consumer offset WITHIN SAME TRANSACTION
      await this.producer.sendOffsetsToTransaction({
        consumerGroupId: this.groupId,
        topics: [{
          topic: message.topic,
          partitions: [{
            partition: message.partition,
            offset: (BigInt(message.offset) + 1n).toString(),
          }],
        }],
      });

      await this.producer.commitTransaction();
    } catch (error) {
      await this.producer.abortTransaction();
      throw error;
    }
  }
}

// Thực tế: Exactly-once across systems khác nhau là GẦN NHƯ BẤT KHẢ THI.
// Kafka exactly-once chỉ hoạt động TRONG Kafka ecosystem.
// Cross-system: dùng at-least-once + idempotency = "effectively once"
```

## Case Study: Distributed Rate Limiter

### Requirements

```
1. Rate limit API: max N requests per window per user
2. Works across multiple server instances
3. Precise count (không chấp nhận sai lệch lớn)
4. Low latency (< 1ms overhead per request)
5. Graceful degradation khi Redis unavailable
```

### Implementation: Sliding Window Counter

```typescript
import { Redis } from 'ioredis';

interface RateLimitConfig {
  /** Max requests per window */
  maxRequests: number;
  /** Window size in seconds */
  windowSizeSeconds: number;
}

interface RateLimitResult {
  allowed: boolean;
  limit: number;
  remaining: number;
  retryAfterMs: number | null;
  /** Current window's request count */
  currentCount: number;
}

class DistributedRateLimiter {
  constructor(
    private readonly redis: Redis,
    private readonly config: RateLimitConfig,
    private readonly keyPrefix: string = 'ratelimit:',
  ) {}

  /**
   * Sliding window counter algorithm
   * Kết hợp 2 fixed windows: current + previous
   * Weighted average dựa trên vị trí trong window hiện tại
   */
  async checkAndIncrement(identifier: string): Promise<RateLimitResult> {
    const now = Date.now();
    const windowMs = this.config.windowSizeSeconds * 1000;

    // Current and previous window boundaries
    const currentWindowStart = Math.floor(now / windowMs) * windowMs;
    const previousWindowStart = currentWindowStart - windowMs;

    const currentKey = `${this.keyPrefix}${identifier}:${currentWindowStart}`;
    const previousKey = `${this.keyPrefix}${identifier}:${previousWindowStart}`;

    // Lua script: atomic check + increment
    const result = await this.redis.eval(
      `
      local currentKey = KEYS[1]
      local previousKey = KEYS[2]
      local maxRequests = tonumber(ARGV[1])
      local windowMs = tonumber(ARGV[2])
      local now = tonumber(ARGV[3])
      local currentWindowStart = tonumber(ARGV[4])
      local ttl = tonumber(ARGV[5])

      -- Get counts
      local currentCount = tonumber(redis.call('GET', currentKey) or '0')
      local previousCount = tonumber(redis.call('GET', previousKey) or '0')

      -- Sliding window weight
      -- elapsed = how far into current window
      local elapsed = now - currentWindowStart
      local weight = 1 - (elapsed / windowMs)  -- 1.0 → 0.0

      -- Weighted count = previous * weight + current
      local estimatedCount = math.floor(previousCount * weight) + currentCount

      if estimatedCount >= maxRequests then
        -- Rate limited
        local retryAfterMs = windowMs - elapsed
        return {0, currentCount, estimatedCount, retryAfterMs}
      end

      -- Allowed: increment current window
      local newCount = redis.call('INCR', currentKey)

      -- Set TTL (2x window để previous window cũng có data)
      redis.call('PEXPIRE', currentKey, ttl)

      return {1, newCount, estimatedCount + 1, 0}
      `,
      2, // number of keys
      currentKey,
      previousKey,
      this.config.maxRequests.toString(),
      windowMs.toString(),
      now.toString(),
      currentWindowStart.toString(),
      (windowMs * 2).toString(), // TTL
    ) as [number, number, number, number];

    const [allowed, currentCount, totalCount, retryAfterMs] = result;

    return {
      allowed: allowed === 1,
      limit: this.config.maxRequests,
      remaining: Math.max(0, this.config.maxRequests - totalCount),
      retryAfterMs: retryAfterMs > 0 ? retryAfterMs : null,
      currentCount,
    };
  }

  /**
   * Batch check: kiểm tra rate limit cho nhiều resources cùng lúc
   * Ví dụ: check cả user limit VÀ IP limit VÀ global limit
   */
  async checkMultiple(
    checks: Array<{ identifier: string; config: RateLimitConfig }>,
  ): Promise<RateLimitResult[]> {
    const results = await Promise.all(
      checks.map(c => {
        const limiter = new DistributedRateLimiter(this.redis, c.config, this.keyPrefix);
        return limiter.checkAndIncrement(c.identifier);
      })
    );

    return results;
  }
}

// === Rate Limiter Middleware ===

class RateLimitMiddleware {
  private limiter: DistributedRateLimiter;
  private localFallback: LocalRateLimiter; // Fallback khi Redis down

  constructor(redis: Redis, config: RateLimitConfig) {
    this.limiter = new DistributedRateLimiter(redis, config);
    this.localFallback = new LocalRateLimiter(config);
  }

  async middleware(
    req: HttpRequest,
    res: HttpResponse,
    next: () => Promise<void>,
  ): Promise<void> {
    const identifier = this.getIdentifier(req);

    let result: RateLimitResult;
    try {
      result = await this.limiter.checkAndIncrement(identifier);
    } catch (error) {
      // Redis unavailable → graceful degradation
      // Use local (per-instance) rate limiter
      console.warn('Redis rate limiter unavailable, using local fallback');
      result = this.localFallback.check(identifier);
    }

    // Set rate limit headers (RFC 6585 / draft-ietf-httpapi-ratelimit-headers)
    res.setHeader('RateLimit-Limit', result.limit.toString());
    res.setHeader('RateLimit-Remaining', result.remaining.toString());

    if (!result.allowed) {
      res.setHeader('Retry-After', Math.ceil((result.retryAfterMs ?? 1000) / 1000).toString());
      res.status(429).json({
        error: 'Too Many Requests',
        retryAfterMs: result.retryAfterMs,
      });
      return;
    }

    await next();
  }

  private getIdentifier(req: HttpRequest): string {
    // Multi-level rate limiting
    // Priority: API key > User ID > IP address
    return req.headers['x-api-key']
      ?? req.user?.id
      ?? req.ip
      ?? 'anonymous';
  }
}

// Local fallback: Token Bucket per instance
class LocalRateLimiter {
  private buckets = new Map<string, { tokens: number; lastRefill: number }>();

  constructor(private readonly config: RateLimitConfig) {}

  check(identifier: string): RateLimitResult {
    const now = Date.now();
    let bucket = this.buckets.get(identifier);

    if (!bucket) {
      bucket = { tokens: this.config.maxRequests, lastRefill: now };
      this.buckets.set(identifier, bucket);
    }

    // Refill tokens
    const elapsed = (now - bucket.lastRefill) / 1000;
    const refillRate = this.config.maxRequests / this.config.windowSizeSeconds;
    bucket.tokens = Math.min(
      this.config.maxRequests,
      bucket.tokens + elapsed * refillRate,
    );
    bucket.lastRefill = now;

    if (bucket.tokens >= 1) {
      bucket.tokens -= 1;
      return {
        allowed: true,
        limit: this.config.maxRequests,
        remaining: Math.floor(bucket.tokens),
        retryAfterMs: null,
        currentCount: this.config.maxRequests - Math.floor(bucket.tokens),
      };
    }

    return {
      allowed: false,
      limit: this.config.maxRequests,
      remaining: 0,
      retryAfterMs: Math.ceil((1 - bucket.tokens) / refillRate * 1000),
      currentCount: this.config.maxRequests,
    };
  }
}

// === Multi-tier Rate Limiting ===

class MultiTierRateLimiter {
  constructor(private readonly redis: Redis) {}

  async check(req: HttpRequest): Promise<{ allowed: boolean; tier: string }> {
    const userId = req.user?.id ?? req.ip;

    // Tier 1: Per-user limit (100 req/min)
    const userLimiter = new DistributedRateLimiter(this.redis, {
      maxRequests: 100,
      windowSizeSeconds: 60,
    }, 'rl:user:');

    // Tier 2: Per-IP limit (500 req/min) — chống abuse
    const ipLimiter = new DistributedRateLimiter(this.redis, {
      maxRequests: 500,
      windowSizeSeconds: 60,
    }, 'rl:ip:');

    // Tier 3: Global limit (10000 req/min) — bảo vệ hệ thống
    const globalLimiter = new DistributedRateLimiter(this.redis, {
      maxRequests: 10000,
      windowSizeSeconds: 60,
    }, 'rl:global:');

    // Check all tiers — reject nếu BẤT KỲ tier nào bị limit
    const [userResult, ipResult, globalResult] = await Promise.all([
      userLimiter.checkAndIncrement(userId),
      ipLimiter.checkAndIncrement(req.ip),
      globalLimiter.checkAndIncrement('global'),
    ]);

    if (!globalResult.allowed) return { allowed: false, tier: 'global' };
    if (!ipResult.allowed) return { allowed: false, tier: 'ip' };
    if (!userResult.allowed) return { allowed: false, tier: 'user' };

    return { allowed: true, tier: 'none' };
  }
}
```

### Trade-offs của Distributed Rate Limiter

```
┌──────────────────┬─────────────────┬──────────────────────────────┐
│ Approach         │ Accuracy        │ Trade-off                    │
├──────────────────┼─────────────────┼──────────────────────────────┤
│ Local only       │ Per-instance    │ N instances = N× total limit │
│ Redis fixed      │ Exact per window│ Boundary problem (2× burst)  │
│ Redis sliding    │ Very accurate   │ Slightly more computation    │
│ Redis + local    │ Best effort     │ Handles Redis failure        │
│ Token bucket     │ Smooth          │ Memory per identifier        │
└──────────────────┴─────────────────┴──────────────────────────────┘

Production recommendation:
  Redis sliding window + local fallback
  = Accurate under normal conditions
  + Graceful degradation when Redis is down
```

| System | Key Insight | Bài học |
|--------|-------------|---------|
| DNS | Hierarchical + caching = scale to billions | Eventual consistency is OK for many use cases |
| Kafka | Partition ordering + consumer groups | Partition key quyết định ordering |
| Redis Cluster | Hash slots + async replication | Accept potential data loss for speed |

| Network partitions | Test early, test often | Use Toxiproxy, Chaos Engineering |
| Idempotency | At-least-once + idempotency = effectively once | Every write API needs idempotency key |
| Rate limiter | Multi-tier + graceful degradation | Fallback to local when distributed fails |

> **Nguyên tắc vàng cho production distributed systems:**
> 1. Design for failure from day one
> 2. Idempotency everywhere — mọi write operation
> 3. Monitor replication lag — nó sẽ bite you
> 4. Test network partitions TRƯỚC KHI production incident
> 5. Graceful degradation > total failure
> 6. Khi nghi ngo: chon at-least-once + idempotency hon exactly-once
