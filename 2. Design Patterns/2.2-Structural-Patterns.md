## 6. Adapter

> Còn gọi là **Wrapper**. Chuyển đổi interface của class này thành interface mà client mong đợi.

### Vấn đề

Bạn có class/library hoạt động tốt nhưng **interface không khớp** với code hiện tại. Không thể (hoặc không nên) sửa library đó.

### ✅ Real-world: Adapter cho third-party payment gateways

```typescript
// Application interface — code của bạn dùng interface này
interface PaymentProcessor {
  charge(amount: Money, source: PaymentSource): Promise<ChargeResult>;
  refund(chargeId: string, amount?: Money): Promise<RefundResult>;
}

interface ChargeResult {
  id: string;
  status: 'succeeded' | 'failed' | 'pending';
  amount: Money;
  error?: string;
}

// --- Stripe SDK (third-party, interface khác) ---
// stripe.paymentIntents.create({ amount: 1000, currency: 'usd', ... })
// stripe.refunds.create({ payment_intent: 'pi_xxx', amount: 500 })

class StripeAdapter implements PaymentProcessor {
  constructor(private readonly stripe: Stripe) {}

  async charge(amount: Money, source: PaymentSource): Promise<ChargeResult> {
    try {
      const intent = await this.stripe.paymentIntents.create({
        amount: amount.cents,
        currency: amount.currency.toLowerCase(),
        payment_method: source.token,
        confirm: true,
      });

      return {
        id: intent.id,
        status: this.mapStatus(intent.status),
        amount,
      };
    } catch (error) {
      if (error instanceof Stripe.errors.StripeCardError) {
        return { id: '', status: 'failed', amount, error: error.message };
      }
      throw error; // Re-throw unexpected errors
    }
  }

  async refund(chargeId: string, amount?: Money): Promise<RefundResult> {
    const refund = await this.stripe.refunds.create({
      payment_intent: chargeId,
      ...(amount && { amount: amount.cents }),
    });

    return {
      id: refund.id,
      status: refund.status === 'succeeded' ? 'completed' : 'pending',
      amount: Money.fromCents(refund.amount, refund.currency.toUpperCase() as Currency),
    };
  }

  private mapStatus(stripeStatus: string): ChargeResult['status'] {
    switch (stripeStatus) {
      case 'succeeded': return 'succeeded';
      case 'requires_action':
      case 'processing': return 'pending';
      default: return 'failed';
    }
  }
}

// --- PayPal SDK (third-party, interface hoàn toàn khác) ---
// paypal.orders.create({ purchase_units: [{ amount: { value: '10.00' } }] })
// paypal.orders.capture(orderId)

class PayPalAdapter implements PaymentProcessor {
  constructor(private readonly paypal: PayPalClient) {}

  async charge(amount: Money, source: PaymentSource): Promise<ChargeResult> {
    const order = await this.paypal.orders.create({
      intent: 'CAPTURE',
      purchase_units: [{
        amount: {
          value: (amount.cents / 100).toFixed(2),
          currency_code: amount.currency,
        },
      }],
    });

    const capture = await this.paypal.orders.capture(order.id);

    return {
      id: capture.id,
      status: capture.status === 'COMPLETED' ? 'succeeded' : 'pending',
      amount,
    };
  }

  async refund(chargeId: string, amount?: Money): Promise<RefundResult> {
    const captureId = await this.getCaptureId(chargeId);
    const refund = await this.paypal.payments.capturesRefund(captureId, {
      amount: amount ? {
        value: (amount.cents / 100).toFixed(2),
        currency_code: amount.currency,
      } : undefined,
    });

    return {
      id: refund.id,
      status: refund.status === 'COMPLETED' ? 'completed' : 'pending',
      amount: amount ?? await this.getOriginalAmount(chargeId),
    };
  }

  private async getCaptureId(orderId: string): Promise<string> { /* ... */ }
  private async getOriginalAmount(orderId: string): Promise<Money> { /* ... */ }
}

// Client code — works with ANY payment processor
class CheckoutService {
  constructor(private readonly payment: PaymentProcessor) {} // Interface, not concrete

  async processCheckout(order: Order, paymentSource: PaymentSource): Promise<CheckoutResult> {
    const result = await this.payment.charge(order.total, paymentSource);
    // ... rest of checkout logic — KHÔNG biết Stripe hay PayPal
  }
}
```

- Wrap legacy code mà không muốn/không thể sửa

## 7. Bridge

> Tách **abstraction** khỏi **implementation** để cả hai có thể thay đổi độc lập.

### Vấn đề

Khi có 2 dimensions of variation (ví dụ: loại notification × kênh gửi), inheritance tạo ra class explosion: `EmailUrgentNotification`, `SmsUrgentNotification`, `EmailInfoNotification`...

### ❌ Class Explosion với Inheritance

```typescript
// 3 types × 3 channels = 9 classes!

class EmailInfoNotification { /* ... */ }
class EmailMarketingNotification { /* ... */ }

class SmsInfoNotification { /* ... */ }

// Thêm 1 channel (WhatsApp) = thêm 3 classes
```

### ✅ Bridge — Tách 2 dimensions

```typescript
// Dimension 1: HOW to send (Implementation)
interface MessageSender {
  send(recipient: string, content: MessageContent): Promise<DeliveryReceipt>;
}

class EmailSender implements MessageSender {
  constructor(private readonly mailer: MailerClient) {}

  async send(recipient: string, content: MessageContent): Promise<DeliveryReceipt> {
    const result = await this.mailer.send({
      to: recipient,
      subject: content.title,
      html: content.body,
    });
    return { id: result.messageId, channel: 'email', sentAt: new Date() };
  }
}

class SmsSender implements MessageSender {
  constructor(private readonly smsClient: SmsClient) {}

  async send(recipient: string, content: MessageContent): Promise<DeliveryReceipt> {
    // SMS: truncate body, no title
    const text = content.body.length > 160
      ? content.body.substring(0, 157) + '...'
      : content.body;
    const result = await this.smsClient.send({ to: recipient, body: text });
    return { id: result.sid, channel: 'sms', sentAt: new Date() };
  }
}

class PushSender implements MessageSender {
  constructor(private readonly pushClient: PushClient) {}

  async send(recipient: string, content: MessageContent): Promise<DeliveryReceipt> {
    const result = await this.pushClient.send({
      token: recipient,
      notification: { title: content.title, body: content.body },
      data: content.metadata,
    });
    return { id: result.messageId, channel: 'push', sentAt: new Date() };
  }
}

// Dimension 2: WHAT to send (Abstraction)
abstract class Notification {
  constructor(protected readonly sender: MessageSender) {} // Bridge to implementation

  abstract prepare(context: NotificationContext): MessageContent;

  async notify(recipient: string, context: NotificationContext): Promise<DeliveryReceipt> {
    const content = this.prepare(context);
    return this.sender.send(recipient, content);
  }
}

class UrgentNotification extends Notification {
  prepare(context: NotificationContext): MessageContent {
    return {
      title: `🚨 URGENT: ${context.subject}`,
      body: context.message,
      metadata: { priority: 'high', requiresAck: true },
    };
  }
}

class InfoNotification extends Notification {
  prepare(context: NotificationContext): MessageContent {
    return {
      title: context.subject,
      body: context.message,
      metadata: { priority: 'normal' },
    };
  }
}

class MarketingNotification extends Notification {
  prepare(context: NotificationContext): MessageContent {
    return {
      title: `✨ ${context.subject}`,
      body: `${context.message}\n\nUnsubscribe: ${context.unsubscribeUrl}`,
      metadata: { priority: 'low', category: 'marketing' },
    };
  }
}

// Usage — combine ANY type × ANY channel
const urgentEmail = new UrgentNotification(new EmailSender(mailer));
const urgentSms = new UrgentNotification(new SmsSender(smsClient));
const marketingPush = new MarketingNotification(new PushSender(pushClient));

// Thêm WhatsApp = 1 new class (WhatsAppSender)
// Thêm Reminder = 1 new class (ReminderNotification)
// KHÔNG cần CartesianProduct
```

### Khi nào dùng

- 2+ independent dimensions of variation
- Muốn tránh class explosion
- Abstraction và implementation cần evolve independently

## 8. Composite

> Tổ chức objects thành **tree structure** và xử lý individual objects và compositions **uniformly**.

### Vấn đề

Cần biểu diễn cấu trúc dạng cây (part-whole hierarchy) mà client code xử lý leaf và container giống nhau.

### ✅ Real-world: Permission System

```typescript
// Permission có thể là atomic hoặc group chứa nhiều permissions khác

interface Permission {
  readonly name: string;
  check(context: AuthContext): boolean;
  describe(): string;
}

// Leaf: Single permission
class SimplePermission implements Permission {
  constructor(
    readonly name: string,
    private readonly checker: (ctx: AuthContext) => boolean,
  ) {}

  check(context: AuthContext): boolean {
    return this.checker(context);
  }

  describe(): string {
    return this.name;
  }
}

// Composite: Permission group (AND — tất cả phải true)
class AllOfPermission implements Permission {
  readonly name: string;

  constructor(
    name: string,
    private readonly children: ReadonlyArray<Permission>,
  ) {
    this.name = name;
  }

  check(context: AuthContext): boolean {
    return this.children.every(child => child.check(context));
  }

  describe(): string {
    const childDescriptions = this.children.map(c => c.describe()).join(' AND ');
    return `(${this.name}: ${childDescriptions})`;
  }
}

// Composite: Permission group (OR — ít nhất 1 true)
class AnyOfPermission implements Permission {
  readonly name: string;

  constructor(
    name: string,
    private readonly children: ReadonlyArray<Permission>,
  ) {
    this.name = name;
  }

  check(context: AuthContext): boolean {
    return this.children.some(child => child.check(context));
  }

  describe(): string {
    const childDescriptions = this.children.map(c => c.describe()).join(' OR ');
    return `(${this.name}: ${childDescriptions})`;
  }
}

// Build complex permission trees
const canRead = new SimplePermission('read', ctx => ctx.hasScope('read'));
const canWrite = new SimplePermission('write', ctx => ctx.hasScope('write'));
const canDelete = new SimplePermission('delete', ctx => ctx.hasScope('delete'));
const isOwner = new SimplePermission('owner', ctx => ctx.userId === ctx.resourceOwnerId);
const isAdmin = new SimplePermission('admin', ctx => ctx.role === 'admin');

// Complex rule: can edit if (admin) OR (owner AND has write scope)
const canEdit = new AnyOfPermission('can-edit', [
  isAdmin,
  new AllOfPermission('owner-with-write', [isOwner, canWrite]),
]);

// Complex rule: can manage if admin AND (has delete scope)
const canManage = new AllOfPermission('can-manage', [
  isAdmin,
  canDelete,
]);

// Client code — treats simple and complex permissions uniformly
function authorize(permission: Permission, context: AuthContext): void {
  if (!permission.check(context)) {
    throw new ForbiddenError(`Permission denied: ${permission.describe()}`);
  }
}

authorize(canEdit, authContext); // Works for both simple and composite
```

### ✅ Real-world: UI Component Tree / Menu System

```typescript
// Menu system: menu items và submenus

interface MenuItem {
  readonly label: string;
  readonly icon?: string;
  render(depth?: number): string;
  findByPath(path: string): MenuItem | null;
}

class ActionItem implements MenuItem {
  constructor(
    readonly label: string,
    readonly icon: string | undefined,
    readonly action: () => void,
    readonly shortcut?: string,
  ) {}

  render(depth = 0): string {
    const indent = '  '.repeat(depth);
    const shortcutStr = this.shortcut ? ` (${this.shortcut})` : '';
    return `${indent}${this.icon ?? ''} ${this.label}${shortcutStr}`;
  }

  findByPath(path: string): MenuItem | null {
    return path === this.label ? this : null;
  }
}

class SubMenu implements MenuItem {
  constructor(
    readonly label: string,
    readonly icon: string | undefined,
    private readonly children: ReadonlyArray<MenuItem>,
  ) {}

  render(depth = 0): string {
    const indent = '  '.repeat(depth);
    const header = `${indent}${this.icon ?? ''} ${this.label}`;
    const childrenStr = this.children.map(c => c.render(depth + 1)).join('\n');
    return `${header}\n${childrenStr}`;
  }

  findByPath(path: string): MenuItem | null {
    const [first, ...rest] = path.split('/');
    if (first !== this.label) return null;
    if (rest.length === 0) return this;

    const remainingPath = rest.join('/');
    for (const child of this.children) {
      const found = child.findByPath(remainingPath);
      if (found) return found;
    }
    return null;
  }
}

// Build menu tree
const fileMenu = new SubMenu('File', '📁', [
  new ActionItem('New', '📄', () => createFile(), 'Ctrl+N'),
  new ActionItem('Open', '📂', () => openFile(), 'Ctrl+O'),
  new ActionItem('Save', '💾', () => saveFile(), 'Ctrl+S'),
  new SubMenu('Export', '📤', [
    new ActionItem('PDF', undefined, () => exportPdf()),
    new ActionItem('CSV', undefined, () => exportCsv()),
    new ActionItem('JSON', undefined, () => exportJson()),
  ]),
]);

console.log(fileMenu.render());
// 📁 File
//   📄 New (Ctrl+N)
//   📂 Open (Ctrl+O)
//   💾 Save (Ctrl+S)
//   📤 Export
//     PDF
//     CSV
//     JSON
```

### Khi nào dùng

- Dữ liệu có cấu trúc cây (file systems, menus, org charts, permissions)
- Client cần xử lý individual và group uniformly
- Recursive structures

## 9. Decorator

> **Thêm behavior** cho objects tại runtime bằng cách **wrap** chúng, mà không sửa original class.

### Vấn đề

Cần thêm/bớt responsibilities cho object linh hoạt, mà inheritance không phù hợp (quá nhiều combinations).

### ✅ Real-world: Repository với cross-cutting concerns

```typescript
// Base interface
interface UserRepository {
  findById(id: string): Promise<User | null>;
  findByEmail(email: string): Promise<User | null>;
  save(user: User): Promise<void>;
  delete(id: string): Promise<void>;
}

// Core implementation
class PostgresUserRepository implements UserRepository {
  constructor(private readonly db: Pool) {}

  async findById(id: string): Promise<User | null> {
    const result = await this.db.query('SELECT * FROM users WHERE id = $1', [id]);
    return result.rows[0] ? this.toDomain(result.rows[0]) : null;
  }

  async findByEmail(email: string): Promise<User | null> {
    const result = await this.db.query('SELECT * FROM users WHERE email = $1', [email]);
    return result.rows[0] ? this.toDomain(result.rows[0]) : null;
  }

  async save(user: User): Promise<void> {
    await this.db.query(
      `INSERT INTO users (id, name, email) VALUES ($1, $2, $3)
       ON CONFLICT (id) DO UPDATE SET name = $2, email = $3`,
      [user.id, user.name, user.email],
    );
  }

  async delete(id: string): Promise<void> {
    await this.db.query('DELETE FROM users WHERE id = $1', [id]);
  }

  private toDomain(row: any): User { /* ... */ }
}

// Decorator 1: Caching
class CachedUserRepository implements UserRepository {
  constructor(
    private readonly inner: UserRepository,
    private readonly cache: Cache,
    private readonly ttlMs = 300_000,
  ) {}

  async findById(id: string): Promise<User | null> {
    const cached = await this.cache.get<User>(`user:${id}`);
    if (cached) return cached;

    const user = await this.inner.findById(id);
    if (user) await this.cache.set(`user:${id}`, user, this.ttlMs);
    return user;
  }

  async findByEmail(email: string): Promise<User | null> {
    // Email lookups: cache with email as key
    const cached = await this.cache.get<User>(`user:email:${email}`);
    if (cached) return cached;

    const user = await this.inner.findByEmail(email);
    if (user) {
      await this.cache.set(`user:email:${email}`, user, this.ttlMs);
      await this.cache.set(`user:${user.id}`, user, this.ttlMs); // Also cache by id
    }
    return user;
  }

  async save(user: User): Promise<void> {
    await this.inner.save(user);
    // Invalidate cache entries
    await this.cache.delete(`user:${user.id}`);
    await this.cache.delete(`user:email:${user.email}`);
  }

  async delete(id: string): Promise<void> {
    const user = await this.findById(id);
    await this.inner.delete(id);
    await this.cache.delete(`user:${id}`);
    if (user) await this.cache.delete(`user:email:${user.email}`);
  }
}

// Decorator 2: Logging
class LoggedUserRepository implements UserRepository {
  constructor(
    private readonly inner: UserRepository,
    private readonly logger: Logger,
  ) {}

  async findById(id: string): Promise<User | null> {
    this.logger.info('UserRepository.findById', { id });
    const start = performance.now();
    const result = await this.inner.findById(id);
    this.logger.info('UserRepository.findById completed', {
      id,
      found: !!result,
      durationMs: Math.round(performance.now() - start),
    });
    return result;
  }

  async findByEmail(email: string): Promise<User | null> {
    this.logger.info('UserRepository.findByEmail', { email });
    return this.inner.findByEmail(email);
  }

  async save(user: User): Promise<void> {
    this.logger.info('UserRepository.save', { userId: user.id });
    await this.inner.save(user);
  }

  async delete(id: string): Promise<void> {
    this.logger.warn('UserRepository.delete', { id });
    await this.inner.delete(id);
  }
}

// Decorator 3: Metrics
class MetricsUserRepository implements UserRepository {
  constructor(
    private readonly inner: UserRepository,
    private readonly metrics: MetricsClient,
  ) {}

  async findById(id: string): Promise<User | null> {
    const timer = this.metrics.startTimer('user_repo_find_by_id_duration');
    try {
      const result = await this.inner.findById(id);
      this.metrics.increment(result ? 'user_repo_hit' : 'user_repo_miss');
      return result;
    } catch (error) {
      this.metrics.increment('user_repo_error');
      throw error;
    } finally {
      timer.stop();
    }
  }

  // ... similar for other methods
  async findByEmail(email: string): Promise<User | null> { return this.inner.findByEmail(email); }
  async save(user: User): Promise<void> { await this.inner.save(user); }
  async delete(id: string): Promise<void> { await this.inner.delete(id); }
}

// Compose decorators — order matters!
const userRepository: UserRepository =
  new LoggedUserRepository(          // Outermost: log everything
    new MetricsUserRepository(       // Track timing
      new CachedUserRepository(      // Cache layer
        new PostgresUserRepository(pool), // Core DB
        redisCache,
      ),
      metricsClient,
    ),
    logger,
  );

// Request flow: Log → Metrics → Cache check → (cache miss?) → PostgreSQL
// Thêm rate limiting? Wrap thêm 1 decorator. KHÔNG sửa code hiện tại.
```

### Decorator vs Inheritance

```
Inheritance: compile-time, static, combinatorial explosion
  UserRepository
  ├── CachedUserRepository
  │   ├── CachedLoggedUserRepository
  │   └── CachedMetricsUserRepository
  ├── LoggedUserRepository
  │   └── LoggedMetricsUserRepository
  └── MetricsUserRepository

Decorator: runtime, dynamic, compose as needed
  Logging(Metrics(Cache(Postgres)))  ← Production
  Logging(Postgres)                  ← Development
  Metrics(Postgres)                  ← Performance testing
  Postgres                           ← Unit testing
```

### Khi nào dùng

- Thêm behavior không sửa existing code (OCP)
- Behavior cần composable (mix & match)
- Cross-cutting concerns (caching, logging, retry, auth)

## 10. Facade

> Cung cấp **interface đơn giản** cho một subsystem phức tạp.

### Vấn đề

Subsystem có nhiều classes/APIs mà client cần interact. Facade che giấu complexity, cung cấp "front door" đơn giản.

### ✅ Real-world: Order Processing Facade

```typescript
// Subsystem phức tạp: inventory, payment, shipping, notification, analytics

class OrderFacade {
  constructor(
    private readonly inventory: InventoryService,
    private readonly payment: PaymentService,
    private readonly shipping: ShippingService,
    private readonly notifications: NotificationService,
    private readonly analytics: AnalyticsService,
    private readonly orders: OrderRepository,
  ) {}

  // Simple interface cho complex workflow
  async placeOrder(request: PlaceOrderRequest): Promise<OrderConfirmation> {
    // Step 1: Check inventory
    const availability = await this.inventory.checkAll(request.items);
    if (!availability.allAvailable) {
      throw new OutOfStockError(availability.unavailable);
    }

    // Step 2: Process payment
    const payment = await this.payment.charge({
      amount: request.total,
      method: request.paymentMethod,
      customerId: request.customerId,
    });

    // Step 3: Create order
    const order = Order.create(request, payment.transactionId);
    await this.orders.save(order);

    // Step 4: Reserve inventory
    await this.inventory.reserve(request.items, order.id);

    // Step 5: Schedule shipping
    const shipment = await this.shipping.schedule({
      orderId: order.id,
      items: request.items,
      address: request.shippingAddress,
      method: request.shippingMethod,
    });

    // Step 6: Notify (fire-and-forget)
    this.notifications.sendOrderConfirmation(order, shipment).catch(err =>
      console.error('Notification failed:', err),
    );

    // Step 7: Track
    this.analytics.trackPurchase(order).catch(() => { /* best effort */ });

    return {
      orderId: order.id,
      estimatedDelivery: shipment.estimatedDelivery,
      trackingNumber: shipment.trackingNumber,
    };
  }

  // Một method che giấu 7 service interactions
  async cancelOrder(orderId: string, reason: string): Promise<void> {
    const order = await this.orders.findById(orderId);
    if (!order) throw new NotFoundError('Order', orderId);

    await this.payment.refund(order.transactionId);
    await this.inventory.release(order.items, orderId);
    await this.shipping.cancel(orderId);

    order.cancel(reason);
    await this.orders.save(order);

    await this.notifications.sendOrderCancellation(order, reason);
  }
}

// Client code — clean and simple
app.post('/orders', async (req, res) => {
  const result = await orderFacade.placeOrder(req.body);
  res.status(201).json(result);
  // Client KHÔNG cần biết về inventory, payment, shipping, notifications, analytics
});
```

### Facade vs God Class

```
Facade:
- KHÔNG chứa business logic → delegates to subsystem services
- Thin layer — chỉ orchestrate
- Subsystem services vẫn accessible trực tiếp nếu cần

God Class:
- CHỨA business logic
- Fat layer — implement everything
- Subsystem bị ẩn hoàn toàn
```

### Khi nào dùng

- Subsystem phức tạp, client chỉ cần use cases đơn giản
- Giảm coupling giữa client và subsystem
- Cung cấp "high-level API" cho common workflows

## 11. Flyweight

> Chia sẻ **intrinsic state** (state chung) giữa nhiều objects để tiết kiệm memory.

### Vấn đề

Cần tạo số lượng LỚN objects tương tự nhau. Mỗi object có phần state chung (intrinsic — shared) và phần riêng (extrinsic — unique).

### ✅ Real-world: Text Rendering / Icon System

```typescript
// Mỗi character có font, size, color (intrinsic) + position (extrinsic)

// Flyweight: shared formatting
class TextStyle {
  private constructor(
    readonly fontFamily: string,
    readonly fontSize: number,
    readonly fontWeight: 'normal' | 'bold',
    readonly color: string,
    readonly italic: boolean,
  ) {
    Object.freeze(this);
  }

  // Flyweight Factory — cache and reuse instances
  private static readonly cache = new Map<string, TextStyle>();

  static of(
    fontFamily: string,
    fontSize: number,
    fontWeight: 'normal' | 'bold' = 'normal',
    color = '#000000',
    italic = false,
  ): TextStyle {

    let style = TextStyle.cache.get(key);
    if (!style) {
      style = new TextStyle(fontFamily, fontSize, fontWeight, color, italic);
      TextStyle.cache.set(key, style);
    }
    return style;
  }

  static get cacheSize(): number {
    return TextStyle.cache.size;
  }
}
```

## 12. Proxy

> Cung cấp **surrogate/placeholder** kiểm soát access đến object khác.

### Các loại Proxy

| Loại | Mục đích |
|------|----------|
| **Virtual Proxy** | Lazy loading — tạo heavy object khi thực sự cần |
| **Protection Proxy** | Access control — kiểm tra permissions |
| **Remote Proxy** | Represent remote object locally |
| **Caching Proxy** | Cache results (tương tự Decorator, nhưng focus access control) |
| **Logging Proxy** | Log access patterns |

### ✅ Real-world: Lazy Loading Proxy

```typescript
// Vấn đề: Load images chỉ khi user scroll đến

interface Image {
  readonly width: number;
  readonly height: number;
  readonly src: string;
  render(canvas: Canvas, x: number, y: number): void;
  getData(): ImageData;
}

class RealImage implements Image {
  private data: ImageData;

  constructor(
    readonly src: string,
    readonly width: number,
    readonly height: number,
  ) {
    // Heavy operation: load full image data
    console.log(`Loading image: ${src} (${width}x${height})`);
    this.data = this.loadFromDisk(src);
  }

  render(canvas: Canvas, x: number, y: number): void {
    canvas.drawImage(this.data, x, y);
  }

  getData(): ImageData {
    return this.data;
  }

  private loadFromDisk(src: string): ImageData { /* heavy I/O */ }
}

// Virtual Proxy — delays loading until actually needed
class LazyImage implements Image {
  private realImage: RealImage | null = null;

  constructor(
    readonly src: string,
    readonly width: number,
    readonly height: number,
  ) {
    // Lightweight: chỉ lưu metadata, KHÔNG load image data
  }

  render(canvas: Canvas, x: number, y: number): void {
    // Load on first render
    this.ensureLoaded();
    this.realImage!.render(canvas, x, y);
  }

  getData(): ImageData {
    this.ensureLoaded();
    return this.realImage!.getData();
  }

  private ensureLoaded(): void {
    if (!this.realImage) {
      this.realImage = new RealImage(this.src, this.width, this.height);
    }
  }
}

// Gallery: 1000 images nhưng chỉ load ~10 visible ones
class Gallery {
  private images: Image[];

  constructor(imageSources: ImageInfo[]) {
    // Tạo proxies — instant, zero I/O
    this.images = imageSources.map(info =>
      new LazyImage(info.src, info.width, info.height)
    );
  }

  renderVisible(viewport: Viewport, canvas: Canvas): void {
    const visible = this.images.filter(img => viewport.isVisible(img));
    // Chỉ images thực sự visible mới bị load
    visible.forEach(img => img.render(canvas, img.x, img.y));
  }
}
```

### ✅ Real-world: Protection Proxy

```typescript
// Access control proxy — kiểm tra permissions trước khi delegate

interface DocumentService {
  getDocument(id: string): Promise<Document>;
  updateDocument(id: string, content: string): Promise<void>;
  deleteDocument(id: string): Promise<void>;
  listDocuments(): Promise<ReadonlyArray<Document>>;
}

class DocumentServiceProxy implements DocumentService {
  constructor(
    private readonly inner: DocumentService,
    private readonly auth: AuthContext,
    private readonly permissions: PermissionService,
  ) {}

  async getDocument(id: string): Promise<Document> {
    await this.permissions.assertCan(this.auth.userId, 'read', 'document', id);
    return this.inner.getDocument(id);
  }

  async updateDocument(id: string, content: string): Promise<void> {
    await this.permissions.assertCan(this.auth.userId, 'write', 'document', id);
    return this.inner.updateDocument(id, content);
  }

  async deleteDocument(id: string): Promise<void> {
    await this.permissions.assertCan(this.auth.userId, 'delete', 'document', id);
    return this.inner.deleteDocument(id);
  }

  async listDocuments(): Promise<ReadonlyArray<Document>> {
    const allDocs = await this.inner.listDocuments();
    // Filter: chỉ trả về documents user có quyền đọc
    const accessible = await Promise.all(
      allDocs.map(async doc => {
        const canRead = await this.permissions.can(this.auth.userId, 'read', 'document', doc.id);
        return canRead ? doc : null;
      }),
    );
    return accessible.filter((doc): doc is Document => doc !== null);
  }
}
```

```typescript
// JavaScript có Proxy built-in — không cần class pattern

function createValidatingProxy<T extends Record<string, unknown>>(
  target: T,
  validators: Partial<Record<keyof T, (value: unknown) => boolean>>,
): T {
  return new Proxy(target, {
    set(obj, prop, value) {
      const validator = validators[prop as keyof T];
      if (validator && !validator(value)) {
        throw new Error(`Invalid value for ${String(prop)}: ${value}`);
      }
      return Reflect.set(obj, prop, value);
    },

    get(obj, prop) {
      const value = Reflect.get(obj, prop);
      console.log(`Accessed ${String(prop)} = ${value}`);
      return value;
    },
  });
}

const user = createValidatingProxy(
  { name: 'Alice', age: 30, email: 'alice@test.com' },
  {
    age: (v) => typeof v === 'number' && v >= 0 && v <= 150,
    email: (v) => typeof v === 'string' && v.includes('@'),
  },
);

user.age = 25;    // ✅ OK
user.age = -5;    // 💥 Error: Invalid value for age: -5
user.email = 'x'; // 💥 Error: Invalid value for email: x
```

## So sánh Structural Patterns

| Pattern | Mục đích | Interface? | Khi nào |
|---------|----------|------------|--------|
| **Adapter** | Chuyển đổi interface | Khác interface | Integrate third-party |
| **Bridge** | Tách abstraction ↔ implementation | 2 hierarchies | 2+ dimensions of change |
| **Composite** | Tree structure | Uniform leaf/node | Part-whole hierarchy |
| **Decorator** | Thêm behavior | Cùng interface | Cross-cutting concerns |
| **Facade** | Simplify subsystem | New simple interface | Complex subsystem |
| **Flyweight** | Share state | N/A | Memory optimization |
| **Proxy** | Control access | Cùng interface | Lazy load, auth, remote |

### Decorator vs Proxy vs Adapter

```
Adapter:  Interface A  → [Adapter]  → Interface B     (convert)
Decorator: Interface A → [Decorator] → Interface A    (enhance)
Proxy:     Interface A → [Proxy]     → Interface A    (control)

Decorator: thêm behavior
Proxy: kiểm soát access
Adapter: chuyển đổi interface
```
